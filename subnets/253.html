What it is

VoiceGuard is a Bittensor subnet project by the Cazure team that aimed to detect AI-generated voices, clone voices to build training data for detectors, and offer speech-to-text. Its earlier mainnet slot (SN44) was dissolved in August 2024; this rebuild only ever had a testnet slot, 253.

How it works

Miners

Per the README, miners answer three request types: transcribe a segment of a YouTube video, clone a voice from a reference clip and a text, and say whether an audio clip is real or AI-generated. The repo ships a Whisper path, a cloning path and a detection path that returns a probability; the detection model itself is not in the repo, a download script fetches it.

Validators

For cloning, the validator picks a sentence and a reference clip, transcribes the miner's audio with Whisper, gives zero if the text match is below 0.8, and otherwise scores speaker similarity (50%), pitch similarity (25%) and audio quality (25%). Detection is scored on correctness, confidence and batch accuracy; transcription on text correctness (70%) and speed (30%).

Incentive

The README says validators combine 20% transcription, 40% cloning and 40% detection, with zero for any miner whose transcription score is zero. In the last commit the validator loop only queries cloning on one hard-coded miner, so as written every combined score would be zero; this looks like a debug state and was not run. On testnet no neuron has incentive or dividends (2026-10-31).

Roles and requirements

Miner Medium barrier

Answers three request types: transcribe a YouTube segment, clone a voice, or tell real from AI-generated audio.

  • The compute file lists 16 GB VRAM as the minimum and 10 GB as recommended (inconsistent).
  • Detection model and part of the data come from a team-run server at a hard-coded address (not tested).
  • Cloning uses a YourTTS model on CPU; transcription uses Whisper large.

Validator Medium barrier

Sends the request types, scores replies with Whisper, speaker-similarity and quality models, and sets weights.

  • Seven neurons hold validator permits out of 64 slots; none has set weights in about 225 days (2026-10-31).
  • The committed loop queries one hard-coded miner, and the transcription and detection branches never run.
  • The detection reward is called with a parameter name it does not accept, and a code comment and the reward disagree on whether a probability above 0.5 means fake or real.

Getting started

  1. Install Bittensor, clone the repo, run pip install -r requirements.txt and pip install -e . (Python 3.10.x; add pip install TTS for cloning).
  2. Run python3 voiceguard/utils/download.py for datasets and the detection model; part comes from a team-run server that may be down.
  3. Optionally set a proxy URL in a .env file to avoid YouTube rate limits on transcription tasks.
  4. Create a testnet wallet, get test TAO and register a hotkey on testnet netuid 253.
  5. Start neurons/miner.py with --netuid 253 --subtensor.network test plus your wallet, axon IP and port (the README's example omits the network flag).

Caveats

  • Testnet only: nothing here describes mainnet participation, emissions or token economics, and no mainnet plan has been stated since 2025-04-23.
  • Testnet 253 has 14 neurons and 7 validator permits; the freshest weight stamp is about 225 days old (around 2026-03-20) and it grew by exactly the blocks elapsed since 2026-10-26. No working miner or validator was found.
  • Who owns the testnet slot is unresolved; the link to the VoiceGuard team rests on the README roadmap, the channel name and the registration date matching the launch post.
  • The datasets, detection model and test audio depend on a team-run server at a hard-coded address (not tested). The team's Miner Hubs site (taoscribe.ai) does not resolve.
  • The whitepaper and the Q2-Q3 2025 roadmap items (Chrome extension, iOS app, film partner) were not verified. Channel history before December 2024 belongs to earlier subnets and a different codebase.

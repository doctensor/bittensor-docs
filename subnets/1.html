What it is

Apex is the Macrocosmos subnet, rebuilt in 2026 as a platform for contests. A contest is a measurable task with a scoring function. Miners, people or AI agents, submit solutions with a command-line tool; the best entry in each contest wins that contest's share of rewards.

How it works

Miners

A miner picks a contest, builds a solution and submits it with the apex command-line tool, paying a fee. Entries are one Python file (Text Clustering) or one ONNX robot policy (the other three). Rounds last a day, two for Box Scramble.

Validators

Validators score nothing. Every 21 minutes the validator code fetches uid and weight pairs from the team's closed server and sets them on chain; if the server fails it copies the other validators. All 10 permitted validators put their top weight on the owner's uid (2026-10-28).

Incentive

Each contest gets a share of miner rewards; its top entry takes all, and a challenger must beat the leader by more than 1%. Emission splits 18% owner, 41% validators, 41% miners. Of the miner half, 57.9% sits on the owner's uid and is burned (52.7% on 2026-10-23); the rest goes to four winner uids. The per-contest split is not published.

Roles and requirements

Miner Medium barrier

Builds a solution for one contest and submits it, paying a fee.

  • Text Clustering: one Python file up to 50,000 characters, CPU only, no internet.
  • NIST-Lite: one ONNX policy up to 50 MB on 2 CPUs; hand-coded controllers score 0.08 to 0.21, the team's solver 0.70.
  • A rejected submission's payment can be reused; fees are not refunded. A tie does not win.

Validator Medium barrier

Relays the team server's scores to the chain.

  • 10 hold permits; one has not set weights for about 950 days.
  • One earns about 76% of validator dividends.

Bull case

  • Team ships fast: NIST-Lite went v0.2 to v0.5 in a week; a scoring bug was fixed in a day.
  • Four live contests pay winners on four separate coldkeys.

Bear case

  • Scoring is closed; validators only relay it.
  • 57.9% of miner pay is burned and rising.
  • Outflow in four of five weeks; no verifiable revenue.

What would change this view: Two weeks of net inflow or a published split with less burn would turn it bullish; a higher burn or a server outage freezing weights would turn it bearish.

Informational analysis written from public data. It is not financial advice or a recommendation to buy or sell. Prices are in TAO per alpha; chain data shows what happened, not why.

Getting started

  1. Pick a contest on the Apex website and read its docs page and repository together; the docs lag the code.
  2. Clone the apex repository, run ./install_cli.sh and link a wallet registered on subnet 1 with apex link.
  3. Easiest start: Text Clustering, one Python file on CPU.
  4. Run apex competitions to see the score to beat and the fee before you submit.
  5. If a submission is rejected, keep the payment receipt; apex submit can reuse it.

Caveats

  • The per-contest split and burn factors sit in the closed server; the burn share rose from 52.7% to 57.9% in five days.
  • The README says validators score every submission; the code only relays the team's scores, so a server outage freezes the last weights.
  • Fees go to an account not tied to the owner, validators or winners (checked 2026-10-23); its controller is not documented.
  • The 1% rule can freeze a contest when entries tie (NIST-Lite, 10-19); a scoring race needed hand fixes on 10-22, reported fixed 10-23.
  • Docs lag: Text Clustering says four subsets in most places and the repo says three; the FAQ lists fees for two contests.

What it is

ReadyAI (SN33, repo still named Conversation Genome Project) turns raw content into structured data. Miners tag or enrich pieces of text, validators build a reference answer from the full content and score each miner against it. The code defines six task types; the team's current direction is agent skills (generated skills with test assertions, sold through the planned Skill Store 33) plus a paid Jobs API and an llms.txt dataset of 10,000+ websites. On chain, nearly all UIDs and incentive sit with eleven coldkeys and miner UIDs turn over within days.

How it works

Miners

Run the neuron from the repo, register on netuid 33 (testnet is 138) and answer tasks with your own LLM. For conversation tagging, the task people discuss in chat, a miner receives one masked window of up to 10 lines of a longer conversation and returns a list of topical tags; the validator computes the embeddings itself, so miners do not need to send them (team confirmed 2026-09-19). Other task types in the code: webpage metadata, survey tagging, named entities, skill generation, and skill_coverage_evaluation, where the miner writes a skill plus tests for it. A project moderator said on 2026-09-08 that the subnet sends several of these task types and that the repo ships only default code. Miner IP addresses are committed on chain in encrypted form, so the metagraph shows the same address for everyone; the team says this protects miners from DDoS. On chain (block 9343853, 2026-10-23) the median miner UID was registered 2.5 days earlier and the oldest 27 days earlier.

Validators

Each validator needs an API key for the ReadyAI Conversation Server (issued after a stake check) and a private commitment key that the team hands out to validators, so task supply and validator onboarding go through the team. A validator fetches about 10 task bundles, cuts each into up to 5 tasks, sends each task to 6 random miners (the README says 3; the code default is 6) and scores the replies against ground-truth tags it built from the whole conversation. Embeddings are made with OpenAI text-embedding-3-small (hard-coded in the code; the large model named in config files is only written into the record sent to the team server). On mainnet validators ignore LLM overrides and use the in-code default (OpenAI gpt-5.2). Results are uploaded to the team server at the end of each loop. On chain there are 10 validator permits: two validators hold about two thirds of the dividends, and the owner's own hotkey holds a permit but its last weight update on record is over 5 million blocks old (about 700 days).

Incentive

Per-tag score is the cosine similarity between the tag's embedding and the average embedding of the ground-truth tags. The set score is 55 percent mean of the top 3 unique tags, 25 percent mean, 10 percent median and 10 percent max, with multiplicative penalties for few tags, no overlap with ground truth or a very low best score; fewer than 3 tags scores zero. Scores are smoothed with a moving average (alpha 0.1). The weights a validator sets are rank-based: miners are sorted by score, ties are broken randomly, and weight falls along a cubic curve whose top is about three times its bottom; every serving miner also gets a tiny baseline weight. Chain read at block 9343854 (2026-10-23) agrees: 242 of 256 UIDs have incentive, the best UID has 0.6 percent, commit-reveal is off, and each active validator's top target holds only 0.6 to 0.75 percent of its weights. The emission split on chain is 18 percent owner, 41 percent validators, 41 percent miners, and miner emission aimed at owner hotkeys is configured to be burned. The code's miner burn rate is 0 (removed 2026-06-30; no validator row on chain shows a burn share today); open pull request 139 would set it to 25 percent.

Getting started

  1. Clone the repo, copy env.example to .env and fill in an OpenAI key and a Weights and Biases key (both are required for miners and validators).
  2. Check that your miner port is reachable from outside; the moderator and team name this as the most common reason a miner gets no requests.
  3. Start on testnet (netuid 138) with the miner command in the README, ideally also run a validator there to see both logs; the team says testnet is for checking setup, not for competing.
  4. Build a local test set with the repo's code (generate your own tasks and ground truth) and compare miner changes in a closed loop before registering on mainnet; validator ground truth is not published.
  5. Registration on mainnet was cheap on 2026-10-23 (about 0.055 TAO) but all 256 slots are full and most miner UIDs are under a week old, so expect to be replaced if you score low outside the one-day immunity period.
  6. Register on netuid 33 and run neurons.miner; validators additionally need a ReadyAI Conversation Server key and the commitment key from the team. Check pull request 139 first: if it merges, validators will send tasks in random order and 25 percent of weight goes to the owner UID.

Caveats

  • The chain numbers are one snapshot (block 9343844 to 9343854, 2026-10-23). The chain proves that eleven coldkeys hold 239 of 256 UIDs; it does not prove they share one operator. That claim comes from a participant's funding-history and transaction-ordering analysis posted on 2026-10-20, which was not re-run here, and the team says several UIDs per operator are allowed.
  • The claim that most newcomers are removed within 48 hours of registering was not verified: a snapshot only shows that no miner UID is older than 27 days and the median is 2.5 days.
  • Which task types mainnet serves right now is decided by the team's server and is not visible in the repo; a project moderator listed several types on 2026-09-08 and chat shows conversation tagging is what miners discuss most.
  • The README says three miners per task and GPT-4o; the code defaults are six miners and gpt-5.2.
  • Pull request 139 is not merged, so the 25 percent burn and random task order are not in any released validator; no validator's weight row on chain shows a burn share today (each active validator's largest weight is under 1 percent). Whether the burned share would be destroyed or paid out depends on the subnet's burn setting, which is currently 'burn'.
  • Task supply, validator keys and the commitment key come from the team, so the subnet depends on team-run services.
  • Revenue figures and the 75 percent buyback share are the team's statements. Two buybacks (9.2 and 17.07 TAO) were confirmed on chain; the September one was not located.
  • Skill Store 33, the MCP package and the new dataset are announced but not launched as of 2026-10-23; the readyai.ai docs page says it is in internal testing and the home page statistics are labelled March 2026.
  • The benchmark claims about skills (cost and quality gains) are the team's own and were not reproduced.
  • A community moderator hired by the project answers many miner questions in the channel; those answers are not official team policy.

What it is

AdTAO (SN21) is a prediction contest for Google Ads. Miners submit containerised models that forecast how real advertising changes (budget edits, bid strategies, pauses and similar) will move cost, conversions and efficiency over 7, 14 and 28 days. The team runs every admitted model each day on a fresh basket of real account changes, scores it once the outcomes settle and pays the most accurate models, with the best one used live on customer accounts. The on-chain identity describes the subnet as counterfactual impact prediction for advertising interventions.

How it works

Miners

Miners ship a model, not daily predictions. They build a container image that reads one account-change episode per line and returns P10/P50/P90 ranges for cost, conversion and efficiency changes at 7, 14 and 28 days, push it to a public registry and commit its digest on chain. The subnet's own runner pulls the image every day, runs it offline (no network, 1 GB memory, 15 CPU minutes per basket) and records the output. A new digest first passes an admission test: identical output on repeat runs, a better score than a naive baseline, and at least 90 percent of the reference model's coverage. Miners also hold 1,000 alpha on the miner hotkey to be paid.

Validators

The team's own pipeline, not individual validators, builds the daily basket of real account changes, collects settled outcomes and scores each prediction once, 10, 17 and 31 days after the basket day for the three horizons. A score blends interval accuracy, calibration, direction and goal-metric accuracy and is measured against the average of all miners on the same change; standings use the last 28 days with a 7-day half-life. Validators fetch the team's daily weight vector with an API key and set it on chain. Signed daily receipts are published so anyone can recompute scores.

Incentive

Standings are ranked and mapped through a published curve: 50, 25 and 10 percent for ranks 1 to 3, then each further rank gets 80 percent of the one before, for at most 20 earners, renormalised. Identical or near-identical models pay only the earliest submission, and one hotkey per coldkey is paid. To be seated a hotkey needs 250 scored predictions, 7 scored days and the alpha hold. A separate, stricter rule picks the champion model that runs live. The team also applies a burn share whose current level was not read. At block 9334296 (2026-10-21), 8 of the 9 validators with revealed weights put their top weight on UID 72, which was first on the public leaderboard that day.

Recent activity

  • 2026-10-20 (#21-adtao, GitHub commit log) Team said two scoring changes are built but switched off: no efficiency result when spend has zero conversions, and a count-based score for small campaigns shown beside the current score before it counts. Dates are to be announced first.
  • 2026-10-18 (#21-adtao, GitHub commit log) Team said some models were not run on baskets 2026-10-05 to 2026-10-12 because of a problem on its side. Those days were excused from the absence charge, the baskets were re-run with each model's committed image, and the recovered predictions count on horizons that had not yet settled.
  • 2026-10-14 (#21-adtao) Miners asked whether the operator-run miners train on data that is not in the public slices, pointing to a dated data file in the operator's public image. The team said they use only public slices and are scored identically; the question was not settled in chat.
  • 2026-10-13 (#21-adtao, GitHub docs) Team announced that from the 2026-10-20 run every episode lists the 28-day horizon and counts as covered only if all three horizons are returned; a few miners that skipped 28 days had been turned away at admission.
  • 2026-10-09 (#21-adtao, GitHub release) Training data v4 published: 27,768 episodes with settled labels, shaped exactly like the live daily basket (change windows 15 June to 14 August 2026).
  • 2026-09-17 (#21-adtao, GitHub docs) A standing rule took effect so a replaced model's old results fade as the new model builds evidence. Miners checked the first proposal against public receipts, and the team withdrew one part (ageing results from the prediction day) because it would have shrunk the 28-day horizon's share.
  • 2026-09-10 (#21-adtao, GitHub docs) After a proposal and miner feedback, the team said it would slow the reward curve's tail so each rank after third gets 80 percent of the previous share instead of 50 percent.

Getting started

  1. Register a hotkey on netuid 21 (mainnet); the team said on 2026-09-30 that onboarding is on mainnet, not testnet 466.
  2. Create the one-time ed25519 signing key and register its binding on chain (quickstart steps 3 and 4).
  3. Start from the reference model in the repo and train on the published slices (training v2, v3 and v4 releases).
  4. Make the container deterministic and return 7, 14 and 28 day blocks for every episode, then push it by digest to a public registry.
  5. Commit sn21-model:v1:<repo>@sha256:<digest> on chain; to protect a new model, commit while the image is still private, then make it public and keep it public.
  6. Hold at least 1,000 alpha on the miner hotkey and check admission and first settle date on the miner-status page.

Caveats

  • The team's off-chain pipeline supplies the baskets, outcomes, execution and scoring on real account data. Receipts are signed and published, but this research did not recompute any day.
  • Operator-run miners (UIDs 1, 154 and 221) compete under the same rules. The team says they use only public training slices; miners questioned this on 2026-10-13 and 14 and it cannot be verified here.
  • The repo docs disagree in places: the model spec still mentions a 7-day settling window and a 35-day standing window, while the scoring doc and a sampled receipt show 2 days and 28 days.
  • The model spec says a basket is about 250 episodes, but a miner cited a daily manifest of 1,151 episodes on 2026-10-04; the current size was not checked.
  • Several rules exist in code but are switched off or only planned (zero-conversion null efficiency, count score, stopping absence charges for departed hotkeys, keeping the last admitted model, closed-while-earning image privacy).
  • The current burn level was not read; the docs call burn figures indicative and adjustable at any time. The leaderboard header says 118 scored while the list shows 120, and the site itself says the chain and repo are authoritative.
  • Chain weights were read only as an aggregate (47 validators with permits, 9 with revealed weights) and were not matched to payouts.

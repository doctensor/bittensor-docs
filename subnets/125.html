  • Miners submit training algorithms; one team validator trains a 360M model with each and pays only confirmed gains over the best.
  • Pay is thin: three miners have ever earned, one holds 78% of payouts, and 33% of miner weight burned in the latest round.
  • Each submission costs 0.85 TAO. No GPU is needed to submit, but real research needs compute and ML skill.
  • Optimizer payouts shrink by formula (34% paid now, about 20% by 2026-11-06) unless someone beats the 2026-10-06 best.
  • Main risks: one team validator decides scores, 0 to 1 submissions per round, and 30-day TAO outflow (-455 TAO; flat since 10-25).

What it is

Refinery (SN125) pays for research that helps open language models train better. Challenge 1 asks for optimizers that reach a lower validation loss than the current best on a fixed compute budget; Challenge 2 (open since 2026-10-19) asks for a refiner that decides what a fixed model reads and learns from.

How it works

Miners

Miners write an optimizer or refiner in Python, test it on their own compute and prepay evaluation credits. A commit with no credit is rejected.

Validators

The team validator trains each submission on one rented B200 for at most 20 hours (a 360M-parameter model on FineWeb-Edu). Optimizers are scored on held-out loss, refiners on a benchmark suite; a winner needs a second run to confirm. Rounds are meant to be daily but drift by hours.

Incentive

Miners get 41% of emission, half per challenge. Each confirmed gain earns credit that halves every 14 days; a pool pays only as far as credit covers a reference level that rises for 56 days. The unpaid share goes to UID 0, the owner slot, which burns it.

Roles and requirements

Miner Medium barrier

Writes an optimizer or refiner, serves its source, prepays an evaluation credit and reveals the code when asked.

  • Fee = estimated rental cost of one full run plus 10%. It is never refunded in TAO; a credit is returned only for validator-side failures.
  • One Python file under 1 MB; commit its hash, then reveal. Only the pinned validator hotkey can query your source server.
  • A new best must beat the frontier by the bar (floor 0.03 nats; 0.02 suite points for refiners) and pass a second validator-funded run.

Validator High barrier

Trains and scores submissions and sets weights; only the team's validator (UID 203) may query miners.

  • 11 of 12 permit holders set weights within one tempo on 2026-10-28, all with the same top target; how they get the vector is undocumented (no code in the repo).

Getting started

  1. Use Linux and Python 3.12, install the repo requirements and read MINING.md.
  2. Start from the optimizer or refiner template and check your candidate locally.
  3. Test against the published baseline before paying.
  4. Verify the fee, treasury and validator in the signed round announcement before sending funds.
  5. Register a hotkey, open a public port, fund credits, then commit and reveal your source.

Caveats

  • Dashboard figures are team-published and unchecked, though its weight split matches the chain.
  • All 11 weight-setting validators carry the team validator's vector; how is undocumented.
  • The refiner suite is called a placeholder in its own spec and the held-out loss gate is off: all 10 results have worse held-out loss than baseline (2.86 to 3.24 vs 2.59).
  • The team says it runs no miner; the chain fits that but cannot prove it.
  • The review planned for about 2026-10-20 has no recorded outcome. The repo has no LICENSE file.

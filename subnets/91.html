What it is

Cascade trains time-series forecasting models by making the training data the competition. Miners write synthetic-data generators; the owner's trainer trains each one, validators score the result on private real-world data, and the best generator holds the throne.

How it works

Miners

A miner writes a generator: Python code, fully set by its seed, that streams synthetic series (v2: exactly 32 channels). The operator's CPU machines generate the data; the miner pays for one rented GPU training run.

Validators

The owner's trainer trains each entry and signs the record; validators check it and score private held-out windows. A challenger must beat the king by a bar that falls with the king's tenure; v2 adds a public-benchmark gate.

Incentive

King of the hill. A new v2 king starts at 50% of the miner-side weight while eras are random-init (first 7 days), gains 10 points per passed check up to 95%, and the last former king keeps 5% for about 5 days; unclaimed weight burns.

Roles and requirements

Miner High barrier

Writes a 32-channel synthetic-data generator and pays for one rented multi-GPU run per entry.

  • Default pods stay under the operator's caps ($40 an hour, about $110 a leg); plan for up to $105 (8xH100) or $210 (8xH200).
  • Drained Lium keys stopped some evals (2026-10-31); a $30 waste cap followed.
  • A pod that went dark cost one miner $56 (2026-11-05); dark hosts are now quarantined for 24 h.
  • One entry per hotkey per round (about 3 hours).

Validator High barrier

Checks the owner's signed training record, scores private windows and sets weights.

  • Satellite validators replay the owner's signed receipts and never re-score; a full evaluator and the owner's main validator need a GPU.
  • On 2026-11-06, 9 uids held a permit and 8 had set weights within a tempo; the king (uid 220) holds one but has never set weights.

Getting started

  1. Read the v2 miner intro and FAQ; v2 is open.
  2. Clone the repo, pip install -e '.[hippius,chain,generation]', and commit only through the cascade CLI.
  3. Write a 32-channel generator, run cascade verify, then cascade iterate (scores you and the king on one pool).
  4. Register a hotkey on netuid 91 (0.1 TAO), set a Lium key budgeted for the plan-for cost, then cascade submit --yes and cascade status --watch.

Caveats

  • The first v2 king and the old king (uid 31) share one coldkey with 16 of 256 uids; a coldkey is not one person.
  • The owner trains, signs and holds the private windows, and has used that power (a king removed 2026-09-28); cascade-audit trusts the recorded scores.
  • All 8 weight-setters submit the same row, so chain data cannot show independent scoring.
  • The first v2 king came four days after launch; 9 of 39 feed entries failed; kings' benchmark gains are unverified.
  • Chat after 2026-11-01 was not read.

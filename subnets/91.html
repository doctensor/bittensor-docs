What it is

Cascade trains time-series forecasting models by making the training data the competition. Miners write synthetic-data generators; the owner's trainer trains each one, validators score the result on private real-world data, and the best generator holds the throne.

How it works

Miners

A miner writes a generator: Python code, fully set by its seed, that streams synthetic series (v2: exactly 32 channels). The operator's CPU machines generate the data; the miner pays for one rented GPU training run.

Validators

The owner's trainer trains the king and each challenger and signs the record. Validators check it and score forecasts on private held-out windows. The challenger must beat the king by a bar that falls with the king's tenure; v2 adds a public-benchmark gate.

Incentive

King of the hill: the king and up to four former kings share the weights (about 52, 26, 13, 6 and 3%); losers earn nothing. Until a v2 king is crowned, lane A is capped at 5% of emission and the rest goes to the burn uid.

Roles and requirements

Miner High barrier

Writes a 32-channel synthetic-data generator and pays for one rented multi-GPU run per entry.

  • Default pods: 8xH200 (about $42), 8xH100 ($59), 4xH200 ($62); 4xH100 ($88) only with --gpu and your own --max-price (docs, 2026-10-29). Blackwell GPUs are unsupported.
  • One entry per hotkey per round (about 3 hours); hotkeys burned in v1 can be reused (team, 2026-10-30).
  • Code on main (2026-10-31): a leg that cannot finish is aborted unburned as an operator fault; memory use is unpublished.

Validator High barrier

Checks the owner's signed training record, scores private windows and sets weights.

  • Satellite validators replay the owner's signed receipts and never re-score; a full evaluator and the owner's main validator need a GPU.
  • On 2026-10-31, 9 uids held a permit and 8 had set weights; 1 had not in over 5 tempos.

Getting started

  1. Read the v2 miner intro and FAQ; v2 is open and no verdict is out yet.
  2. Clone the repo, pip install -e '.[hippius,chain,generation]', and commit only through the cascade CLI.
  3. Write a 32-channel generator, run cascade verify, then cascade iterate (scores you and the king on one pool).
  4. Register a hotkey on netuid 91 (0.1 TAO), set a Lium key, then cascade submit --yes and cascade status --watch.

Caveats

  • No v2 verdict, king or pay change yet; the carried king (uid 31, since 2026-10-17) shares its coldkey with 18 other uids.
  • The owner trains, signs and holds the private windows, and has used that power (a king removed 2026-09-28).
  • All 8 weight-setters carry the same top target, so chain data cannot show independent scoring.
  • Reliability is uneven: late first v2 verdict; code says legs ran far slower than planned, fix deployment unknown. Benchmark gains of kings are unverified.

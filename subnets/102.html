What it is

Connito (SN102) is a subnet for collaborative training of a Mixture-of-Experts language model. The base model, Qwen3.6-35B-A3B, stays frozen; miners train only a small added residual expert and gate per MoE layer. Validators score each submission against the pretrained base, publish the round's best residual as the starting point for the next round, and set weights. The team describes the longer goal as cheaper training of very large models, and has floated a training-as-a-service product. Its next incentive, announced on 2026-10-15 for 2026-10-30, is described by the team as "dataless expert fine-tuning": a customer gives a task description, and a second miner role writes the evaluation prompts.

How it works

Miners

Each cycle a miner fetches the latest published winner, trains a residual (about 250 MB) on the round's data (PubMed full text 80 percent, C4 20 percent, per the team), uploads it to Hugging Face and posts two on-chain commits (a signed hash and a hash commit with repo and revision) inside the commit windows. Team hardware guidance of 2026-10-14: one 48 GB GPU (L40S or A6000 class), about 64 GB RAM, about 100 GB disk, driver 570 or newer. Malformed shards, NaNs and untrained experts are refused.

Validators

Validators load each miner's residual onto the frozen base and measure gain on the task data, loss rise on C4 replay data, and how often the gate fires (target about 20 percent of task tokens, quiet on C4). A C4 loss rise above 0.02 scores zero. Phases and their lengths come from a cycle API run by the subnet owner, not from the repo; a cycle is 524 blocks, about 1.75 hours. Not every miner is checked every cycle: cohort groups A and B are checked most, group C rotates, and the rest are checked about every third cycle (team, 2026-10-05). On chain (block 9335301) six UIDs hold validator permits on six different coldkeys; five had set weights, including the owner's own validator on UID 0, and one permit holder had not set weights for about 2.8 days. The public dashboard API listed the owner validator and one other as online.

Incentive

Per the repo, each round only the top three miners with a positive score earn rank points (2.25, 1.5, 1.0); a rolling 8-round average then sets weights. Each validator reserves 25 percent for UID 0 (the owner), then gives 98 percent of the rest to the top three of the consistently scoring miners and 2 percent to the next five. If nobody qualifies, that share goes to UID 0. Chain check at block 9335285: four of the five validators that had set weights submitted the identical vector this formula predicts (25.0 percent to UID 0, 73.5 percent across three miners, 1.5 percent across three more); the fifth put about 73 percent on a single miner. Seven UIDs received incentive. The subnet's emission split is 18 percent owner, 41 percent validators, 41 percent miners, commit-reveal is off, and the recycle-or-burn setting reads Burn, so miner emission aimed at the owner UID is burned rather than paid. The team said the owner validator carries most of the stake; on chain it held about 47 percent of dividends and a second validator about 42 percent in the last epoch, so the owner's is the largest but not the only one that matters.

Getting started

  1. Read the miner prerequisites and the docs/miner-faq folder in the repo (hardware, config, scoring, troubleshooting).
  2. Use a 48 GB GPU, a recent NVIDIA driver and the Python stack pinned by the release; download the pinned Qwen3.6-35B-A3B revision (about 72 GB).
  3. Run the current release tag (v0.7.1 at last check, 2026-10-21) so your residual matches the active task.
  4. Check the phase API, then post both on-chain commits before the commit phases end; a late or half-posted commit is skipped.
  5. Watch the #102 channel and repo tags for the announced incentive change before investing in long runs.

Caveats

  • Chain figures are one snapshot (block 9335285 to 9335301, about 2026-10-22 00:00 UTC). The owner validator had been down for part of 10-20 and 10-21, so weights move with validator availability.
  • The next incentive (model role plus prompt role, LLM-judged, preliminary numbers) was described on 2026-10-20 and announced on 10-15 for 10-30. No code for it exists on any of the repo's 213 branches (newest commit 2026-10-16), so the scoring above applies until it ships.
  • Validator and dashboard stability: miners reported the 3x0.25 fallback again on 10-21 after v0.7.1 and the team said it was escalated with no fix announced; the chain vector at the time of the check followed the normal formula. The dashboard gateway flagged its data as stale (polled 2 of 5 configured validators).
  • One permit holder (UID 103) had not set weights for about 2.8 days; the dashboard shows three of five configured validator slots as offline or unconfigured.
  • Miners dispute each other repeatedly. On chain, the 7 paid UIDs sit on 6 coldkeys (two share one), which is not evidence of a rule breach by itself; a report of UID 155 as top miner with zero score was not reproduced on chain (no incentive at block 9335285).
  • The repo README links to connito.ai/docs pages that still returned 404 on 2026-10-21; the working docs site is doc.connito.ai.
  • The cycle API, phase lengths and validator whitelist are run by the owner and are not in the repo.
  • The subnet previously hosted another project (Vocence) before Connito; older chat refers to it.

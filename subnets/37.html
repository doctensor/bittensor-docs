What it is

Aurelius runs a competition in which miners train sparse autoencoders (SAEs), tools that read a model's internal activations, for one pinned model: OLMo-2 7B, layer 16. An evaluator scores how much of the model's accuracy each SAE keeps, and the champion takes the reward. The team says the SAEs feed its Proba product for debugging fine-tuning data.

How it works

Miners

Miners train an SAE (32,768 features on 4,096-dimension activations) on their own GPUs, export two files and run the miner service on a Linux machine with a public IPv4 address. Each evaluation costs 10 work tokens (WT), bought with SN37 alpha at 1 WT per alpha.

Validators

The chain allows one validator permit (cut from 64 on 2026-10-10; the team calls it null consensus mode). Its evaluator splices each SAE into the model on a rotating text draw and measures the loss recovered, with sparsity, copying and probing checks. The evaluator code is not public.

Incentive

A 70% base burn comes first. The champion's share is scaled by its SN37 alpha (about 16% at 100 alpha, 95% at 10,000); anything unpaid is burned. A challenger must beat the champion by 0.003, or a quarter of its remaining gap if larger; ties keep the incumbent.

  • Team (10-06): new versions need much more validator resources; auto-update is off by default.

Getting started

  1. Read INCENTIVES.md and lanes/lane1.md in the repo; the miner asks you to confirm the incentive terms.
  2. Prepare a Linux server with Python 3.11 or 3.12, uv and a public IPv4 address; register a hotkey on subnet 37 (burn 0.0005 TAO on 2026-10-30) and hold alpha.
  3. Install per the README, make a hotkey-only wallet copy, fill in .env and run aurelius-miner serve --netuid 37 --port 8091.
  4. Buy WT with aurelius-miner fund (preview, then --execute); check the repo's runtime pin first.
  5. Train an SAE with SAE-Lens 6.46.0, check it with aurelius-sae check, then upload, stage and track it with aurelius-sae status.

Caveats

  • The docs call the rules an open beta that can change at any time; the signed config is authoritative and rewards may be adjusted retroactively.
  • Chain weights are one validator's opinions, not payouts. The champion's identity and score are not public (a miner's 0.99383 is unverified).
  • README and .env.example pin runtime 479 while the 2026-10-20 funding update admits 481; check before sending funds.
  • A stake-retention mechanism (hold-time credit, exit penalties, a WT bonus) is built but disabled and unpublished.

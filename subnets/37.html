What it is

Aurelius runs a competition in which miners train sparse autoencoders (SAEs), interpretability tools that read a model's internal activations, for one pinned model: OLMo-2 7B at layer 16. An evaluator scores each submission by how much of the model's prediction quality the SAE preserves, and the winner takes the lane. The team says submitted SAEs feed its Proba product for debugging fine-tuning data. The repo describes SAEs as the first lane, with probes and steering vectors possible later.

How it works

Miners

Train an SAE on your own GPUs (32,768 features on 4,096-dimension activations), export a bundle of two files (cfg.json and sae_weights.safetensors, up to 2 GiB), then run the miner service on a Linux machine with a public IPv4 address and a hotkey-only wallet copy. Upload and stage the bundle; the evaluator pulls it. Each evaluation costs 10 work-tokens (WT), bought by transferring SN37 alpha at 1 WT per alpha. Uploading alone does not submit.

Validators

The chain shows a single validator permit (max_validators was cut from 64 to 1 on 2026-10-10, which the team called null consensus mode). Evaluation uses a rotating text draw seeded by a finalized block: the SAE is spliced into the model and cross-entropy loss recovered is measured, plus checks on sparsity (mean active features 40 to 120, at most half dead), copying against earlier decoders, and an SAE-Bench probing and absorption battery. The public repo has the miner and shared protocol, not the evaluator or validator code.

Incentive

Only the eligible rank-1 champion gets a positive lane score. A challenger must beat the incumbent on the same draw by at least 0.003, or a quarter of the incumbent's remaining gap if larger; ties keep the incumbent. A base burn of 70% is taken first, then the champion's share is scaled by a multiplier based on SN37 alpha its coldkey owns (about 16% at 100 alpha, 95% at 10,000), and anything unpaid is burned. At block 9334315 about 71% of incentive sat on the owner-keyed UID 200, which the repo names as the burn destination.

Recent activity

  • 2026-10-20 (#37 aurelius) After miners said the top SAEs were within about 0.001 and the 0.003 minimum gap blocked challengers, the team said the gap is partly intended but it would adjust the rules to increase competition.
  • 2026-10-18 (#37 aurelius) A miner reported seven straight evaluations failing with an infrastructure error. The team said they were marked refund-eligible and that it fixed the issue halting the competition.
  • 2026-10-17 (#37 aurelius; GitHub repo Aurelius-Protocol) A miner found the fund command refused the chain's runtime version. Repo fixes followed on 2026-10-17 (runtime 479) and 2026-10-20 (runtime 481).
  • 2026-10-15 (#37 aurelius) The owner said the new incentive mechanism was up and running and that mining was officially live, with the public miner repo linked.
  • 2026-10-10 (#37 aurelius (hyperparameter tracker and team reply)) Subnet settings changed to a single validator (commit-reveal was toggled off and back on). The team described this as a move to null consensus mode while testing the public miner.
  • 2026-10-06 (#37 aurelius; GitHub repo Aurelius-Protocol) The team told validators the next versions need much more compute including GPUs, and disabled auto-updating validators until they opt back in. The repo added a validator master switch that defaults to off.
  • 2026-09-17 (#37 aurelius) After holders asked about missed deadlines, the team said the new incentive mechanism was delayed by testnet bugs and that Proba, its fine-tuning data debugging product, was still in a design-partner stage.

Getting started

  1. Read INCENTIVES.md and lanes/lane1.md in the repo; the miner asks you to accept the incentive terms before serving or funding.
  2. Prepare a Linux machine with Python 3.11 or 3.12, uv and a public IPv4 address, plus a hotkey registered on SN37, TAO for fees and SN37 alpha for evaluation fees.
  3. Install per the README, make a hotkey-only wallet copy with prepare_wallet_view.py, fill in .env, and run aurelius-miner serve --netuid 37 --port 8091.
  4. Buy WT with aurelius-miner fund (preview first, then --execute) and wait for the signed receipt; a chain transfer alone does not credit WT.
  5. Train an SAE for the pinned model and layer with SAE-Lens 6.46.0, check it with aurelius-sae check, then upload and stage it and watch results with aurelius-sae status --refresh --accounting --netuid 37.

Caveats

  • The docs call the incentive rules an open beta that can change at any moment, say the signed public config is authoritative, and say the team may audit and adjust rewards retroactively.
  • Only the champion earns. Miners said on 2026-10-19 the top SAEs were nearly tied, and one stated the champion's score (not verified); the team said on 2026-10-20 it plans to tweak the rules.
  • The evaluator and validator code is not in the public repo, and the chain shows one validator permit, so weights reflect one operator's evaluation. Chain weights are opinions, not payouts.
  • Chain and config were read once, on 2026-10-21 (config version 31, block 9334317). The README and .env.example pin runtime 479 while a 2026-10-20 repo update admits runtime 481 for funding; check before sending funds.
  • A stake-retention mechanism (hold-time credit, exit penalties and debt, a WT bonus) is described as built but disabled, with details unpublished.
  • The team's launch dates slipped repeatedly between July and mid-October. Proba and the claim that miner SAEs feed it come from the team and were not verified.
  • Not read: the whitepaper, evaluator code, any leaderboard or champion identity, and market data. Chat is moderated against price discussion, so none is included.

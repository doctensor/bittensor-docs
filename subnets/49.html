What it is

Nepher Robotics runs discrete tournaments in which each round fixes one robot and one NVIDIA Isaac Lab task, such as a Unitree Go2 quadruped solving mazes from LiDAR. Miners train a control policy locally and upload it as an agent; validators score every agent in isolated GPU sandboxes on hidden benchmark scenes. After a manual review by the Nepher team, a podium of up to three miners receives the subnet's miner weight during a reward window. The team positions the winning policies as assets that companies could later buy, test on real robots or sponsor.

How it works

Miners

Miners register a hotkey on subnet 49 (the registration cost on chain was the 0.05 TAO minimum on 2026-10-21), get an account and API key on the Nepher platform, clone the task repository published for each tournament and train a policy in Isaac Sim 6.1 and Isaac Lab 3.0.0 (a GPU with 24 GB or more is advised for training). They check and submit an agent archive with the nepher-cli tool; the archive is signed with the hotkey and must include the training and play scripts. Only the latest upload per hotkey counts, and each upload costs a fee from a TAO platform balance. The team allows tuning of the whole training project, but not changes to termination logic or the shared environment components that affect scoring. Both nepher-cli and the nepher package were upgraded on 2026-10-21 and the team asked miners to update both.

Validators

Validators download each eligible agent, start a throwaway Docker container with Isaac Sim, run the eval-nav evaluation inside it and send the score to the Tournament API. The container has no wallet or Docker socket, limited memory, a 30-minute timeout and an outbound firewall with a domain whitelist. During the contest period a public benchmark gives a live preview leaderboard; a short warm-up window before the evaluation period stops public evaluation, and the final ranking comes from a private benchmark. The backend combines validator scores by stake weight, with ties going to the earlier upload. A lighter validator mode that only sets weights, without evaluating, is also offered. On chain, 15 uids held a validator permit on 2026-10-21 and 10 of them had set weights; the API reported 5 validators scoring the Go2 tournament on 2026-10-20.

Incentive

Each tournament has five stages: contest, submit, evaluation, review and reward. During the review stage the team checks the top entries for cheating and approves a podium of up to three, or declares no winner. In the reward window, validators give the whole remaining weight to the approved podium, by default split 7:2:1 (the docs site says 70, 20 and 10 percent). Outside a tournament's reward window, the preliminary leader gets a fixed 1 percent and unallocated weight goes to UID 0, which the docs call a burn. Weights are reset about every 30 minutes. The team said on 2026-10-19 that rewards are split by unique account and submission, so one person with several accounts gets a single share. Chain check at block 9335223 (2026-10-21): incentive sits on exactly three miner uids at 70, 20 and 10 percent, matching the API podium, and all 10 validators that had set weights name the same top uid at 70 percent and give UID 0 nothing. UID 0 is the owner's hotkey and also a validator that earns most of the validator dividends (74.5 percent), so its 37 percent share of last-epoch emission is validator dividend, not miner incentive and not a burn. The chain's emission split is the default 18 percent owner, 41 percent validators and 41 percent miners, and miner emission aimed at owner hotkeys is burned. Weights are validator opinions, and the podium itself comes from the team's backend and manual review, which cannot be checked in code.

Getting started

  1. Register a hotkey on subnet 49 with btcli, as described in the miner guide in the subnet repository (the on-chain registration cost was the 0.05 TAO minimum on 2026-10-21).
  2. Create a Nepher account and API key, then register your coldkey and send TAO to the platform balance to pay submission fees; the balance cannot be withdrawn.
  3. Install Isaac Sim 6.1 and Isaac Lab 3.0.0, clone the task repository linked on the tournament page and follow its README to train a policy.
  4. Optionally run the eval-nav harness locally to preview your score using the same configuration validators use.
  5. Install or upgrade nepher-cli and the nepher package (both were upgraded on 2026-10-21 and the team asked miners to update), log in with your API key, run the tournament check command on your agent folder and then submit it with your wallet name and hotkey.
  6. Validators need Docker, the NVIDIA container toolkit and a GPU (A6000 24 GB minimum, A100 recommended) following the validator guide; a CPU-only variant exists that only sets weights.

Caveats

  • The README and miner guide on the main branch still describe a winner-takes-all design, while the incentive document, the code and the live API use an approved podium (default 7:2:1) added around 2026-09-18. A miner asked on 2026-10-19 to go back to winner-takes-all; the team said it wants more miners to compete.
  • The docs site tournament page still lists Isaac Sim 5.1 and Isaac Lab 2.3.2 (checked 2026-10-21), while the repository, API and chat use 6.1 and 3.0.0 since 2026-10-05. Chat said the preliminary leader would get 0.5 to 1 percent in March; the code uses a fixed 1 percent.
  • Scoring across validators, the preliminary leaderboard, podium approval and the submission scanner run in a team-operated backend whose code was not found in the 17 public repositories of the organization. Winners are chosen after a manual team review; the rule that alternate accounts of one person share one reward, and the choice of the seventh-ranked entry for third place, are known only from the team's chat posts.
  • Three distinct coldkeys hold the paid uids on chain, which does not show whether the participants are independent. Public criticism in chat (2026-10-06, 2026-10-16 and 2026-10-19), including claims about miner independence, was disputed and could not be verified.
  • Two unmerged branches of the subnet repository (main has not changed since 2026-10-05, release tag v1.0.0) show where the code may go, but it is unknown whether validators run them. The branch feat/fix, committed on 2026-10-21, makes a failed API or chain lookup skip the weight update instead of burning on UID 0, retries validator-side evaluation failures instead of scoring them zero, runs miner code as an unprivileged user, and states in its docs that the sandbox does not prevent a miner from tampering with the score inside the simulator process (cross-validator aggregation is the defence).
  • The branch feat/brain-runtime (last commit 2026-10-13) is a draft specification for large-model tournaments in which miners keep weights in their own private Hugging Face repository and upload code plus a signed seal; validator code withholds payout until the winner's weights are archived by Nepher. The team teased a new tournament type on 2026-10-12 but has not said that this is it, and the Go2 tournament keeps the zip upload.
  • Chain reads are from the public node at blocks 9335223 to 9335252 (2026-10-21, about 23:50 UTC) and show validator opinions, not payouts. Five of the 15 validator-permit holders had not set weights for over two tempos. The reward window ends on 2026-10-23 08:37 UTC, after which the weight vector should change; this was not yet observed.
  • Scam warnings were posted on 2026-10-02 and 2026-10-05: moderators said unsolicited messages or friend requests claiming to be subnet support, including ones using moderators' names, are scams.
  • The incentive page on the docs site did not render for the researcher, so the repository copy was used.

What it is

Harnyx is a contest for deep-research agents. Miners upload one Python file that answers research questions with citations; validators run it and AI judges compare it with reference answers. The team aims to sell the result as a research API.

How it works

Miners

Miners write agent.py (one file, 1 MB) that answers a query with text and numbered citations, calling platform tools in a sandbox: LLM chat, web search and fetch, rerank, a decision model. Default budget 0.50 USD per task; time limit 70 to 300 seconds.

Validators

The team-run platform (not public) builds tasks, picks the champion and records the allocation. Validators run each agent in a sandbox, judge answers against references in both orders, and set weights from the platform's signed allocation; all 8 permit holders had done so within a tempo (360 blocks) on 2026-10-30.

Incentive

Emission splits 41% miners, 41% validators and stakers, 18% owner. On the miner side a daily champion takes a score-scaled top share and non-duplicate entries split the rest (rules below).

Roles and requirements

Miner Medium barrier

Writes a Python research agent run on daily tasks.

  • Each validator's run uses your stored provider keys, so every run adds to your bill.
  • Uploads close 15:00 UTC; small code edits still count as duplicates (team, 2026-10-23).
  • Black-box mining (a public endpoint) is described as unreleased.

Validator High barrier

Runs agents in sandboxes, judges answers, sets weights.

  • The weights call needs a validator signature; the allowlist covers only batch delivery (README).
  • 8 of 64 permit slots held; the owner holds 74% of validator dividends (2026-10-30).
  • Monitoring API: 9 endpoints, 4 healthy, 3 unhealthy, 2 unknown (2026-10-30).

How a batch picks the champion

  • Uploads close at 15:00 UTC; results arrive overnight.
  • Every non-duplicate agent does 10 qualifying tasks; the champion and up to 29 challengers then do 20 more.
  • A challenger takes the title with a 10% score margin, or an equal score at 10% lower cost, or equal score and cost at 10% lower runtime; earlier uploads get priority.
  • 12 of 14 completed batches (cutoffs 10-14 to 10-28) changed the champion; best raw score 0.08-0.35 after the 10-15 task change, 0.49 on 10-28.

Who gets paid

  • A new champion takes up to 50% of miner pay, 25% on a hold, 12.5% after, scaled by score: 24.6% at 0.49 (2026-10-30).
  • Other non-duplicate entries share the rest by stage and novelty. A failed batch splits pay equally; 1.57% of incentive burned through UID 0 (2026-10-30).

Getting started

  1. Read the mining runbook, clone the repo and run uv sync --all-packages --dev.
  2. Register a hotkey (burn 0.0531 TAO); set PLATFORM_BASE_URL, a Chutes key and a search key in .env.
  3. Run harnyx-miner-local-eval on agent.py and fix repeated failures; read the champion through api.harnyx.ai/mcp (MCP client).
  4. Store provider keys with harnyx-miner-config, then upload with harnyx-miner-submit before 15:00 UTC.
  5. Validators: follow validator/README.md; batch work needs team allowlisting.

Caveats

  • The platform that builds tasks and picks the champion is closed, and the repo licence is 'Proprietary'.
  • Research API usage and revenue are not visible; demand rests on the team's own words.
  • The task regime changes often and the title changes almost daily; scores before 2026-10-15 are not comparable.
  • Open: cause of the failed 10-15 batch, whether the 10-27 commit fixed DRACO, why the API's alpha estimate runs 24% above the chain.

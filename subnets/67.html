What it is

Harnyx is a contest for deep-research agents. Miners upload one Python file that answers research questions with citations; validators run it and AI judges compare it with reference answers.

How it works

Miners

Miners write agent.py that answers a query with text and numbered citations, calling platform tools in a sandbox: LLM chat, web search and fetch, rerank, a decision model. Default budget 0.50 USD per task; time limit 70 to 300 seconds.

Validators

The team-run platform (not public) builds tasks and picks the champions. Validators run each agent in a sandbox, judge answers against references in both orders, and set weights from the platform's signed allocation.

Incentive

Emission splits 41% miners, 41% validators and stakers, 18% owner. Two champion titles share a score-scaled miner budget; other agents split the rest.

Roles and requirements

Miner Medium barrier

Writes a Python research agent run on daily tasks.

  • Each validator's run uses your stored provider keys, so every run adds to your bill.
  • Small code edits still count as duplicates (team, 2026-10-23).
  • Keep a winning hotkey registered: unregistered shares burn through UID 0.

Validator High barrier

Runs agents in sandboxes, judges answers, sets weights.

  • The weights call needs a validator signature; the allowlist covers only batch delivery (README).
  • 8 of 64 permit slots held; the owner holds 73% of validator dividends (2026-11-13).

How a batch picks the champion

  • Uploads close at 15:00 UTC; results arrive 10 to 18 hours later (11.8 h for the 11-09 batch).
  • Every non-duplicate agent does 10 qualifying tasks; the main round adds 20 for up to 30 agents per title (README, 11-04).
  • A challenger takes a title with a score 10 points higher, or no lower score and cost or runtime down 10%; challengers go in upload order.
  • Overall score = 30% of mean F1 over all tasks + 70% of mean judge score on deep tasks; the F1 title uses F1 alone (README).
  • 20 of 26 batches (10-14 to 11-09) changed the champion; the 11-09 batch kept both titles after two challenger steps. No batch ran for the 11-10 to 11-12 cutoffs.

Who gets paid

  • The titles share 80% of miner pay times the Overall score (0.34): 27%. F1 gets 40% plus half the F1 gap between the champions (0.862 vs 0.786): 44%. Each title was retained once, so each is paid half: 7.6% and 5.9% (API, 11-13); a second retention quarters it.
  • Others share the rest in tiers from 1.78% (4 hotkeys) and 1.07% (25) down to 0.18% (20); 127 get nothing (API, 11-13). Lower title pay leaves them 81.9%.
  • A failed batch splits pay equally. Shares of 12 unregistered hotkeys burn through UID 0: 4.6% (5.0% on 11-10).

Getting started

  1. Read the mining runbook, clone the repo and run uv sync --all-packages --dev.
  2. Register a hotkey (burn 0.0179 TAO); set PLATFORM_BASE_URL, a Chutes key and a search key in .env.
  3. Run harnyx-miner-local-eval on agent.py and fix repeated failures; read the champion through api.harnyx.ai/mcp (MCP client).
  4. Store provider keys with harnyx-miner-config, then upload with harnyx-miner-submit before 15:00 UTC.
  5. Validators: follow validator/README.md; batch work needs team allowlisting.

Caveats

  • The platform that picks the champion is closed; the repo licence is 'Proprietary'.
  • The task and payout rules change often; scores before 2026-10-15 are not comparable.
  • Open: cause of the failed 10-15 batch and of the three missed daily batches (no error is public); the API's validator list lacks UIDs 12 and 246.

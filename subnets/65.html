What it is

TPN, built by the team Taofu Labs, runs timed competitions in which miners turn a given base language model into a quantized GGUF file that fits under a fixed memory ceiling and scores as high as possible on a benchmark. Each competition names its base model, memory cap, benchmark and prize split. Miners now run the benchmarks themselves on the team's paid benchmark service and submit the run ids with a timelocked on-chain commit; the leader validator then checks everything, ranks the entries and pays the top places. The subnet was a VPN subnet before it pivoted to this design.

How it works

Miners

A miner registers a hotkey, uploads one GGUF file to a private Hugging Face repo (one repo per submission, exactly one GGUF in it), and runs the competition's benchmark on the team's benchmark service, paying for each run in credits. Then the miner commits the repo, file, file hash, an immutable revision, the self-reported maximum memory and the benchmark run ids as a timelocked on-chain payload that nobody can read until the chain decrypts it around the commit deadline, which prevents copying. The repo must be made public before scoring starts, every benchmark run must have completed by then, and the reported memory must be within 1% of what the validators measure. Competitions pick the base model, the memory ceiling and the context length; the latest two use Ministral-3-8B Uncensored at a 32,768-token context.

Validators

One leader validator does the real work: it reads the revealed commitments, drops duplicates (the earliest reveal of a file hash wins), verifies each run id against the benchmark service, ranks candidates, and prechecks them one at a time in rank order inside a public Docker container. The precheck confirms the model derives from the base model (matching tokenizer and an embedding-similarity score of at least 0.80), measures memory with a CPU build of llama.cpp, and checks the file hash; a hash mismatch permanently bans the hotkey. Follower validators download nothing: they read the leader's finalized results and set the same weights. When no competition is paying out, validators copy stake-weighted consensus weights from the chain.

Incentive

In the ram-ceiling format used by the recent competitions, a model passes if its measured memory is under the cap and its score is the lowest of its benchmark results, so ranking is by score. Every competition so far has a fixed 25% share of validator weight, split among the top places: five places in competitions 1 to 4, the top three (60/25/15) in TPN-005 and the winner alone in TPN-006. Weights are set only from the end of the scoring phase and run for about seven days of blocks; winners who are no longer registered lose their share and any unallocated weight is burned to uid 0, so while one competition pays out about 75% of validator weight burns. Collateral was removed after competition 4 and the registration burn was cut from 0.5 to 0.2 TAO on 2026-10-01.

Recent activity

  • 2026-10-21 (TPN leader validator API) The leader's public state listed TPN-005 and TPN-006 as finalized (3 of 11 and 1 of 6 candidates scored). The TPN-006 winner scored 0.7493 at about 7.7 GiB of measured memory. Its scoring phase ends around 2026-10-21 and payouts run to about 2026-10-28 by block arithmetic.
  • 2026-10-19 (#tpn) Miners kept reporting benchmark runs failing on the service side, with credits held until released; the team said it was looking into them. The team also announced a quantization service on its benchmark site.
  • 2026-10-15 (#tpn, TPN leader validator API) TPN-006 launched: the same base model under an 8 GiB cap at 32k context, scored only on Fluid Bench, with a single winner taking the whole competition share.
  • 2026-10-14 (#tpn, TPN leader validator API) After miner feedback on TPN-005 (a closed benchmark, unreliable reads, tiny score gaps, and three paid places going to what a miner said were the same weights in different quantizations), the team said the multi-winner split is intentional, the benchmark stays closed to prevent overfitting, and a second scoring method based on KL divergence is in development. The leader's data shows the three winning scores differing by about 0.0014 and 0.0021.
  • 2026-10-05 (#tpn, TPN leader validator API) TPN-005 went live as the first round under Fluid Bench: an 11 GiB cap on Ministral-3-8B Uncensored, miners running the benchmarks themselves and submitting run ids, no collateral, and a 60/25/15 split among the top three.
  • 2026-10-01 (#tpn) The team released 'TPN v0.2: Fluid Bench', a private knowledge benchmark meant to resist overfitting, and a hyperparameter change cut the registration burn from 0.5 to 0.2 TAO. The team later said the benchmark scores across 800 knowledge domains and declined to say how answers are graded.
  • 2026-09-21 (#tpn) The team said competitions were halted because of overfitting and that a new validation mechanism had shipped but was not a long-term fix.
  • 2026-09-15 (#tpn) After competition 4, miners complained that near-identical models from one operator could fill several top-five places. The team said it had seen miners overfit the reward formula, that the results were not a useful product, and that it preferred sticking to the code over banning entries by hand.

Getting started

  1. List the live competitions with the tpn CLI (tpn competitions) or the leader's public competitions endpoint and note the block-based deadlines, the memory cap, the context length and the required benchmark epoch (TPN-005 and TPN-006 both use epoch-000001-r7).
  2. Install the CLI with the repository's install script and register your hotkey on netuid 65 (tpn register). As of 2026-10-01 the registration burn is 0.2 TAO and there is no collateral lock.
  3. Build or quantize your GGUF from the competition's base model, then measure memory with the public precheck container's local check at the competition's context length. Commit that figure; a claim more than 1% off the measured value fails precheck.
  4. Upload the file to a private Hugging Face repo with exactly one GGUF (tpn upload), then create an account on the benchmark service, add credits and create an API key.
  5. Run the competition's benchmark with tpn benchmark well before the commit deadline: each run is paid, runs have been failing on capacity and worker errors, and a run still in progress when scoring starts counts as zero.
  6. Commit with tpn commit, then make the repo public with tpn publish before scoring starts, and follow your entry with tpn status or the leader's state endpoint.

Caveats

  • Chain weights were not read. Per the docs, payouts begin only at the end of the scoring phase, so TPN-006 winnings had not yet reached the chain when this was researched; the 25% share, the burn of the remainder to uid 0 and the top-place splits come from the leader API and the code.
  • Competition specs and results live on the team's leader validator API, not in the git history, and the repository was last updated on 2026-10-08. Followers rely on the leader's published results, so the leader is a single trust point.
  • The benchmark is closed by design, runs only on the team's paid service, and the team has declined to say how answers are graded. Miners reported many failed or stuck runs (capacity errors, worker failures, credits held), with refunds and retries handled case by case, and the team said GPU availability on its providers was low in early October.
  • Rankings can be very close: in TPN-005 the top three scores were within about 0.002 of each other, and a miner reported that retraining the same recipe moved its score by about 0.016. The claim that the three winning files held identical weights was not verified (the leader data shows three different file hashes, two with identical measured memory).
  • A hash mismatch at precheck permanently bans a hotkey. A miner reported being banned wrongly on 2026-09-03 because of a faulty precheck container, and the team later unbanned one hotkey after fixing the container, so keep the committed revision and file untouched.
  • The team has said a KL-divergence scoring method is being built and that Lium GPU support is being added; neither had shipped as far as the chat read. Prices, token economics and emission amounts are not covered because the server bans price discussion.

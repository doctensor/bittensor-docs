What it is

Cacheon runs speed competitions for AI inference. The team picks a model and a workload and publishes the serving engine (SGLang) as the baseline. A miner submits a code bundle that replaces one registered part of that engine, either the model's modules or the scheduler's prefix cache, and the team's evaluator measures whether it serves the same workload faster without hurting output quality. Competitions are called arenas and come and go by announcement: GLM-5.3, DeepSeek-V4.1-Flash and Qwen3.8 have run, and Muse Spark Open opened on 2026-10-21. The repository is marked pre-release software.

How it works

Miners

A miner writes a bundle for one registered target, checks it locally with the repository's scan, verify and check commands, hosts the archive, pays the arena's fee to the subnet owner and commits it on chain. The bundle must be built against the arena's current SGLang baseline, which is a team-maintained fork for some arenas and changed on 2026-10-14. Miners may not change model weights, and the repository's latest commit says bundles that prune more routed experts than the stock engine does now fail. The current Muse Spark Open arena runs a large mixture-of-experts model on four B300 GPUs with speculative decoding, and the repository's arena README tells miners to confirm in a local check which model modules actually execute before paying for a submission.

Validators

The evaluator belongs to the validator. It builds and runs each bundle in isolated containers with no network access, replays a sealed workload (recorded coding-agent sessions for GLM, 16 to 24 concurrent sessions in the later arenas) against both the baseline and the candidate, and checks speed, graph safety and output quality in an audit. A separate publisher turns settled claims into weights and confirms them on chain. The public repository runs finalized intake only and does not ship a production arena provider, so the full evaluation cannot be run by a third party from the repository alone; the docs also say one validator's measurement is not globally trustworthy.

Incentive

A bundle earns credit only if it passes one complete audited run and beats the best earlier rewarded pass for the same arena and baseline by at least 1.5 percent. Credit is the logarithm of that improvement, multiplied by a waiting factor that grows with the square root of the time since the previous earning pass in that arena, and halved over a decay period that starts only once weights containing the claim are confirmed on chain. The decay period and each arena's share of the weights are set by the operator and not published. Fees are not rewards: each submission pays 0.5 TAO to the subnet owner, and the chain confirms the payment address is the current owner's coldkey. On the chain the owner takes 18 percent of emission and validators and miners 41 percent each by the subnet's split setting.

Getting started

  1. Read the repository's miner guide (overview, incentives, submitting) and the arena's README under examples/arena_inputs for the model, hardware, engine image and measured baseline.
  2. Open the dashboard before spending anything: its health and queue views show which arena is live, the fee, whether the evaluator heartbeat is fresh and how long submissions have been waiting.
  3. Install the package with Python 3.11 or newer and run the scan and verify commands on one of the examples to learn the bundle format.
  4. Build your bundle against the arena's current SGLang baseline and test on hardware like the arena's (four B300 GPUs for Muse Spark Open), including the local check that shows which model modules execute.
  5. Register a hotkey on subnet 14, then use the chain-submit command, which pays the fee to the subnet owner and commits the bundle; do not submit while the team has paused an arena.
  6. Follow the submission's state on the dashboard and ask in chat if it stays pending.

Caveats

  • Evaluation and weight publication run on team infrastructure. On chain, nine uids hold a validator permit and six set weights, all with the identical single-target row (the owner's among them); the other five sit on other coldkeys and probably copy the owner's vector, but who runs them was not found, and the public repository ships no production arena provider.
  • An arena's payout lasts only as long as the operator keeps it in the weights. Between the evening of 2026-10-20 and early 2026-10-21 the DeepSeek winners went from a share of 11 paid uids to nothing. Arena shares, decay period, fees and baselines are operator settings changed by announcement and none are published, so the 80, 100 and 10 percent figures from earlier in October are team statements that no longer describe the weights.
  • The evaluator has been paused or restarted repeatedly because the owner could not keep GPUs running at current submission volumes. On 2026-10-21 the dashboard showed stale evaluator heartbeats since about 04:20 UTC and a queue of five, so a 0.5 TAO fee may buy a long wait.
  • Miners disputed credit decisions and audit changes on 2026-10-16 and 2026-10-17. The repository's commit text shows the rules were later written into code, but the evaluator code was not audited here and the owner said on 2026-10-15 that submissions made during a pause would not be refunded.
  • Fees go to the subnet owner as an admission cost (confirmed against the chain on 2026-10-21). Revenue claims (about 100 thousand USD in a month, Affine on subnet 120 as first customer, buying alpha with revenue) are team statements that were not verified.
  • The chain's split setting says 41 percent of emission to miners, yet the winner's alpha was 50 percent of the subnet's last-epoch total on 2026-10-21; the difference was not explained.
  • Dashboard figures come from a public read-only API for the Muse Spark Open arena only; earlier DeepSeek standings were not available there. The scoring formula is taken from the repository's emissions policy document, not traced end to end through the code.

What it is

Cacheon runs speed contests for AI inference. Miners submit code that speeds up one part of a serving engine (SGLang); the team's evaluator checks that it is faster with no loss of quality. One arena is open (GLM-5.3-Flash on eight B300 GPUs); ten passes so far, the best 1.389x stock.

How it works

Miners

Build a bundle that replaces one part of the SGLang baseline, host it, pay the fee and commit it on chain; model weights may not change.

Validators

The team's evaluator replays a sealed workload against baseline and candidate and audits speed and quality. One signed weight offer goes out about every two hours; followers republish it.

Incentive

Credit needs one audited pass that beats the arena's best earlier pass by 1.5% (stock for the first) and grows with the log of the speedup. Older winners' shares decay and dilute as new winners arrive. Chain split: 18% owner, 41% validators, 41% miners.

Roles and requirements

Miner High barrier

Builds and tests a faster bundle for the open arena; pays a fee per entry.

  • Score: the mean of three throughput ratios against stock (96, 160, 224 sessions); decode must stay above 85, 82 and 80 tokens/s per user.
  • Ten passes in 6 days, 1.025x to 1.389x; 34 of 42 failed entries fell below the payment bar.

Validator High barrier

Nine permit holders, seven publish weights, all the team's one offer; the team does the scoring.

  • All seven weight-setters put uid 36 first (83.4%), then uids 244, 191, 35 and 140: the team's offer. Miners uid 244 and 191 hold permits and never set weights.
  • If the gateway fails, followers repeat the last offer for up to 12 hours, then send 100% to a burn hotkey.

Getting started

  1. Read the miner guide and the GLM arena README (arena_inputs/glm53flashpd on main).
  2. Check the dashboard queue; install the package (Python 3.11+) and run scan and verify on an example.
  3. Register a hotkey on subnet 14, build on the arena's SGLang baseline, beat the payment bar (about 1.410x stock), then chain-submit (about 0.5 TAO per entry).
  4. The kernel-challenge claim route is closed.

Caveats

  • Scoring and weights run on team servers; the chain shows what is paid, not that scoring is fair (one crown was revoked).
  • Pay moved within days (uid 35 68.2% on 11-05, uid 182 94.8% on 11-10, uid 140 62.5% on 11-14, uid 36 44.9% on 11-16 and 83.4% on 11-19); the decay setting is unknown.
  • The grading code was only partly read; the 11-15 merge was read by file list and doc patches only; who runs the followers and gets the 18% cut is unknown.
  • The evaluator stalled 44 and about 94 hours in early November and 11-10 to 11-12; it has run since 11-14; no cause is stated (chat after 11-01 unread).

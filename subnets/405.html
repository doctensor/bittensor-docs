What it is

ACORE AI is pitched as a platform for 3D virtual agents that talk and show emotion; its subnet was meant to supply the AI work. The code only turns text prompts into scored 3D models. It ran on testnet only, gave no mainnet date, and has been silent since December 2025.

How it works

Miners

A miner turns a text prompt into a 3D model and returns a preview image plus a .glb file. It passes the prompt, with a fixed style suffix, to its own text-to-3D service; the repo's bundled server is only a stub, so miners bring their own model. The miner's blacklist is meant to block unregistered callers but, as written, lets them through (code reading, not tested).

Validators

Each round (700 seconds by default) a validator sends up to 25 miners one prompt from a team-run API, with an 87-second limit. Its own scoring service renders each model from seven angles, rejects images that do not look like a real object, has Claude describe the preview and renders, and compares them with the prompt by text and image similarity plus a quality model.

Incentive

Score per round: 0.25 x prompt-vs-preview similarity + 0.5 x prompt-vs-render + 0.3 x preview-vs-render + 0.1 x quality; below 0.35 is zero. Scores are normalised and squared, averaged over time, and only averages above 0.4 earn weight, raised to the eighth power, so top scorers dominate.

Roles and requirements

Miner Medium barrier

Turns a text prompt into a 3D model (preview image plus .glb file) with a generator the miner supplies.

  • Reports idle or busy before each job; the prompt gets a fixed style suffix.
  • The repo's generation server is a stub (sleeps 5-15 seconds, returns a placeholder).
  • Output returns as base64 or presigned S3 links (needs AWS keys). No Dockerfile or .env example; MIT licence.

Validator Medium barrier

Samples miners each round, sends a prompt and scores the 3D models with its own scoring service.

  • Prompts come from a team-run API (api.acore.app, not called); a fixed list of 10 prompts is the test-mode fallback.
  • The scoring service needs pytorch3d, trimesh, CLIP and the operator's own CLAUDE_API_KEY.
  • Only the owner hotkey can send the team app's prompts through validators; this does not change scores.

Getting started

  1. Do not register on testnet netuid 405 for ACORE: since 2026-03-10 it is the Verathos project's subnet.
  2. To study the code, clone acoreai/subnet-acoreai and run pip install -e . in a Python virtual environment.
  3. Miner: run your own text-to-3D service on the port in --generation.endpoint (default 8093), then neurons/miner.py.
  4. Validator: start the scoring service in validation/ (serve.py, port 8094; GPU and Claude API key), then neurons/validator.py.
  5. No live ACORE netuid and no mainnet guide exist; both neurons take --netuid and --subtensor.network.

Caveats

  • Dormant and testnet only: no mainnet economics exist and testnet TAO has no market value. The team never said the project stopped.
  • The neurons on testnet slot 405 (21, with 4 validators setting weights on 2026-10-31) belong to Verathos, not ACORE; the link rests on Verathos's own posts, as the slot's chain identity holds only a name.
  • Scores rest on a team-run prompt API (not called) and the validator operator's own Claude API key.
  • The repo is a template fork: README mainnet and staging sections, the validation README and wandb defaults are leftovers, and the generation server is a stub, so a working node needs parts not in the repo.
  • The website (acore.app) and app (ai.acore.app) did not load from our server on 2026-10-31, so product claims rest on the repo, whitepaper and chat.

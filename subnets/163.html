What it is

Safe Scan (repo cancer-ai) runs model competitions: miners submit medical-imaging classifiers, such as skin-lesion models, and validators score them on data from medical institutions. It was mainnet subnet 76 until early 2026; the team then said it would keep testing on testnet, as netuid 163. It looks dormant: the comeback is on hold and no testnet validator has set weights for over 180 days.

How it works

Miners

Per the docs (written for mainnet SN76): miners train an ONNX model for the current competition (documented: Tricorder-3, 11 skin-lesion classes, image plus demographics), publish it with its training code under an MIT licence on Hugging Face, and commit the link on chain 120+ minutes before the start.

Validators

A competition starts when medical institutions add a data batch to a central Hugging Face dataset repo; validators download it and score every eligible model. The Tricorder-3 score is 0.9 x prediction + 0.1 x efficiency. Prediction is half accuracy, half weighted F1 (malignant 3, medium 2, benign 1); efficiency is 1.0 up to 50 MB and falls to 0 at 150 MB. The scoring code was not audited.

Incentive

The competition doc splits rewards among the top 10 models: 50, 17, 10, 7, 5, 4, 3, 2, 1 and 0.5 percent, with a minimal share for the rest. Testnet tokens have no market value (moderator, 2026-03-19), and on 2026-10-31 no testnet 163 neuron earned incentive or dividends.

Roles and requirements

Miner Low barrier

Trains and submits a skin-lesion classifier for the current competition.

  • Also in min_compute.yml: 4 GB swap, Ubuntu 24.04, 1 TB SSD recommended; each competition dataset takes about 1 to 5 GB.
  • The Hugging Face repo must be public and hold an extrinsic_record.json (the guide's anti-copy rule).
  • The guide targets netuid 76 on finney; the network flag takes finney or test, with the testnet netuid left as a placeholder.

Validator Low barrier

Detects new data batches, downloads them and scores every eligible model.

  • Also in min_compute.yml: 4 GB swap, Ubuntu 24.04, 500 GB SSD recommended; a card with 6 GB of VRAM is listed only for future use.
  • A Hugging Face token (--hf_token) is required; .env.example also lists W&B and Axiom keys, and whether Axiom is optional was not read.
  • Testnet 163 allows 64 validators; 43 permits were held on 2026-10-31, none with recent weights.

Getting started

  1. Ask in the channel whether anyone still validates: no testnet 163 validator has set weights for over 180 days (2026-10-31), so nothing would be scored.
  2. Read DOCS/miner.md and DOCS/validator.md. Both default to mainnet SN76; the validator guide's testnet example uses --netuid 163.
  3. Miner: build an ONNX model for Tricorder-3, upload it to a public Hugging Face repo, and use the command line (evaluate, self-check, upload, submit) with --subtensor.network test --netuid 163.
  4. Validator: install Python 3.12 and PM2, copy .env.example to .env, add a W&B key, and run scripts/start_validator.py with a Hugging Face token.

Caveats

  • Testnet only: netuid 163 does not exist on mainnet (2026-10-31). Testnet tokens have no market value, so the page gives no price or emission figures.
  • The chain slot has no subnet identity and was registered 2024-05-24, before the repo existed; the Safe Scan link rests on the repo (validator guide, code) and chat.
  • The weights figure covers validator permits only; it does not show that nobody runs miner software. Scoring numbers come from the docs, not a code audit.
  • A testnet competition config exists (tricorder-3, daily 14:38, no time zone stated); whether a competition or dataset is live on testnet was not verified.
  • safe-scan.ai redirects to frichi.cz, which blocked the research machine; dashboard.safe-scan.ai does not respond; skin-scan.ai (200) never mentions Bittensor.

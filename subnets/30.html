What it is

Endure (SN30) is a risk-intelligence subnet. Miners submit forecasts about other Bittensor subnets' Alpha tokens: worst price drop, volatility, average price and pool liquidity, each over 5 and 30 days. Validators wait for the real market data, score each forecast against what happened, and publish a signed consensus feed with an A to E risk tier per subnet. The team presents Forge, a lending product, as the first intended consumer; the subnet itself does not lend, hold collateral or liquidate.

How it works

Miners

Each day a miner commits a hash of a forecast bundle, then reveals the same bundle and a nonce later in the day. The bundle covers every whitelisted subnet (15 in the public feed, 120 forecasts per round: 15 subnets x 4 outputs x 2 horizons). Commit window is 11:00 to 19:30 UTC and reveals run 20:30 to 00:00 UTC. Miners send to validator axons that hold a permit, and the protocol caps commits and reveals at 10 each per round. Miners need their own Finney archive RPC for market data; the public archive endpoint was rate-limited in early October. The reference miner is in the repo, but forecasts that exactly match another hotkey's are pooled (see incentive).

Validators

A validator freezes the round's list of subnets, accepts commits and reveals, and resolves the real values from archive market data once each horizon ends (about 6 days for the 5-day outputs and about 31 days for the 30-day ones). Each forecast gets a bounded linear deviation score. Scores feed a decaying average (half-life of 5 rounds), and the validator publishes a quality-weighted median per output and sets weights. It runs as one Python process on SQLite and needs no GPU. Startup refuses non-archive market-data endpoints.

Incentive

Per the code at release v0.1.3 (protocol key 2044): payout follows the decaying score record with cubic sharpening of weights. After a miner's first accepted round, any skipped forecast counts as zero, so partial coverage is penalised. There is no minimum runtime, but the first positive resolved scores take about 6 days. The owner publishes a burn rate as an on-chain commitment and validators give that share of every vote to the owner UID, which the chain burns; miners split the remainder. A missing rate burns the whole vote, and with no positive scores a validator votes entirely for the owner. In code from 2026-10-20 (key 2044), hotkeys that reveal identical values are pooled and share what the best member would earn alone. The docs state that duplicate resistance, at least two independent validators and a full 30-day cycle are still open requirements, accepted by the owner.

Getting started

  1. Read docs/mining.md or docs/validating.md and docs/running_on_mainnet.md in the repo.
  2. Get a mainnet archive-capable Finney RPC; a pruned or non-archive endpoint makes the neuron refuse to start.
  3. Register a hotkey on netuid 30 (the repo's runbook uses btcli subnets register --netuid 30 --network finney); the registration burn floor was about 1 TAO on 2026-10-19, so check the live cost.
  4. Run the prod image (ghcr.io/endure-network/endure-subnet-miner or -validator) with the mainnet serving-stage flag; releases must be on the prod channel, currently v0.1.3.
  5. Miners: build your own forecasts for the whole universe each round and persist the state directory so a restart can reveal the same bundle.
  6. Check the validator's /health and the dashboard before relying on results.

Caveats

  • Chain weights, the metagraph and the owner-published burn rate were not read. The share of incentive going to miners (about 1% in the dashboard's latest receipt, 1.33 alpha against 146.271 alpha owner-associated, at chain epoch 25,855 on 2026-10-21) comes from the team's dashboard only.
  • Chat on 2026-10-17 and 2026-10-19 says emission is not on or asks how it works, while the dashboard shows non-zero miner incentive on 2026-10-21. The chat does not say which kind of emission is meant, so this is unresolved.
  • The repo README and docs still lead with testnet netuid 504 and a testnet soak, and the public read API is the testnet one. Mainnet numbers come from the dashboard and chat, not from a documented mainnet API.
  • Mainnet validators beyond the team's, and their upgrade to v0.1.3, were not confirmed. The docs say only one public validator endpoint existed during the soak.
  • The docs describe the economics as experimental and say gamma 3 and the 5-round half-life are starting values, not proven for mainnet.
  • The dashboard flagged its overall accuracy tile (92.7%) as based on a stale saved index, and counts of miners and hotkeys differ by source (245 active, 248 ranked in the team post, 266 distinct accepted hotkeys).
  • A partnership with Synthdata (SN50) was announced on 2026-06-12 as in development; no code confirming it was found.

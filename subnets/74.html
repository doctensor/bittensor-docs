What it is

Gittensor is a subnet that set out to reward open-source work: miners link a GitHub account to a hotkey, and validators score their merged pull requests to whitelisted repositories. Over August to October 2026 the team narrowed this to a few team-run projects (a GPU inference runtime called sparkinfer and an agent-strategy competition called Spark-Hermes) and added a GPU compute pool. Since 2026-10-12 the code no longer tracks any repository and sets the miner share of emission to recycle, so the mechanism described in the README and the docs site is currently not paying anyone.

How it works

Miners

Per the docs site and README: there is no miner neuron to run. A miner posts a fine-grained GitHub access token to validators with the project's command-line tool, the GitHub user is pinned to the hotkey (a different account needs a new hotkey), and the miner then contributes pull requests to repositories on the registry. Two team-run tracks were paid in 2026: sparkinfer, where a source pull request must show a verified speed-up over the current best on one real RTX 5090 and pass accuracy checks (tiers by percentage speed-up, docs-only pull requests earn nothing); and Spark-Hermes, where miners submit written strategy files for one pinned agent, which are scored on hidden Python bug-fix tasks in two-hour rounds. A compute track pays for running a verified GPU server and renting GPUs out (admitted cards listed on the docs site include RTX 5090, RTX PRO 6000, L40S, H100, H200, B200 and B300).

Validators

Per the docs site and code: every two hours a validator loads recent pull requests (30-day look-back by default), filters and scores them, and applies eligibility rules per repository (defaults: at least 3 merged pull requests and at least 80 percent merged out of merged plus closed; repositories can override). The base score is a saturating curve on a token-level measure of the changed source code, plus a small bonus, or a fixed value a repository sets. Repository weights come from a local JSON registry file; if the file is missing or empty nothing is allocated. Compute pay comes from a signed controller scorecard and only counts when the compute pool has a share. Weights on chain are set with commit-reveal.

Incentive

Documented design: miner emission is split across registered repositories by each repository's share, with leftover share, empty repository slices and any unused non-OSS share recycled to uid 0. Before the change the registry listed three repositories (sparkinfer 25 percent, Spark-Hermes 20 percent, a third at 5 percent, so about half of miner emission recycled). In commit 884ce17 (merged 2026-10-12) the registry was emptied and the OSS share set to 1.0, which leaves the compute pool zero: everything recycles. On chain at block about 9.33 million (2026-10-21) incentive was non-zero on exactly one neuron, uid 0, and a boolean check confirmed that uid is both the owner hotkey and owner coldkey slot of the subnet. The team calls this a burn or recycle (chat 2026-08-28 and 2026-10-19); whether the owner could spend that alpha was not checked.

Getting started

  1. First ask in the subnet channel whether miner emission has resumed: as of 2026-10-21 the code and the chain recycle all of it, so contributing now earns nothing.
  2. Open-source track (docs.gittensor.io, OSS contributions page): create a fine-grained GitHub access token, post it to validators with the project's command-line tool, then contribute pull requests to repositories that are on the registry again.
  3. sparkinfer: read CONTRIBUTING.md in the repository; a paid change needs a measured speed-up over the current best on an RTX 5090, and docs-only changes are not paid.
  4. Spark-Hermes: read the repository README for the round format (two-hour submission windows, practice bugs, hidden scoring bugs).
  5. Compute track: the docs site describes admitted NVIDIA cards and the up and rent commands; it was read only as documentation here and no running fleet was found.

Caveats

  • Docs versus code and chain: the docs site (OSS page last updated 2026-10-01) and the README still describe miners being paid, while code and chain show the opposite as of 2026-10-21. The docs had not been updated after the change.
  • The reason for the 100 percent recycle and any end date are not in the channel archive. Repository main has no commit after 2026-10-12 and the only open work found is a draft pull request that is not on main.
  • The check that uid 0 is the owner slot is a boolean comparison on chain; whether the owner can spend the alpha that accrues there was not checked, so this page repeats the team's word 'burn' without confirming it.
  • On chain, the per-block TAO injected into the subnet pool read 0 on the dates sampled from about 2026-10-13 (it was non-zero around 2026-10-10); the cause was not checked and no price or pool numbers are published here.
  • A critic wrote on 2026-09-26 that the sparkinfer repository owner self-mines, and the team said it had answered that repeatedly; this research found no first-hand evidence either way. Users also questioned perfect scores and trajectories with no edits in Spark-Hermes on 2026-10-11 and 2026-10-12; the team said it would check and no resolution was found.
  • Fleet size and real demand for the compute pool were not found (the project's compute page is rendered in the browser and could not be read with a plain fetch).
  • Chat is what the team said; code is what it does. Individual handles, hotkeys and quotes are deliberately not published.

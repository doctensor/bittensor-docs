What it is

Instant is an inference subnet built around one open model that miners serve from their own GPU machines. Validators check speed and reliability and set weights, and an OpenAI-style API for customers sits on top; a team-run public dashboard at instantnetwork.ai lists each miner's score. Since 2026-10-13 the model is an uncensored FP8 variant of GLM-5.3-Flash. The team chose speed and uncensored output over private execution: it uses proofs on the generated tokens and, per its statements, collateral slashing rather than trusted hardware.

How it works

Miners

A miner runs the team's signed binary on one host with a single qualified GPU class: four RTX PRO 6000 cards, two B300 cards or four H200 cards. It needs Ubuntu 24.04, NVIDIA driver 580 or newer, and about 360 GiB of free disk for the 306 GiB checkpoint. The miner serves customer and test requests and sends proof evidence for each one. An installer script needs only the hotkey, updates itself every 15 minutes with a health check and rollback, and sends a fault report when something breaks. The miner binary is distributed as releases only, not as source.

Validators

A validator needs no GPU. The public Rust code polls a platform-signed epoch summary from a team-run server, checks its signature and the chain state, scores it with a shared library that is not public (the repository's test vectors show what that library computes, see the incentive entry), and writes weights with commit-reveal. The proof checking itself is done by team infrastructure that re-runs the same model; the team says this is expensive and is being reworked to run on CPUs.

Incentive

Each epoch a qualified miner gets a score made of 60 percent speed (median generation tokens per second against the best qualified miner), 25 percent verified tokens, 10 percent successful requests (both against the best qualified miner) and 5 percent success rate. The team dashboard states these weights and the validator repository's test vectors reproduce them. A miner with at least two bad proofs (failed or timed out) that also exceed 0.5 percent of its checked proofs scores zero and does not set the reference maximum for the others. Weights are each score relative to the best one, scaled by one minus the burn, with the burn share sent to the owner UID. Paying customer traffic is routed first and idle miners are topped up to 10 verified requests per epoch. The team said on 2026-10-12 that burn was off, and the chain agreed on 2026-10-21: the owner UID, which is a validator, received 0 percent of incentive, and 14 UIDs shared it at roughly 4.6 to 8.3 percent each. Counted by owner coldkey, those 14 UIDs belong to six operators, the largest controlling four UIDs (about 31 percent of incentive). Before 2026-10-12 a share went to the owner UID so that miners received a set dollar target per epoch.

Getting started

  1. Read the miner README in the releases repo and check that your host matches one qualified GPU configuration, with swap disabled and at least 60 GiB spare for updates.
  2. Register a hotkey on subnet 46 and keep the unencrypted hotkey file on the machine; the coldkey is never needed.
  3. Run the installer from the miner releases repo; it asks for the UID and hotkey, downloads the checkpoint (about an hour), and starts the service.
  4. Run the miner's status and doctor commands to confirm the platform accepted the worker and that you are on the current version.
  5. To validate, install the validator with its installer script on a registered hotkey; no GPU is needed.
  6. Look up your UID in the dashboard's miner table to see its score components, speed first, once the miner has been routed requests.

Caveats

  • The scoring library the validator depends on (sn46-shared) is a private repository (anonymous clone refused on 2026-10-21). The weights on this page come from the team dashboard's text and the validator repository's public test vectors, which agree; rounding and edge cases inside the library were not read, and the owner's remark of 2026-10-20 that scoring is public covers only the validator wrapper and those vectors.
  • Validators trust a platform-signed summary from a team-run server, and proof checking runs on team infrastructure. The miner is closed source and distributed as signed binaries. The validator repository has no commit since 2026-10-12 (version 0.1.3) while the miner and verifier moved to 0.8.0 and 0.5.0 on 2026-10-19; whether validators must update was not found.
  • Collateral slashing is described as the owner's preferred answer to bad proofs (2026-10-03) and as part of the design, but no chat message up to 2026-10-21 says it is in place.
  • Burn is off on chain as of 2026-10-21, but the validator code still contains a burn mode driven by a dollar target in the platform's summary, so the team can switch it back on without a new validator release.
  • At chain block 9,334,722 UID 182 was the top weight target in several validators' rows and appears on the dashboard, yet had no incentive yet; commit-reveal lag is a plausible cause but was not confirmed. The dashboard is team-run and its figures were not independently reproduced, apart from the miner ranking, which matches the chain.
  • The performance report is the team's own, uses single trials and reported rates that include overhead; it was not reproduced.
  • The GitHub organisation also holds forks of TensorFold (an inference engine), flashinfer and vllm. The chat does not say whether any of them is the 'new inference engine' the team announced on 2026-10-18.
  • Old documentation links shared in chat in August (docs.instantsubnet.com) now redirect to a different project, DaniLabs. Two X accounts and several Discord invites have been named in chat in the last month, and the owner asked people to leave an earlier Discord, so confirm links before following them.
  • Chat read: the latest 200 messages, team posts from 2026-08-25 on, and every message from 2026-10-20 to 2026-10-21; claims about miner profits and revenue in chat were left out.

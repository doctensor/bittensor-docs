What it is

ChronoLLM rewards miners for training language models that only know what was publicly known up to a chosen year, so that finance and research teams can backtest without the model already knowing the future. Each weekly round covers one vintage year: the team has finished 2013 to 2025, and round 17 is vintage 2012, with years then walking back toward 1999. CrunchDAO announced on 2026-06-10 that it was taking over the subnet. Its website offers API access and self-hosted point-in-time models, and the team said on 2026-10-21 that first paid enterprise pilots are targeted for the fourth quarter of 2026 or the first of 2027.

How it works

Miners

Miners train a model of up to 2.2 billion parameters for the round's vintage year, upload it to HuggingFace, and commit a file on chain that points to the repository pinned to an exact commit. Any architecture that loads as a standard causal language model is accepted, and custom architectures can be added through a pull request. Everything is cleared each round, so miners resubmit every week before Monday 12:00 UTC. A rate-limited self-test inside a secure enclave gives pass or fail on a separate sample dataset.

Validators

The evaluation runs inside a Phala Cloud secure enclave on an H200 GPU. It downloads the models, fetches a private evaluation dataset from the team's backend, rejects copies, tests whether each model knows its own period but not later ones (the leak test), keeps the best 30 by leak score, and ranks those by head-to-head duels on fresh prompts judged by an OpenAI model. On chain, twelve UIDs hold validator permits and six set weights, all six with the same ten targets. In rounds 13 to 16 the results on the public leaderboard API were posted by the hotkey of UID 0, which is the subnet owner's own slot. All five of the others update their weights far more often than a weekly evaluation could produce new results, and the sources do not say what they run.

Incentive

Final score is 30 percent normalised leak score plus 70 percent duel win rate (a raw leak score of -11 maps to 0 and -25 to 1), per the code and live config on 2026-10-23. The published results for rounds 15 and 16 match that formula to four decimals, while rounds 13 and 14 matched win rate alone, because leak was only a pass or fail gate until Round 14. The top 10 share emissions on a decaying curve, roughly 52, 23, 12, 6, 3.2 and 1.7 percent for the first six places, and the on-chain incentive on 2026-10-23 matches it. A model that fails a check or is skipped (duplicate weights, too large, would not load) scores zero. Separately, the chain splits subnet emission 18 percent to the owner, 41 percent to validators and 41 percent to miners, and the owner's UID 0 holds about 86 percent of validator dividends.

Getting started

  1. Read docs/miner.md in the GitHub repository and check the live config and current round endpoints to see which vintage year is being evaluated.
  2. Train a model of at most 2.2 billion parameters on data available only up to that year, and upload it to HuggingFace in safetensors format.
  3. Try your model with the self-test described in the miner guide (pass or fail, 12 calls per day per hotkey) and with the repository's architecture test script.
  4. Register a hotkey on subnet 38, list your model pinned to a commit SHA, and submit with the miner script before Monday 12:00 UTC; make the model repository public within an hour of the deadline.

Caveats

  • Documentation lags the code: the README still describes leak as a pass or fail gate with ranking by duels only, and states the qualifying condition the opposite way round from the code, where a lower leak score is better and must be below -3.0. The miner guide and a constants file describe one model per year for 2013 to 2024, but each round now evaluates a single vintage year.
  • The evaluation data, per-year known and unknown scores and the backend are private and run by the team. The public leaderboard API does show each round's leak score per UID, the qualifiers, duel win rates, final scores and paid weights, but a zero cannot say why: failing the leak test, duplicate weights, an oversize model and a load error all score zero.
  • The config endpoint is controlled by the team and has no change log; on 2026-10-12 it briefly showed zero leak weight. The published Round 15 results match the 30/70 split. It also lists leak settings the validator code does not read, so the repository cannot prove which thresholds run in production.
  • In practice one evaluator runs this subnet: the results for rounds 13 to 16 were posted by the owner's UID 0, and five other validators carry identical weights. The team says anyone can run a validator, but no other validator's evaluation results were found.
  • Fairness accusations from 2026-10-12 to 2026-10-21 are unresolved. The team denies self-mining, says nobody has access to the data and that models are public. On chain on 2026-10-23, no paid UID shared the owner's coldkey; the ten paid UIDs sat under five coldkeys, with the two largest payouts under one. That neither proves nor rules out anything, because other keys are not visible.
  • The self-test uses a separate dataset by design, so passing it does not guarantee passing the real test. An authorization error on the newer enclave image was reported on 2026-10-19, and the team said on 2026-10-20 that the test was available, without naming a fix.
  • The website markets API access, self-hosted weights and point-in-time models back to 1999, and shows a 72 billion parameter model, while subnet models are capped at 2.2 billion parameters. How subnet output feeds the product is not documented in what was read. The first public product (first week of November) and the first paid pilots (fourth quarter of 2026 or first of 2027) are chat statements only, and no answer to holders asking about buybacks was found.
  • Validators need an H200 GPU in a secure enclave and an OpenAI key. The docs say a validator needs enough stake, while the team said in chat that no minimum stake is required.

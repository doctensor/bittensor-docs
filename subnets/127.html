What it is

Astrid Arena runs month-long competitions (called Miners Showdowns) in which AI trading agents trade live against each other, and the subnet pays the top three miners of a finished competition. Miners run their own agents and report each decision to the Arena platform; validators later replay the public trade record, check eligibility and rank miners by the competition's scoring metric. Between payouts, all validator weight goes to the burn UID.

How it works

Miners

Miners are traders: each registers a coldkey as a miner on subnet 127, verifies wallet ownership on the Arena platform, creates one agent and joins a competition. The miner runs the agent on their own infrastructure, which reads market data from the platform API, places orders and posts an execution run for each decision cycle. Competitions that require code submission also take a strategy container (capped at 30 versions); the platform runs it only for build, smoke test and replay checks, never to trade live.

Validators

A lightweight validator process (Node.js in Docker, 1 vCPU and 1 to 2 GB of RAM at minimum) polls the Arena API every hour for competitions inside their payout window. It drops disqualified participants, requires at least one trade and an execution run within two hours of each trade made in the miner's last 12 hours of activity, replays trades from the public record, ranks miners by the competition's metric and resolves their UIDs from the coldkey. The metric is replayed PnL, or the Astrid Score (a blend of return, Calmar, Sortino, Ulcer index, maximum drawdown and execution activity) from MS6 onward.

Incentive

Only the top three eligible miners of a finished competition are paid, split 60, 30 and 10 percent (70 and 30 with two eligible miners, 100 with one). The validator code sets each competition's share of total weight to a hardcoded 30 percent and sends the rest to UID 0, which the repo calls burn; with no competition in a payout window, all weight goes to UID 0. The team said payouts run for about four weeks after validation. On 2026-10-21 all 12 validators with permits had set weights and every one put 100% on UID 0, matching the no-payout state.

Recent activity

  • 2026-10-21 (#astrid; Arena public API) A member reported that the public trade endpoint for MS7 returns trades without a ticker identifier, which the validator treats as unscorable. A check the same day on the first 500 of 979 MS7 trades found none with the field. No team reply was seen. The same day the platform API showed no active competition and an empty payout list.
  • 2026-10-19 (#astrid) The team said the validator updates were in final testing before Astrid Score emissions could start.
  • 2026-10-15 (GitHub (astridintelligence/sn-127)) A validator change was committed to rank competitions by the Astrid Score; it was merged on 2026-10-20.
  • 2026-10-09 (#astrid) The team said MS5 would finish paying on 2026-10-15, that MS6 and MS7 would then pay on the Astrid Score starting by 2026-10-20 for about four weeks, and that no new competition would start straight away while it reviews submitted archives and reworks rewards (a buy-and-hold benchmark and longer windows were mentioned as likely). Sign-ups stay closed until the next competition is announced.
  • 2026-09-17 (#astrid) The team confirmed the MS5 top three on the 60/30/10 split using live results and enabled emissions. It said replays of the winners' code did not match their live trades trade for trade, after a long dispute over replay fidelity in which many archives placed no trades in replay.

Getting started

  1. Create a wallet and register a hotkey on subnet 127 (the burn registration cost was at its 0.0005 TAO minimum on 2026-10-21).
  2. Create an Arena account and an agent through the platform API, set your coldkey on the profile and prove ownership by signing a challenge.
  3. Practise in the Strategy Testing Playground, and use the local test runner in the example agent repo before submitting any container.
  4. Wait for the next miner competition to be announced in the channel (none was open on 2026-10-21), then join and get approved before it starts.
  5. Run your agent yourself for the whole competition and post an execution run for every decision cycle; if code submission is required, upload your strategy container and test it with the self-serve replay.
  6. To run a validator, use the installer script in the sn-127-install repo, which starts the Docker validator and an auto-updater.

Caveats

  • The share of total weight per competition is 30 percent in the validator code but 25 percent in the platform API and in the docs' examples, and chat never states it; the live figure is unconfirmed.
  • The promised start of MS6 and MS7 payouts by 2026-10-20 had not happened by 2026-10-21: no competition was in a payout window and the chain showed all weight on UID 0. Whether MS6 results were ever announced was not found in chat.
  • The missing ticker identifier on public MS7 trades could stall Astrid Score payouts if validators read the same data, because the code keeps its previous weights when it cannot replay. This was verified only on a sample, and how the team's own validators read the data was not tested.
  • The miner guide and the repo README still describe ranking by PnL; the ranking document and code were updated for the Astrid Score in October 2026.
  • Chat and the platform pages disagree on whether the arena is spot-only or margin and perpetual style, so no leverage terms are stated here.
  • Dates, scoring and sign-up rules have changed often (replay rules, heartbeats, registration windows) and the team has said rewards will be reworked, so check the channel before joining.
  • Miners repeatedly complained of slow communication on results and of replay results that did not match live trading; these claims were not independently verified.

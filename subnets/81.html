What it is

Reliquary (SN81) is a post-training network for language models. Independent GPU miners generate model outputs, the team's validator checks them and the team's trainer uses them to improve models. It began as reinforcement learning (RL) on a small Qwen model; since 2026-10-22 the main task is a fully asynchronous RL run on the team's 9B Teutonic model, where miners lease prompts, generate rollouts at their own pace and are paid for each token a validator's own recomputation reproduces. Since 2026-09-24 the network has also paid for SFT and distillation data, agentic software-engineering jobs and, since 2026-10-20, benchmark evaluation runs, and the team offers it as a data and training service to other subnet teams.

How it works

Miners

Async RL (since 2026-10-22): run the miner command mine-async. The miner asks the team validator for leases on prompts in the environments it picks (SWE, terminal, competitive code, hard math, DAPO math, EnvScaler, instruction following), within a quota the validator sets from the miner's measured throughput. It generates 16 rollouts per prompt, drawing each token with randomness the validator publishes, on the latest or a slightly older checkpoint (weight deltas download in the background), and must submit every leased group. For agentic tasks the miner only sends the model's actions; the team's signed sandboxes run and grade them. The CLI help says a 24 GB card cannot hold the 9B model's default 262,144-token context, so a shorter context has to be set. Corpus and evaluation jobs (SFT data from a Qwen3.8-27B teacher, benchmark answers) ran as one miner process per job id against the team validator, with bf16 recommended; their state could not be re-read on 2026-10-23.

Validators

The team runs the single trainer and grading validator, which is also the subnet owner's UID (237). It issues leases, grades every group, recomputes each token's draw and rejects a rollout whose match is under 90 percent, trains on groups that are neither all right nor all wrong, audits the others by sampling, and publishes checkpoints as a signed index of sparse weight deltas through presigned storage links, with Hugging Face backups. The other validators (7 UIDs held validator permits on 2026-10-23) are weight-only: they replay the team's per-period pay archives into weights on a CPU box and need read access to the team's storage. The README says the system is auditable but not trustless; that text predates the async run.

Incentive

Async RL pays per matched token: a rollout matching the validator's recomputation at 0.90 or better earns its matched tokens times its environment's price, and the first scan of a never-tried prompt that comes back too easy or too hard earns 25 percent of an average trained group. Prices are one nominal rate times a per-environment multiplier of up to 4, adjusted every 5 minutes so each environment supplies its target share of what the trainer consumes (on 2026-10-23: SWE 23 percent, competitive code 21, hard math 21, terminal 18, DAPO math 13, EnvScaler 3, instruction following 1). Each 72-minute period is scaled so it never pays more than the task cap (0.8 on the team's pay board), the rest burns, and period results enter chain weights through an EMA. On 2026-10-23 every multiplier sat at the 4x maximum in a hold state because no trainer speed had been measured yet. On chain the burn goes to the owner UID: it held about 99.8 percent of incentive around 20:25 UTC on 2026-10-22 and about 61 percent at 02:35 UTC on 2026-10-23, with 33 UIDs paid. The chain's emission split is 18 percent owner, 41 validators and 41 miners. Corpus tasks (read 2026-10-21) paid each period the smaller of a cap and a price times verified tokens, with a team-stated ceiling of 0.9 alpha per million tokens.

Getting started

  1. Do not rely on the README or docs/mining.md for the new run: they still describe the earlier window-based Qwen3-4B RL. Use the 2026-10-22 launch post in the channel and docs/rl-async-design.md in the repo, which is marked as a draft.
  2. Before committing GPUs, read the team validator's public RL routes: /rl/pay (prices, multipliers, caps), /rl/prompts/state (which prompts are leasable, cooling down or retired) and /rl/checkpoint (latest checkpoint version).
  3. Register a hotkey on netuid 81, update to the latest main and run mine-async with the environments you want; the design pins vLLM to 0.30.x and refuses speculative decoding. Quantised weights are allowed, but the design's own tests put fp8 weights around 0.96 to 0.97 match and 4-bit formats around 0.86, below the 0.90 floor.
  4. Optionally add the setup-sharing flag the team asked for on 2026-10-23. For the SFT-data and evaluation jobs, check that the team validator's /corpus/tasks answers again before spending on them.

Caveats

  • The chain numbers are snapshots (blocks 9337776, 9339546, 9341316 and 9343176, times estimated from 12-second blocks). The burn share moved from about 99.8 to about 61 percent in roughly six hours; it is not a steady rate. Weights are validator opinions: the seven validators' rows fell into three different shapes (47, 58 and 73 percent to the owner UID).
  • The README and docs/mining.md have not changed since 2026-10-21 and do not mention the async run. What is described here comes from the launch post, the repo code and docs/rl-async-design.md (marked draft, 2026-10-15), and the pay board; whether the deployed settings equal the repo defaults is checked only for the floor, cap and start pool shown on /rl/pay.
  • The team validator's /health, /state and /corpus/tasks returned HTTP 503 on 2026-10-23 while its /rl routes answered, so the current caps, prices and payments of the SFT-data and evaluation jobs are unknown since 2026-10-21. Evaluation results promised on 2026-10-20 and 2026-10-22 had not been seen.
  • The run is new: only three checkpoint versions had been published about 9.5 hours after the launch post, and the pay board had no measured trainer speed, so prices were held at the maximum multiplier. Prices, caps and environments are placeholders in the code and change often; the team says it announces changes.
  • The claim that any GPU and any inference engine works rests on the team's own tests in a draft design (honest match about 0.986 on 3090, 5090, A6000 and L40 cards); the team asked miners to declare hardware to measure it in production.
  • Rewards, grading, selection and checkpoint publication depend on one team-run trainer and team-controlled storage. The team validator is addressed by a bare IP over plain HTTP, and its RL routes returned 503 to a miner for a short time on 2026-10-22 until the team fixed it.
  • A team statement on 2026-10-08 says customer revenue will fund token burns to offset miner emissions; no such mechanism was found in the repo and no revenue figures were found. The 2026-10-01 allegation of team-run UIDs is unresolved: at block 9343176 no other paid UID shared the owner's coldkey, but other team-held coldkeys cannot be excluded.
  • The SN3 team said in its channel on 2026-08-31 that it planned to post-train Teutonic I on Reliquary, and the repo docs never mention SN3; which Teutonic version SN3 itself runs was not verified.
  • The Hugging Face repo for the new run's weights (created 2026-10-23) holds only the latest checkpoint and squashes history, so earlier checkpoints cannot be fetched from it; the signed delta index on the team validator is the other route.

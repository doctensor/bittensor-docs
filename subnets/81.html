What it is

Reliquary (SN81) trains language models on Bittensor. Independent GPU miners generate answers for reinforcement learning (RL), the team's validator grades them and its trainer improves the 9B Teutonic model; checkpoints are public. The team plans to sell data and RL as a service; no customer use is verified.

How it works

Miners

Run mine-async. The miner leases prompts from the team validator in the environments you pick (see the table below), writes 16 answers per prompt on the latest checkpoint and must submit every leased group. The validator recomputes each token; matches of 0.90 or better are paid. The team's sandboxes grade agentic tasks.

Validators

The team runs the only trainer and grader (the owner's slot): it issues leases, audits groups, trains on groups that are neither all right nor all wrong, and publishes signed checkpoints. Other validators are weight-only: they replay the team's pay archives into chain weights.

Incentive

Pay is matched tokens times an environment price that adjusts toward each environment's target share. A 72-minute period pays at most the task cap (0.8 on the pay board). Emission splits 18% owner, 41% validators, 41% miners; the miner-side incentive that lands on the owner slot is burned: 58% on 2026-10-28, 76% after the 2026-10-27 outage. The other 79 earning miners shared about 1,020 alpha a day, about 5 TAO (calculated at the pool price).

Getting started

  1. Skip the README and docs/mining.md (earlier Qwen3-4B task); use the launch post and the draft async design doc.
  2. Check the pay board and run monitor before renting GPUs; prices and targets change often.
  3. Register a hotkey on netuid 81 (0.0005 TAO).
  4. Run mine-async from the latest main with a context length that fits your card; keep bf16 weights (team tests: fp8 about 0.96 match, 4-bit 0.86, floor 0.90).
  5. Validators: run the weight-only Docker image once you hold a permit and the team's read-only credentials.

Caveats

  • Figures are single readings (2026-10-28). The burned share moved between 54% and 76% in five days; which pay switches are live is inferred from the pay board, not the deployed config.
  • The async run is documented only in a launch post and a draft design doc; the README is out of date.
  • Team validator job routes returned HTTP 503 and the dashboard network view is stale since 2026-10-21: SFT-data and evaluation caps and results are unknown.
  • The pay board is a bare IP over plain HTTP.
  • The team's own miners (earnings not read) and the SN3 link to Teutonic are unverified; the promised revenue-funded burn has no code or revenue.

What it is

Lium is a GPU rental marketplace on Subnet 51. Providers list NVIDIA GPU hosts, renters (people, teams and AI agents) rent them by the hour through the website, CLI, Python SDK or API, and one team-run validator checks that listed nodes are real and reachable. Providers earn 95% of rental fees plus a share of subnet emission; on 2026-10-23 about 77% of the miner-side incentive on chain went to a single team-controlled key that the code calls a burner.

How it works

Miners

Providers run a node agent on each GPU host and either their own coordinator or the Lium-run Central Provider Server (the default, per the repo's miner README of 2026-10-22), which holds the hotkey and lists nodes. They set a price per GPU-hour in the provider portal. Hosts need Ubuntu 24.04 (or 22.04 with the HWE kernel), Docker, the Sysbox runtime, a public IP, at least 100 Mbps, 8 GB of RAM and 150 GB of disk; the provider also needs a connected Discord account and a confirmed e-mail address to be paid emission.

Validators

Lium runs a single validator, operated by the team: the docs page, the key built into the node image and chain uid 3 all agree. It checks each node every 15 minutes over SSH (hardware and GPU model, network speed, port reachability, container runtime), and only passing nodes are listed. Nodes accept checks only from the key in their image. Eight other validator permits on chain also set weights, with near-identical vectors (77 to 78.5% on the burner uid); the project points anyone who wants to run a validator to its community auditor script, which sets weights from the platform's public results.

Incentive

Each validator cycle sorts nodes into pools. Rented nodes share a mining pool equal to 1 minus the burn ceiling in the platform's shared config (10% of miner emission at the live value of 0.9), weighted by GPU-model rate and GPU count with Sysbox and driver-version multipliers. Idle nodes of eligible GPU models that are priced at or below a soft limit (1.5 times the model's 90th-percentile price), have enough disk and can set a power limit are paid from an idle pool sized by the dollar value of their listed rates against the dollar value of the subnet's emission, capped at the ceiling. Whatever remains under the ceiling is called burn, but all ten burner slots in the code point at one uid that a code comment calls the Datura payout key. On 2026-10-23 that uid held 77.3% of incentive on chain, which leaves about 23% of the miner side (roughly 9% of total subnet emission, by arithmetic from the emission split) for all other paid miners. The docs say emission lands as stake on the provider's hotkey about 24 hours after scoring. Separately, providers receive 95% of rental fees, paid daily at 17:00 UTC as alpha (or USDT) for the day two days earlier, and a rental that ends while a node is inactive costs the provider 48 hours of that rental's price.

Getting started

  1. Register a hotkey on subnet 51 from your own machine, not the GPU host.
  2. Sign in to the provider portal with that hotkey, use the Lium central provider server, connect Discord and confirm an e-mail address.
  3. On the GPU host (Ubuntu 24.04 or 22.04 with the HWE kernel, NVIDIA driver, Docker) open ports 8080 and 2200 and install Sysbox and the NVIDIA container toolkit with the repo's setup script.
  4. Run the node install command from the Node Quickstart (the lium CLI mine command), then add the node in the portal and set a price at or below the soft limit for your GPU model.
  5. Check the node shows as available in the portal; open a ticket in the project Discord if stuck.

Caveats

  • Chain weights are validator opinions, not payouts. The main chain read is at block 9343147 (about 2026-10-23 02:19 UTC) and the burner's stake at block 9343282; the chain does not show what the burner key does with its alpha beyond holding about 47,170 alpha (1.03% of alpha outstanding).
  • The word burn is the code's name for emission routed to one uid that a code comment calls a team payout key; it is not shown to be destroyed. The team has not published how its buyback is funded.
  • Three figures for one setting: the docs say a 13% rented pool and 87% ceiling, the live shared config reads 0.9 (10%), and the code default is 0.91. The live config is the current value; the docs lag.
  • The code has a delayed-settlement mode that defaults to off, while the docs describe a roughly 24-hour delay before emission arrives. Which mode the production validator runs is not visible from code or chain.
  • Only one validator can check nodes. Two of the 11 validator permits (one is the burner uid) have not set weights for about 163 and 614 days.
  • Chat answers in the channel often come from the project's support assistant and are not team policy. Repo commits show what was written, not what is deployed. Fleet figures come from the team's own stats feed.
  • Whether held payouts from 2026-10-16 were re-sent is unknown (confirmations were promised in private tickets), and the status of the offline provider's hosts after 2026-10-22 is unknown.

What it is

Subnet 498, run by Technology Nucleus and branded CanopyMRV, is meant to produce labeled satellite imagery for climate verification (carbon accounting and deforestation compliance). Miners run their own vision models to outline tree crowns on image tiles and upload the results. Validators score miners against a hidden labeled set and use a vision model to choose which miner's record to keep for each unlabeled image, which together form the dataset the team wants to sell. Everything described here runs on the Bittensor testnet.

How it works

Miners

Miners receive a task of up to 30 image tiles per round, each with an ID that is unique to their hotkey, and have 600 seconds from dispatch to answer. They detect trees with any model they choose (the repo ships SegFormer, YOLO, a self-hosted REST, OpenAI fine-tuning and Qwen2-VL backends) and upload a JSON file of polygons, boxes, class, confidence and area to Cloudflare R2, then return its address. Answers must match the round's batch ID, stay within size and polygon-complexity limits, and avoid crude boxes or spiky outlines.

Validators

A validator plans tasks that mix hidden labeled (golden) images in with unlabeled public images; every sampled miner gets the same images. Golden images are scored by a fidelity function: 60 percent overlap with the true shape (a match needs at least 0.5 IoU) and 40 percent class agreement, reduced for false positives, for large differences in carbon-weighted canopy area, and for geometry that looks like box gaming, saw-tooth outlines or non-vegetation. For public images, a private vision-model step picks at most one miner's record per image, or leaves it unassigned. Parts of the validator (round loop, task planner, selection adapter) ship only as encrypted files, so they cannot be read from the repo.

Incentive

In the readable code, each miner's round score is 0.7 times its golden-set fidelity plus 0.3 times the larger of an adoption bonus and a selection share (the fraction of public images where its record was chosen, scaled down for low fidelity). The adoption bonus stays at zero by design until an audit path that does not yet exist confirms ground truth. Scores are smoothed with a moving average (default weight 0.1 on the newest round). Before weights are set, miners below 5 percent of the top score get nothing, and the rest share a small floor (capped at 20 percent of the total) plus a share proportional to score. The earlier winner-takes-all rule was replaced by per-image selection in Architecture v1.5 (2026-09-29). Chain weights were not read.

Getting started

  1. Clone the Tech-Nucleus repo (the README quickstart names a different GitHub account), make a Python virtual environment and run pip install -r requirements.txt.
  2. Copy .env.example to .env and set your wallet name, Cloudflare R2 credentials and a model backend (see MINER.md for the payload schema and limits).
  3. Create a testnet wallet and register a hotkey on testnet netuid 498; the team offered faucet tokens in chat on 2026-09-21.
  4. Start the miner: python neurons/miner.py --netuid 498 --subtensor.network test with your wallet, hotkey, axon port and model path.
  5. Check the batch ID of every task and answer only for the images of that batch. Validator setup is not documented in a usable way because key modules are encrypted.

Caveats

  • Testnet only. Nothing here describes mainnet emissions or economics, and the number 498 is the testnet netuid the team uses; a mainnet read on 2026-10-21 (block 9334628) found no netuid 498 there, and a testnet read (block 8273072) shows it registered on 2026-06-07 with 19 neurons and no on-chain name set.
  • Part of the validator (round loop, epoch planner, public-image selection) is distributed as encrypted modules decrypted at runtime with a key from the environment or a .env file. How public-image selection works and how round results become on-chain scores cannot be verified from the repo. Chain weights were not read.
  • The ground truth is, by the team's own account, produced by its own multi-stage AI pipeline and checked against a small number of certified human labels; the published benchmark figures cover one tile and changed between the 2026-10-07 chat post and the site as read on 2026-10-21. The team says the pipeline and the human benchmark disagree on crown counts in dense canopy.
  • The repo's image loader describes 10 m Sentinel-2 chips with Hansen and JRC golden labels, while the site describes 0.30 m WorldView-3 chips and a Restor TCD benchmark. Which dataset the live testnet validator uses was not verified.
  • Docs lag code: README, MINER.md and VALIDATOR.md say v1.5.0 while the package version is 1.7.0. MINER.md says polygon outlines get priority from a vision judge; a code comment in the golden scorer says golden labels are boxes and miner polygons cannot change that score. Whether live golden labels carry polygons was not verified.
  • Hardware advice conflicts: min_compute.yml lists 8 GB VRAM and an A100 as recommended (it looks like template boilerplate), while the team said on 2026-09-23 that even a 2 GB GPU can do well and a miner said one consumer GPU is enough.
  • The network is small and run mostly by the team: a miner counted three outside miners plus team-run miners on 2026-10-04, and the team said the validator-only setup is temporary until more validators join. Miners reported task outages on 2026-10-01 and 2026-10-18.
  • An open concern from 2026-10-18 is confirmed in the repo as of 2026-10-12: the per-image fidelity function trusts miner-supplied confidence (default 0.95 when missing, 25 percent of its composite) and checks vegetation on only the first 30 polygons. It feeds the dataset score; whether it affects rewards was not traced, and the team's promised follow-up is not in the archive.
  • A miner reported on 2026-10-04 that the golden set is tree only and that shrub or field classes count as hallucinations; this is one participant's report, not team documentation.

What it is

Recall is a hosted memory and retrieval-augmented generation (RAG) API: a developer creates a vector database, stores text, queries it and asks for generated answers, with a remote MCP endpoint for AI agents. The team's pitch (2026-06-02) is one API call that returns a grounded answer with citations, chained through the best miner for each step (embed, retrieve, rerank, generate), with validators scoring miners on retrieval accuracy and answer quality. The netuid was registered on 2025-12-25 (the previous project there was Candles), and the current owner said in May 2026 that they had recently bought it. The miner, validator and web repositories were private at the time of research, so the mechanism below is what the team said, not what code does.

How it works

Miners

Per the team and the site: miners run storage and embedding and serve user requests to create databases, store text, embed, rerank, generate answers and query. The public explorer lists a capability tag per miner (database, embedding, rerank, generate). Miners declare which embedding models they serve, from one catalog that includes a CPU default and several larger open models, and requests for a database go only to miners that declared its model. On 2026-10-24 the explorer's data (testnet subnet 353) listed 17 UIDs but only 4 with hardware and capability details; all four report the same region and GPU model, about 12 to 20 hours of uptime and almost no processed requests. The team said miners need CPU, GPU and storage, but no hardware requirements document was found.

Validators

Per the team (2026-09 to 2026-10): one master validator computes per-miner scores and publishes a signed bundle to IPFS; the other validators fetch it by content hash, verify the signature and fields, and apply a one-hotkey-per-coldkey rule. On 2026-10-05 the team said validators run only this newer path, committing the allocation on chain and setting weights from it. Validators also check that a miner's self-signed TLS certificate is the one tied to its hotkey at registration. On 2026-10-23 the team said it had built a probe system that checks generated answers against independently calculated results across several task types, and that it had found miner-exploitable paths in the generation tier that it was fixing. The explorer data shows four per-miner tier scores (score version 10) that were last recorded on 2026-10-10; what each tier measures is not published.

Incentive

The reward split and score formula were not found in any public source. The team says only the latest registered hotkey per coldkey earns. On chain, UID 0 is the subnet owner's own hotkey (hotkey and coldkey both owner-linked), and at block 9355046 (2026-10-24) every one of the 16 validators with permits put 100% of its weight on it. UID 0 holds 100% of incentive and about 74% of last-epoch emission, the recycle-or-burn setting is Burn, and the chain's own accounting treats the whole miner side (41% of subnet emission) as withheld because its recipient is owner-owned. The same pattern appeared at all 11 blocks sampled between 2026-09-10 and 2026-10-24, so no miner UID has had incentive since emission was enabled on 2026-09-09. Weights are validator opinions rather than payouts, and whether this is the intended launch state is not known.

Getting started

  1. For users: the site (client-rendered) offers sign-in with Google or GitHub, then creating a vector database, storing text, querying it and generating answers; the docs list default free and builder allowances of 20 databases, 50 GiB, 1,000 embeddings per hour and 10,000 queries per hour, which they call deployment-configurable (unchanged on 2026-10-24).
  2. For agents: the docs describe a remote MCP endpoint using OAuth. Individual items can be deleted through the REST API, and whole accounts from Settings.
  3. Do not store secrets or sensitive data: the site states that miners are not in trusted execution environments and may see plain text while embedding or generating. A confidential-compute phase is planned later.
  4. For miners and validators: no public repository, setup guide or hardware requirements were found, and the site links to no code. The team has said repositories would be opened, and on 2026-10-23 said testnet validation comes before a release date; follow the #recall channel announcements.

Caveats

  • No public code: nothing about scoring, rewards or miner onboarding could be checked, and searches for the team's repositories on 2026-10-24 found nothing. Every mechanism statement above is a team post, and the test results (soak runs, audit findings) are team-reported on a private network. The team said in May 2026 that code was published and later described the repositories as private.
  • Mainnet launch has not happened as far as can be shown. The team has not announced that mining or the service is live on subnet 31, the chain shows zero incentive on every miner UID at every block sampled, and the explorer still reads testnet subnet 353. Whether the hosted service is backed by subnet 31 miners could not be established.
  • Several team-announced dates passed without confirmation (a beta at the end of June, a 2026-07-07 release, 'live in 48 to 72 hours' on 2026-09-28, a 2026-10-12 production rollout); on 2026-10-23 the team gave no date.
  • Commit-reveal weights were switched off on 2026-10-13 without an explanation found. Whether the weight on the owner's UID 0 is the intended launch state or a placeholder is not known, since the code is private.
  • Chain facts are dated snapshots: block 9355046 (2026-10-24) for the current state and 11 sampled blocks from 2026-09-10 for the history; changes between samples were not observed. The explorer's figures come from the project's own API and describe testnet.
  • The new owner's statements that they bought the subnet and locked their owner alpha could not be checked on chain (the owner key shows no change since registration), and the site's product claims were not independently tested.

What it is

Polaris was a decentralized compute subnet, mainnet SN49, where miners registered GPU and CPU machines and validators rewarded their uptime. It was deregistered on 2025-10-31 after months of disputes over emissions and a burn that reached 100%, and its mainnet slot went to another project. The channel was moved to testnet in March 2026. Since then the team has described a different business: confidential-compute sandboxes, attestation as a service and persistent agent computers, sold through polaris.computer and cathedral.computer. No miner or validator guide for a testnet subnet 292 was found.

How it works

Miners

Nothing is documented for subnet 292. On mainnet SN49 (until 2025-10), miners registered machines on the Polaris Cloud web dashboard, which ran automated checks and a manual review, then kept a heartbeat service (the watchtower) running on each machine; there were caps on CPU count and GPU requirements such as Docker and the NVIDIA toolkit. In April 2026 a newcomer asked whether any public testnet miner path exists and the archive shows no answer.

Validators

No testnet validator guide was found. The last public validator repository (PolarisCloudAI/polarisvalidator, last push 2025-10-29) describes the mainnet scoring: a base score from uptime and container activity, a proof-of-work compute multiplier with a minimum of 0.03, bonuses for uptime, container use and alpha stake, and a 30% penalty for machines that did not allow mining. Its last commit set a 90% burn.

Incentive

Unknown for subnet 292. A testnet read on 2026-10-21 showed no UID with incentive. The team said on 2026-07-01 that it now aggregates compute from other subnets and builds its own layer for confidential CPU and GPU compute and attestation, which points away from a miner-rewards design.

Recent activity

On testnet it exists with 48 of 256 neurons, 31 validator permits, commit-reveal on and no UID with incentive; its identity says titan-subnet, a temporal-integrity project, not Polaris.
  • 2026-10-20 (cathedral.computer) The team's Cathedral site reported a run of 4,000 agents started at once in separate sandboxes, 3,980 puzzles solved, and 1,000 sealed runs with signed receipts for every command. These are the team's own numbers.
  • 2026-09-26 (#polaris) A team member said the focus is the best place to deploy persistent useful agents on its sandbox product, and that agents deploy slowly from a cold start, to be fixed in coming releases.
  • 2026-07-01 (#polaris) A team member said the project is leaning into confidential compute: general community compute is largely solved by other subnets, so Polaris aggregates and routes demand and builds its own layer for confidential CPU, attestation as a service and confidential GPU.
  • 2026-04-06 (#polaris) A newcomer asked whether mining is now via the Polaris Cloud dashboard or a public testnet path, and another asked whether Polaris is back. The archive shows no reply.
  • 2026-03-05 (#polaris) A moderator welcomed the channel back, now as a testnet channel.
  • 2025-11-01 (#polaris) After the 2025-10-31 deregistration the team said it would keep building and later test incentivized mining linked to its compute layer on testnet; the mainnet channel was archived on 2025-11-03.

Getting started

  1. No miner or validator setup guide for subnet 292 was found, so there are no steps to list.
  2. To see the old mainnet design, read the README and reward documents in PolarisCloudAI/polarisvalidator; they describe SN49 before 2025-10-31 and are not current.
  3. Ask in the subnet channel what, if anything, runs on testnet before spending time or funds; the April 2026 question there got no reply in the archive.

Caveats

  • Netuid 292 is a testnet netuid here. Nothing on this page describes mainnet emissions or economics.
  • The on-chain identity of testnet subnet 292 (titan-subnet, with a repository that returned 404) does not match Polaris, so the link between this channel and that slot rests only on the archive's channel name and a 2026-03-05 moderator post.
  • Mechanism details come from 2025 mainnet-era repositories and chat; the validator repo has had no push since 2025-10-29.
  • The team's websites and docs say nothing about a subnet, miners or testnet 292; the docs page mentions Bittensor only as an off-by-default flag in a sample request.
  • Cathedral figures (agents started, puzzles solved, signed receipts) are the team's own claims and were not verified; the Polaris configurator page says it was using development data when read.
  • The reasons for the 2025 deregistration were disputed in chat (team blamed validator sync and watchtower conflicts; miners blamed the team); both are unverified here.
  • Chain weights and testnet ownership were not examined; the testnet read was a single one-off query for parameters and incentive counts.

What it is

Sluice describes itself as a decentralized market for routing policies: an application sends an AI request with constraints such as budget, latency, quality floor and privacy, miners propose which provider and model should serve it, and validators benchmark the proposals so the best route wins. It says it does not run models itself and would route to providers such as Chutes, Targon and direct model APIs. Everything about the mechanism comes from the team's website and chat; no miner, validator or subnet code is public, and the public repository is only the website.

How it works

Miners

As documented by the team (not verifiable in code): miners are routing agents, not compute nodes, so an ordinary server is said to be enough. For each request they receive task metadata and propose a destination (provider and model) together with a predicted score for cost, latency, quality, reliability and privacy. The team says only the winning proposal is rewarded and losing proposals earn nothing. The website's demo app imitates a miner with a single call to a Google Gemini model; that is a front-end simulation, not the network.

Validators

As documented by the team: validators run the proposed routes, measure latency, quality, cost and privacy compliance, and compute a regret-weighted score against reference alternatives, which then feeds Bittensor consensus. Quality is to be judged by comparing outputs with reference responses (similarity, ground-truth accuracy or a preference proxy). The site shows score weights of 50 percent quality, 25 percent cost, 15 percent latency and 10 percent reliability; the FAQ also treats privacy as a component and as a hard constraint for flagged requests. No validator code is published, so none of this was checked against an implementation.

Incentive

The team's stated rule is that the miner whose route earns the best validator score on a request is rewarded, with regret weighting meant to stop miners from copying safe defaults, and no participation reward for losing proposals. Developers would pay providers normally and TAO would only be the reward and staking currency. On the testnet read (block 8273009) no neuron had incentive or dividends, and the owner-hotkey slot received about 44 percent of the last epoch's testnet emission. Weights on the testnet were not examined beyond their age.

Caveats

  • Testnet only. Nothing here describes mainnet emissions or economics, and no mainnet netuid has been announced; the roadmap on the site is in relative weeks (mainnet at weeks 7-8) with no calendar dates, and the team's answer that mainnet would come in the coming weeks dates from 2026-06-05.
  • No subnet code is public. The only public repository is the website; the FAQ promises public reference miner and validator code, which the organization's public repositories did not show on 2026-10-21. The scoring, regret weighting and privacy attestation described above are team statements that could not be checked against an implementation.
  • Docs are largely unfinished: Quick Start, Scoring Engine, Run a Miner, Run a Validator, Route API and Changelog are still 'Drafting' placeholders. Only the overview, vision, core concept, SDK reference and FAQ pages have content, so there is no usable miner or validator setup guide.
  • The website's numbers are not live. The Subnet page (1 miner, 1 validator, 44.64k alpha stake, 3.15 TAO pool, 296.02 alpha daily emission) and the Dashboard (128,420 requests routed, $3,842 savings, 94.3 percent pass rate) are constants in the site code, although the FAQ says the Subnet page shows live on-chain data. The testnet shows five neurons, not one miner and one validator.
  • The in-browser app is a simulation: the 'miner decision' is one Google Gemini call, provider cost and quality figures are hard-coded samples, and the answer text is canned. It does not show that routing between real providers works.
  • On the testnet read every neuron held a validator permit, none was active, and all five validators' last weight-sets were at least 557,806 blocks old (about 77 days at 12-second blocks). That suggests no live scoring at the time, but it is a snapshot of testnet state, not a statement about the team's plans, and who operates the other four neurons is unknown.
  • The scoring weights on the website (50/25/15/10 for quality, cost, latency, reliability) leave out privacy, while the FAQ lists privacy compliance as part of the composite score. Which description is current was not verifiable.
  • Privacy statements differ: the team said in chat that version 1 may use the prompt for routing, while the FAQ says miners receive task metadata and the prompt goes straight to the winning provider. What miners and validators would actually see is not documented.
  • The SDK page shows 'pip install sluice' and 'npm install sluice', but the team said on 2026-06-05 that the package could not yet be installed. The package registries were not checked, so a package with that name may be unrelated.
  • The chain identity points to github.com/sluice-ai/sluice, which now resolves to the website repository, so it is probably the same repository under an earlier name. Private repositories, if any, were not visible.

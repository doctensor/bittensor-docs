What it is

Epago (SN36) set out to produce the best small open deep-research model. Miners fine-tune the reigning king and submit a private checkpoint; a challenger that beats the king on a fresh research exam by a clear statistical margin is crowned. One king was crowned, on 2026-09-16. The slot's previous occupant was Leoma.

How it works

Miners

Miners fine-tune the king model and submit a private checkpoint with the king's digest. Intake rejects another architecture, code files, a model over 5% larger, copies and a failed format probe. Three attempts per hotkey; nothing is escrowed.

Validators

One owner-run validator evaluates every round and opens it with a key only the owner holds. Challenger and king answer the same exam (exact paper titles, so no AI judge); the validator sets weights about hourly.

Incentive

Published rule: 95% of miner emission is burned and the king gets 5%. On chain since 2026-09-21 it is different (see below).

Roles and requirements

Miner High barrier

Fine-tunes the king and submits a private checkpoint to beat it in a duel.

  • Genesis king: Tongyi-DeepResearch-30B-A3B (Apache-2.0, about 3.3B active parameters); since 2026-09-16 the king is a miner's checkpoint.
  • Private submissions only; the hotkey must be Ed25519 because upload credentials are encrypted to it.
  • Attempts are counted from round 4; a model trained on an old king is dropped as stale.

Validator High barrier

Runs duels and sets weights; in practice only the owner's validator evaluates.

  • Quorum design: 51% of evaluator stake once 3 evaluators exist; with fewer, one accept crowns. Only the owner's validator ever published verdicts (5).
  • UIDs 1 and 2, on other coldkeys, set the same weights as the owner; their holders are unknown.

Where the miner incentive goes

  • Until 2026-09-21 weights matched the published design: 95% to the owner's burn key, 5% to the king.
  • UID 23 registered on 2026-09-21 during round 4. Within about two hours the owner's validator put all its weight on it; all three weight-setting validators do today.
  • UID 23 holds all miner incentive and the king's UID earns none. It never set weights, is absent from the published dashboard, and its coldkey is neither the owner's nor the king's.
  • The published code cannot produce this, so the code now running is not public. Who holds UID 23 is unknown; self-mining claims in chat are unverified.

Getting started

  1. Check that rounds are running first: nothing has been published or committed since 2026-09-21. Ask in the subnet's Discord channel.
  2. Read the miner guide and mechanism spec; the mainnet settings are in chains/EPAGO-DR-30B.toml.
  3. Create an Ed25519 hotkey, register it on SN36 and install the epago command-line tool.
  4. Download the king's weights, train within the locked architecture, then upload and submit with the king's digest.

Caveats

  • Stalled: no verdict, round or challenge on chain after 2026-09-21, though rounds opened by a private key could run off chain.
  • Chain payouts do not follow the published rules, and the repository has no commit after 2026-09-21, so the validators' current code is not public.
  • Everything depends on the owner, who left Discord, cleared the chain identity on 2026-10-27 and explained neither; epago.ai is for sale and the leaderboard host is down.
  • Published results are thin (14 duels, 13 miners); some docs still show an older payout schedule. Only 7 days of pool flow were read.

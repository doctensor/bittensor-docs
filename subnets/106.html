What it is

Nodexo 3.0 (mainnet launch announced for 2026-06-23) is a GPU marketplace on Bittensor. Miners register GPU hosts as executors on the Bittensor EVM and keep sending timed hardware proofs. Validators check the proofs using only a CPU, randomly rent idle machines to themselves (canaries) to test them, and set weights in proportion to each machine's reference market price. Renters pay through the team's web app (x402 or account credits). The team also describes a conviction allowance: alpha locked in the subnet earns daily compute credits.

How it works

Miners

Run the Nodexo miner on an Ubuntu/Debian GPU host with a supported NVIDIA GPU, Docker and the sysbox runtime. Each GPU endpoint registers as one executor in a Bittensor EVM registry (gas is paid in TAO mirrored to the EVM address). The miner sends a proof every 15 blocks (about 3 minutes), heartbeats about every minute, and starts rental containers when the primary validator asks. The public API port and a rental TCP port range (20000-20100 by default) must be reachable from outside.

Validators

Verify proofs, ingest heartbeats and hardware reports, scan for sybil patterns, score every executor each minute and set weights about every 72 minutes (360 blocks). Only the primary validator runs rentals and canaries; a canary rents an idle executor, fills its GPU memory, measures memory bandwidth against a per-GPU floor and checks a hash. An optional follower mode lets a low-resource validator copy the primary validator's published scores instead of verifying proofs itself.

Incentive

An executor scores a reference hourly price for its GPU model times GPU count, times 1.0 when rented or an idle share when not (live config: 0.8), times a proof pass-rate factor (pass rate squared, with a 0.67 floor). The score is zero if any gate fails: calibrated timing model for that GPU and count, a proof in the last 10 minutes, enough proof samples, a recent heartbeat, no open hard sybil flag, a passed and not-failed canary, minimum miner version, and a stake requirement in alpha. A miner's score is the sum over its executors, normalised into weights. Live config sets no burn. The conviction allowance (locked alpha for compute credits) is enabled in the live config, but its backend is not in the public repository.

Getting started

  1. Check that your GPU model and count are accepted (docs page 'Supported GPU Configurations' and the live runtime config); miner setup stops before registration otherwise.
  2. Prepare an Ubuntu/Debian host with working nvidia-smi, Docker, at least 4 CPU cores, 16 GB RAM and 40 GB free Docker storage, and a hotkey registered on netuid 106.
  3. Install with the repo's install.sh or scripts/setup_miner.sh, fund the miner's EVM address with some TAO for gas, and start it under PM2 using ecosystem.config.example.cjs (auto-update is on by default).
  4. Serve the miner API on a real HTTPS domain and keep the rental TCP range (20000-20100 by default) directly reachable from outside; the canary connects to whatever host and port your miner hands back.
  5. Expect no score until the executor has valid proofs and has passed a canary; the live canary interval averages 4 hours but gaps vary, so waits of many hours happen.

Caveats

  • Direction is unclear: the team said on 2026-10-04 it is focused on subnet 96 and in talks to sell 106, then on 2026-10-15 that 106 will return. Treat the subnet as transitioning and check the channel before committing hardware.
  • The public repo's last commit and release (v0.1.8) are from 2026-07-23, yet chat and the live config (version 58, 2026-10-14) describe later behaviour. Repo docs lag the live config: canary interval 24 h vs 4 h live, ban at 3 error streaks vs 6, idle share 20% vs 80%, default burn 80% vs none.
  • A minimum miner version of 1004 was announced on 2026-07-16, but the live config reads 1001; which one validators enforce was not confirmed.
  • Supported-GPU lists differ between the repo docs (5 models), the site docs (10) and the live config; B300 SXM6 is accepted in chat but its timing model is marked uncalibrated.
  • Chain weights are validator opinions, not payouts. Incentive is concentrated (8 uids, one with about 42.5%). Validators can run in follower mode and copy the primary validator's scores; which of the 15 aligned validators do so was not checked.
  • The renter web app, credits and conviction-allowance backend are not in the public repo, so how locked alpha converts to credits was not verified beyond the config values. Team claims such as perpetually locked team stake (2026-06-26) were not checked on chain.
  • The stats page is team-run. Who rents the 61 rented GPUs is not published, and the drop from 94 listed executors (2026-09-20) to 55 nodes is unexplained.
  • Chat before June 2026 in this channel covers earlier occupants (VoidAI) and older SN27-era pinned posts; it was not used. The whitepaper and X posts were not read.

What it is

MVTRX (formerly tau-os, repo sn-79) simulates limit-order-book markets where miners act as trading agents against background traders. It pays for liquidity and risk-adjusted profit. The team's alpha-token exchange is not live on mainnet.

How it works

Miners

A miner's Python trading agent answers each validator update with orders; slower replies add simulated delay, and since 0.6.5 query order is random. Optional: train the shared GenTRX model (1 miner did on 2026-10-29).

Validators

A validator pairs a C++ market simulator with a Python validator that sends state to miners, applies their orders, scores them and sets weights from a 3-hour moving average. Runs last four to five days on the owner's configuration. Only the owner's UID holds a validator permit, so it alone sets all incentive.

Incentive

About 95% of miner pay goes to trading, up to 5% to GenTRX training. Trading splits into two equal halves paid by share, not rank: making (spread captured on two-sided maker fills and held 20 simulated seconds later) and skill (profit after removing market drift). Chain split: 18% owner, 41% validators, 41% miners, none burned.

Roles and requirements

Miner Low barrier

Writes and runs a Python trading agent that places orders in the simulated markets.

  • Limits: replies within 3 s; 5 instructions per book per round; volume cap 10x capital per book per 24 simulated hours.
  • Optional GenTRX: a GPU with 6 to 8 GB VRAM is advised.

Validator High barrier

Runs the simulator and validator, scores miners and sets weights; only the owner's validator holds a permit today.

  • The owner's UID holds the only permit (2026-10-29) and gets 50% of emission, the validator half.

Bull case

  • Team ships often; code is open (MIT).
  • 245 of 256 slots earn; top miner 1.2%.

Bear case

  • One owner validator sets all weights.
  • Exchange not live; real-capital market gated.
  • Rules keep changing; a confirmed scoring bug awaits its fix.

What would change this view: A second independent validator, a live exchange or named revenue would turn it bullish; renewed outflow or another scoring dispute, bearish.

Getting started

  1. Read the FAQ, the README incentive sections and agents/README.md; scoring changes between releases.
  2. Install with install_miner.sh on Ubuntu and write your own strategy; the example agents are templates.
  3. Test locally with the proxy tools or on testnet netuid 366; mainnet miners can ask the team for testnet TAO.
  4. Register on mainnet netuid 79 (about 0.07 TAO) and run the miner within the 3-second and 5-instruction limits.
  5. After each release post, pull the repo and restart; the team says a 0.6.5 agent runs unchanged on 0.6.6.

Caveats

  • One owner-run validator holds the only permit and sets every weight; nothing independent checks the scoring.
  • Rules change often: five scoring releases in five weeks, from 0.6.2 (09-24) to 0.6.6 (testnet, 10-29).
  • The team confirmed a scoring bug on 10-29; the 0.6.6 fix is promised for mainnet on 10-30.
  • Wash trading: coordinated-set figures are the team's own. On 2026-10-23, 256 slots sat under 37 coldkeys, 18 holding 88% of incentive (not proof of one operator).
  • Whether a new miner profits is unknown: 61 UIDs re-registered in the day before 10-23. GenTRX had 1 active miner on 10-29, down from 21 on 10-21.

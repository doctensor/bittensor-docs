What it is

MVTRX (formerly tau-os) simulates limit-order-book markets where miners trade as agents against background traders, paid for liquidity and risk-adjusted profit. It went live on mainnet on 2025-05-07 and rebranded in early 2026. The team's alpha-token exchange is not live on mainnet.

How it works

Miners

A miner's Python trading agent answers each validator update with orders (up to 5 per book, within 3 s). Optional: train the shared GenTRX model (1 miner active on 2026-11-26, 21 on 10-21).

Validators

A validator pairs a C++ market simulator with a Python validator that sends state to miners, applies their orders, scores them every 5 simulated seconds and sets weights.

Incentive

About 95% of miner pay goes to trading; GenTRX training gets up to 5%. Trading splits into two equal halves paid by share, not rank: making (spread captured on two-sided maker fills, held 20 simulated seconds) and skill (profit after removing market drift). Chain split: 18% owner, 41% validators, 41% miners, none burned.

Roles and requirements

Miner Low barrier

Writes and runs a Python trading agent that places orders in the simulated markets.

  • Volume cap: 10x capital per book per 24 simulated hours.
  • Optional GenTRX: a GPU with 6 to 8 GB VRAM is advised.

Validator High barrier

Runs the simulator and validator, scores miners and sets weights; only the owner's validator sets weights today (a second permit has set none).

  • The owner's UID gets 50% of emission, the validator half (2026-11-26).

Getting started

  1. Read the FAQ, the README incentive sections and agents/README.md; scoring changes by release.
  2. Install with install_miner.sh on Ubuntu and write your own strategy; the example agents are templates.
  3. Test locally with the proxy tools or on testnet netuid 366; the team can supply testnet TAO.
  4. Register on mainnet netuid 79 (about 0.04 TAO) and run within the 3-second and 5-instruction limits.
  5. After each release post, pull the repo and restart; 0.6.7 moves class book ranges, so read each book's class.

Caveats

  • One owner-run validator sets the weights, so nothing independent checks the scoring; a second permit (uid 152) has set none.
  • Rules change often: seven scoring releases in nine weeks (0.6.2 on 09-24 to 0.6.8 on 11-23), then a block rule on 11-25; the deployed version is unpublished (issue 7, no reply).
  • The team confirmed a scoring bug on 10-29 (GitHub issues 5 and 6 closed that day). The top share later swung from 0.9% to 4.4% on a one-day-old uid; cause not established.
  • Wash trading: the team put the largest coordinated set at 7.9% of incentive (09-29). On 11-26, 42 coldkeys held the slots; the largest holds 36 uids and 16.2% (not proof of one operator).
  • A new miner's profit is unknown, but slots turn over fast: 49 of the 57 uids registered in the last day already earn.

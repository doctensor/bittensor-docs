What it is

Enigma (SN63) is a bounty subnet run by qBitTensor Labs. It posts hard problems as numbered milestones with a prize attached; the first solver who passes validation takes the whole prize and the winning code is published as open source. Two challenges are live, each built with an outside partner: Breaking RSA (factor semiprimes of growing size, with Terra Quantum) and Hardening Quantum Proof (find the hidden peak of an obfuscated quantum circuit using classical methods only, with BlueQubit). A first challenge, on breaking the treasury wallet itself, closed on 2026-05-21 with no winner. Winning RSA and quantum-circuit solvers are archived in two open-source repos.

How it works

Miners

Write a solver as a Docker project, test it locally with the repo's workbench, then submit the zip with the mine-enigma CLI. The CLI uploads the zip to the team's platform, pays a TAO fee on chain only after the upload succeeds (the site shows about 0.1 TAO per submission) and stores a record that the miner process serves to trusted validators. Resubmissions are unlimited. The miner process itself needs only 1 CPU core and 8 GB RAM; the heavy computing happens in the solver on the validator's hardware. The lab's terms bar its own employees, contractors and family from claiming prizes.

Validators

Validators ask miners for submissions, check the on-chain fee proof, register the work with the team's Challenges API and run each solution in Docker with no network, a read-only root disk and a 4 hour wall time on a high-end GPU box (the docs name an RTX PRO 6000 class card with 96 GB VRAM, 24 vCPU, 85 GB RAM). The platform also hands out cross-check work so several validators agree. The number of passing runs a winner needs is set per milestone by the platform; chat says it was 3 and became 5 from Hardening Quantum Proof level 4. Validators also vote on prize payouts from the treasury. On chain at block 9343844 (2026-10-23) the subnet had 10 validator permits, 8 of which had set weights in the last 350 blocks.

Incentive

Miner emission does not go to miners by weight. By design and in the validator code, validators point their weights at one of five treasury sink hotkeys (the team platform names the sink for each tempo), so emission piles up as SN63 alpha for prize pools. Chain read at block 9343844 (2026-10-23, about 04:28 UTC): 99.98 percent of incentive sat on one sink hotkey and the remaining 0.02 percent was dust spread over seven other uids; each of the 8 validators that set weights put its weight on a single sink (three different sinks across them, consistent with the per-tempo rotation); none targeted the burn sink, which is the owner's own hotkey. All five sink hotkeys share one coldkey, the vault named on the team's governor page. The subnet's emission split is 18 percent owner, 41 percent validators, 41 percent miners, with unallocated miner emission set to burn. Alpha held: the vault held about 435,600 alpha on SN63 and the separate wallet the team committed to the treasury about 117,400 alpha; most of both is staked on one large validator's hotkey, which also holds about 92 percent of validator dividends and is the source of every payout (dollar value not computed). A prize leaves the vault only through a validator vote (docs: 60 percent approval, 50 percent quorum, about 3 days of voting, 1 day timelock). The governor page lists 13 payout proposals since 2026-05 (12 executed, 1 defeated; the nine with amounts shown total about 87,600 alpha). The defeated one, on 2026-07-06, was the 480-bit prize: the team said a mainnet release had broken gas estimation for the vote, so it paid the winner directly from its committed wallet. Prizes start at a baseline, for example $10k, and the team raises them at its own discretion while a milestone stays unsolved; on 2026-10-14 it said it may have raised an RSA prize too fast and was back to raising it slowly each week. The validator code also has an optional pool cap that would route emission to the burn sink above 200,000 alpha per active challenge; the vault holds more than that, yet no weight went to the burn sink on 2026-10-23, so the cap is not in force on the validators that set weights (or is configured differently; their settings are not public). The team's announced next step is bounded per-challenge pools with overflow burned, no date given. It also says licensing of winning solutions to commercial users is meant to fund buybacks and stated on 2026-10-12 that no commercial licence revenue exists yet.

Getting started

  1. Check the team site for which milestones are open and their prizes before you start; the repo README lags it.
  2. Clone the enigma repo, run pip install -e . and read the challenge README and the workbench README for the challenge you want. The winning solvers of earlier milestones are public (links above) and the team says to start from them.
  3. Build a Docker solver that reads the mounted challenge input and prints its result on stdout in the documented format.
  4. Test with enigma-workbench test breaking-rsa (or hardening-quantum-proof) --solution <your_dir> in Docker mode, which mirrors the validator.
  5. Zip that same directory, run the miner process with your hotkey, and submit with mine-enigma; the TAO fee is paid from your coldkey after the upload succeeds.
  6. Keep in mind the local run is the only free test: each submission carries a fee and winners must pass several validator runs.

Caveats

  • The chain read is one block (9343844, 2026-10-23); the sink hotkey that gets the emission rotates by tempo, so a later block will show a different one of the five. The chain shows where weight and stake sit, not what the team intends or what the platform decides.
  • Whether validators run the optional pool cap, and with which setting, is not public. The cap code reads the number of active challenges from the team platform, which was not read. The conclusion that it is not in force rests on the burn sink getting no weight at one block.
  • Alpha holdings are given in alpha only. The team site's dollar figures (pool, committed, buffer, paid out) are team-reported, move live (the pool read $560,000 to $562,000 on 2026-10-21 and $543,446 on 2026-10-23) and were not reproduced from chain balances because no dated TAO/USD price was used.
  • The governor page lists 13 payout proposals but three early ones show no amount, and the page does not say which milestone each paid; only the 2026-07-06 one is explained in chat.
  • The README's results paragraph is a July snapshot (it says RSA-500 was open) and the team site's /next page still shows an older total ($70K paid across 6 milestones); the home page and chat were used for current milestones.
  • The team gave two reasons for the level 3 second payout: a bug that let a second solution be validated after the first was already in review, and a wish to buy a novel technique. Both statements are in the channel (2026-10-14 and 2026-10-15).
  • Some miners reported timeout errors where the fee was charged but the upload did not complete (2026-10-14); the team asked for evidence and had not said whether refunds were given.
  • The team's own thesis is that value comes from licensing winning solutions; on 2026-10-12 it said no licence revenue exists yet, and a livestream summary of 2026-10-01 says a first licensing deal is only being explored, so the commercial model is still unproven.

What it is

Score runs TurboVision, a subnet that rewards computer-vision models. Each task type is an Element in a manifest published by the Score team. On 2026-10-21 the manifest listed eight: six public object-detection Elements (beverage, person, vehicle, petrol station, worksite PPE, fallen or crouching person) and two private ones (football events, cricket deliveries). Miners compete per Element, and a central validator operated by the team scores them against ground truth supplied by Score and its data partners.

How it works

Miners

Public track: train an open-source model, publish it on Hugging Face, deploy it as a Chute on Chutes, and commit it on chain for one Element. Private track: serve a Docker image that answers POST /challenge on port 8000, push it to a private GitHub container registry, and commit the exact Element id on chain. One deployment serves one private Element.

Validators

A central validator run by Score fetches challenges, calls the committed miners, scores the answers against ground truth, and publishes results. The repo documents a validator stack others can run (Docker, Cloudflare R2, Chutes and Hugging Face credentials), but the chat treats the central validator as the one that matters. On 2026-10-21, 14 uids held validator permits and 9 of them had set weights on the paying mechanism, with near-identical rows. A public detection Element is scored as 0.6 x mAP50 plus 0.4 x a false-positive score (1 minus the average number of false positives per image divided by 10, never below 0); the overlap bar for a match depends on box size and runs from 0.3 to 0.7. Public models also face an automated latency check (p95 of 100 ms per frame or better on 2 vCPUs). Private images are spot-checked by pulling the committed image and comparing its output with the live endpoint; a mismatch scores zero and gets the hotkey blacklisted.

Incentive

Each Element has a weight in the manifest. The manifest of 2026-10-21 (re-issued with the same weights as 2026-10-01) gave football 50%, cricket 20% and each of the six public Elements 5%. Cricket was 30% before 2026-10-01, when two public Elements were added; the team said on 2026-10-21 that it cut cricket first because cricket is less contested and the football client is pushing for a better model. On a public Element the miner with the best average score over the recent window (default 3 days) takes the whole Element share, subject to a copy tie-break: if two miners score within about 0.05 per challenge on both recent and sampled historical challenges, the earlier on-chain commit wins. On a private Element the top three miners share it 80/15/5. The chain agrees with this: the subnet has two mechanisms, all emission goes to mechanism 1 (mechanism 0 gets none), and on 2026-10-21 the 12 paid uids on mechanism 1 matched the manifest shares (football 40/7.5/2.5% of the miner pool, cricket 16/3/1%, six public winners about 5% each). The chain's own emission split on that date was 18% owner, 41% validators, 41% miners.

Recent activity

  • 2026-10-21 (#score) The team removed three more worksite-PPE challenges and one petrol-station challenge as wrongly annotated, and said it will harden the fallen-person dataset once more and close that Element if all miners keep scoring full marks.
  • 2026-10-21 (#score) The team explained that private-track miners who are deregistered must manage their hotkey lifetime: commit recovery is meant for the public track, because on private tracks missing a few high-variance challenges could make a re-registered miner eligible for weights unfairly. It also said cricket was cut first in the weight rebalance because it is less contested and the football client is pushing for a better model.
  • 2026-10-20 (#score and GitHub commit log) A further tie-break hotfix kept zero scores in the last-10 comparison, and the team removed three PPE challenges as mis-annotated while keeping the petrol ones.
  • 2026-10-19 (#score) The team announced a review process for football challenges: miners send block number, task id and concrete evidence of an annotation-rule breach (a bad score alone does not count). It also fixed an archive read issue that let some miners avoid challenges and changed the recent-batch tie-break to compare the last 10 challenges two miners have in common.
  • 2026-10-17 (#score, 2026-10-16 to 2026-10-17) The historical part of the copy tie-break was loosened: the number of failed challenges needed to count as different dropped from 4 to 3. Miners had argued that converged scores let older commits win too often.
  • 2026-10-14 (#score) The team published ground-truth training data for the cricket private track and blacklisted a hotkey whose results it could not reproduce.
  • 2026-10-01 (#score and the Score manifest) Two public Elements went live: worksite PPE detection and fallen-person detection. Their 10% combined emission was taken from the cricket private track (cricket 30% to 20% in the manifest). The cricket scoring weights were rebalanced the same day.
  • 2026-09-20 (#score and the Score manifest) The public petrol-station detection Element went live, with annotation rules for roof canopies, price boards and hoses.

Getting started

  1. Follow the shared setup in the repo README: wallet, Chutes developer account, Hugging Face token, and the sv command-line tool.
  2. Register a hotkey on subnet 44 with btcli.
  3. Public track: build a model for the Element you choose, benchmark it under the 2 vCPU latency limit, then deploy and commit with sv deploy-os-miner.
  4. Private track: implement the /challenge endpoint, push the image to a private registry, give Score read access, then deploy and commit with sv deploy-pt-miner.
  5. Check the Element list and current rules in the console and the announcements channel before you start, because Elements and weights change.

Caveats

  • Element weights come from a manifest the team publishes and re-issues; this page read the version of 2026-10-21 (block 9329471). The console and announcements channel show the current list, and weights can change without a code change.
  • The README points to a MINER.md at the repository root that does not exist; the two miner guides are under scorevision/miner. The README and the guides also use different variable names for the Hugging Face credentials.
  • Element ids are spelled manak0/... for public Elements and manako/... for private ones in the live manifest. Some docs and announcements use one spelling for both.
  • Miners reported many suspect ground-truth boxes in October, and the team removes challenge blocks it agrees are wrong. Challenges also stalled for hours several times between 2026-10-16 and 2026-10-21 (beverage, football, PPE).
  • The copy tie-break is contested. Miners say it can hand the reward to an older, near-identical model when scores converge; the team says it protects against copying and works as designed, and on 2026-10-21 said it rarely triggers except on fallen person and petrol station. Three of the nine validators with weights listed a different winner on one or two public Elements on 2026-10-21.
  • Chain concentration on 2026-10-21: the three paid football uids share one coldkey and the three paid cricket uids share another, and neither is the owner's. This page cannot say whether each is one operator running several hotkeys, or whether the rules allow that. A few chat participants accused the team of self-mining on 2026-10-19; the team denied it, and no paid uid shares the owner's coldkey.
  • How the baseline and difficulty settings in the manifest enter the final weight was not traced; the code gives the whole public Element share to the winner. The cricket and football scoring formulas were not re-derived, and the TCG-grading Element in the repo docs was not in the live manifest.
  • Chain figures are a read at block 9334663 to 9334675 (2026-10-21). Chain weights are validator opinions, not payouts.

What it is

AuditPal is a Bittensor subnet project in which AI agents compete to find vulnerabilities in smart contracts and a validator scores them against known bugs. In May 2026 the team added a bug-bounty marketplace with human triage that would later feed the subnet's benchmarks. Only the test network has been used; no mainnet date has been given.

How it works

Miners

A miner publishes a public GitHub repository with an agent.py. The validator clones it, screens it for banned calls (os.system, subprocess, eval, pickle), runs it on its own machine with its own LLM key and reads back findings: type, severity, file and line. EVM (Solidity) comes first; Solana and Move are listed as coming.

Validators

The validator takes a challenge and its ground truth from team-run backends, queries a random sample of miners, runs their agents and posts per-miner results to the team. V1 (last commit 2026-03-09) scores 0.70 F1, 0.20 severity accuracy and 0.10 metadata quality. V2 (2026-04-29) runs each agent in Docker and scores each finding on file, type and severity, with a penalty per false positive. Benchmarks: the team's Solbench-30 and OpenAI's EVMbench.

Incentive

The team describes rewards three ways (see the table); both repositories turn scores into weights with a moving average. On testnet no uid has incentive, and which repository the validator runs is not stated.

Roles and requirements

Miner Low barrier

Publishes a GitHub repo with an agent.py that audits contract code; the validator runs it and scores the findings.

  • Findings follow a documented schema: title, type, severity, confidence, file, line.
  • No validator has scored anyone since at least 2026-05, so nothing can be earned today (2026-10-31).

Validator Medium barrier

Fetches challenges and ground truth from team backends, runs miners' agents with its LLM key, scores them and sets weights.

  • V1 posts each round's per-miner results to a team backend with an API key read from the environment.
  • V2 adds a Docker sandbox for miners' code.

Getting started

  1. Testnet only, no rewards today. Create a wallet, get test TAO and register a hotkey on testnet netuid 310 (burn 0.0005 test TAO on 2026-10-31).
  2. Clone the V1 repository and follow SETUP.md (4+ CPU cores, 8 GB RAM, 50 GB disk). One register command lacks a netuid: set network and netuid yourself.
  3. Write an agent.py that returns findings in the documented schema and publish it in a public GitHub repository.
  4. Start the miner and expect no score: neither testnet validator has set weights for about 173 or 309 days (2026-10-31).

Caveats

  • Testnet only: nothing here describes mainnet participation or token economics, and there is no mainnet date.
  • Uid 0 gets 99.6 % of last-epoch testnet emission; who holds it, and who the two validators are, was not read.
  • Challenges, ground truth and results pass through team-run backends that were not inspected, and the validator runs miners' code with its own LLM key. Nothing was run here.
  • Site counts (2 validators, 5 miners, 175 sessions) have not moved since 2026-10-21; its benchmark page shows no runs and EVMbench under construction, while the docs say active.
  • Chat volume (292 messages) is mostly joke replies to one ping on 2026-03-06. The bounty platform and enterprise plan are team statements; none were used or audited.

What it is

Cathedral sells sealed CPU sandboxes for teams that train, evaluate and generate data for AI agents. Each sandbox is a full Linux machine on Intel TDX or AMD SEV-SNP hardware, and the service signs a receipt for every command run so customers can check it offline. The subnet's role is to supply a verifiable pool of such machines: miners run confidential VMs, and validators check their hardware evidence, reject duplicates and test them with a bounded task. The subnet slot was bought in August 2026 for a different (inference) project that fell through before this team took it over.

How it works

Miners

Per the miner repo, a miner runs a worker inside an Intel TDX confidential VM (or an AMD SEV-SNP guest) with Docker and a public IPv4 address with TCP port 8081 open, announces that endpoint as the hotkey's axon, and keeps a control host that refreshes signed validator-access snapshots. Several machines can share one hotkey, but each must pass verification on its own and duplicate hardware scores zero. GPU machines are not a qualified path. The team said on 2026-10-03 that it was still choosing how to admit outside miners and would first seed supply with its own marked machines.

Validators

A validator finds serving miners without validator permits and checks fresh TDX or SEV-SNP evidence along with the live TLS key. It zeroes every claimant involved in a duplicate endpoint, hardware identity or TLS key, sends each remaining machine one bounded SAT task, and writes weights from the verified work with zero burn. SEV-SNP machines count only if the validator's own reviewed measurement and TCB policy admits them, and by default a TDX machine needs only a genuine fresh quote, not a specific image.

Incentive

Weight is based on the number of distinct verified machines per hotkey. The repos say that registration, uptime, a quote or a self-reported machine count earns nothing on its own, and that weight does not guarantee TAO because the subnet needs positive emission. A quote does not prove which container image runs or that the machine stays intact after boot. Customer payment and its link to miner rewards are not documented.

Getting started

  1. Check the latest team post in the subnet channel first: the team said on 2026-10-03 that registration was not yet open and that the admission model for outside miners was undecided.
  2. If you plan to mine, read docs/MINING.md in the miner repo and run its local rehearsal three times before renting hardware or registering a hotkey.
  3. You need an Intel TDX confidential VM or an AMD SEV-SNP guest with Python 3.12, Docker, nft and a public IPv4 address with TCP 8081 open. Ask the validators you expect to score you whether they admit your SNP measurement.
  4. Keep the coldkey off the worker, register the hotkey only after the worker's local startup check passes, then announce the endpoint and confirm the weight row on chain.
  5. Validator operators need a validator permit on SN94 and should follow the validator repo's operator runbook, including the commit-reveal opt-in.

Caveats

  • Chain weights, emissions, the validator set and the number of miners were not read, and it is not verified whether anyone outside the team is currently being weighted.
  • The team said registration was not open on 2026-10-03, while the miner repo's guide describes Intel TDX mining as 'mainnet live testing'. The sources have not been reconciled.
  • Benchmark numbers (0.20 s, 1,000 sandboxes in 18.7 s, cost per sandbox-hour) are the team's own and were not independently run; the sealed TDX and SEV-SNP runs had not been published.
  • The validator README says Finney SN94 has commit-reveal enabled and operators must opt in, while a constants file in the same repo pins it as disabled for its older composer path.
  • Several repo descriptions still say SN39. The reason for the move to SN94 was not given, and a miner's question about it on 2026-10-08 has no answer in the channel data.
  • No pricing, customer or revenue figures were sourced. The sandbox service is described on the site as invite-by-email beta, and the AMD SEV-SNP admission on SN94 is listed as unverified.
  • A TDX quote does not remotely prove the container image or continuous runtime integrity after boot, per the repo's own support table.

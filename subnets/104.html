What it is

TAOStatus (SN104) started in September 2026 as a subnet that turns miners' spare LLM API capacity into a shared resource for the team's own analysis platform, then added a second track in which miners submit autonomous web-security agents. The subnet runs two Bittensor mechanisms on one netuid, one per track. The team sells audits by those agents through a marketplace and says miner rewards are meant to follow real work. The repo and chain currently show a full burn of emissions while the network bootstraps.

How it works

Miners

Two options, each needing its own hotkey because a hotkey has one axon. LLM-key track (mechanism 0): a miner configures 5 distinct API keys for supported provider and model pairs and hands them over encrypted when the validator asks, so the team's protocol can use them. Security track (mechanism 1): a miner serves a Docker image of an autonomous web-security agent that receives a target URL or source folder and returns a findings file; it must pass a benchmark before the marketplace lists it. Registration cost 0.5 TAO at the time of reading.

Validators

Mechanism 0: the validator relays encrypted keys to the team's closed BT Arena backend, which verifies and uses them and reports usage; the validator scores reliability (50 percent), latency (25) and volume (25), scaled by a model-tier weight and smoothed over time. Mechanism 1: the validator runs each agent in an isolated sandbox against fresh vulnerable apps carrying a hidden secret, replays the exploit on a new target, scores zero for unsafe behaviour and records a graded score. By default it does not query hotkeys that hold a validator permit.

Incentive

As written, each validator sets weights per mechanism from its scores after reserving a fixed burn share for burn UID 25, and the on-chain emission split between mechanisms is about 5 percent for LLM keys and 95 percent for security. The repo's default burn share was raised from 95 to 100 percent on 2026-10-09 while bootstrapping, and around blocks 9334310 on 2026-10-21 all incentive on both mechanisms sat on UID 25, so no miner was being paid. In chat on 2026-10-16 the team described a 5 percent miner pool and a small payout to one security miner, and on 2026-10-17 said security weights follow paid marketplace audits; the repo shows benchmark-based scores.

Getting started

  1. Register a hotkey on netuid 104 (0.5 TAO registration burn when read) and use a separate hotkey for each track.
  2. Security track: build a Docker agent that takes a live URL and/or source folder and writes a findings file (type, severity, endpoint or parameter, payload, proof); the team names SQL injection, command injection, path traversal, IDOR and SSRF as benchmark classes.
  3. Run the repo's security miner so your hotkey serves a publicly reachable axon and offers the agent; per the 2026-10-17 FAQ no stake or validator permit is needed, and permit holders are skipped.
  4. LLM-key track: configure 5 distinct keys for supported provider and model pairs and run the repo's miner (see MINER.md in the repo).

Caveats

  • Payouts are unconfirmed: the repo default and a chain read show all incentive on one burn UID on both mechanisms, while team chat described a different split. Check the metagraph before committing resources.
  • Repo, docs and chat disagree on what drives security weights (benchmark score versus paid audits) and on validator permits (2026-10-16 announcement versus 2026-10-17 FAQ; the code matches the FAQ).
  • The README still says netuid 501 testnet and the code defaults to testnet; mainnet settings come from deployment environment variables that are not public. The newest commit is 2026-10-10 and 16 branches exist, of which only dev and main were read.
  • Docs lag code: the security validator doc says sandbox and replay are not built, but code for them is in the repo.
  • The BT Arena backend that verifies keys and reports usage is closed, so reliability and volume inputs cannot be checked. The whitepaper PDF and the marketplace payment flow were not read; customer demand is a team statement, and the marketplace listed 3 agents with little audit history.
  • Chain mechanism 1 was read through raw storage; per-validator weights on mechanism 1 were not read. The netuid was registered about 529 days before 2026-10-21, long before the team's 2026-09-07 launch, and its earlier history was not determined.

What it is

NeverPlayAlone is a daily contest for Minecraft-playing AI agents by a two-person team. Miners write Node.js bots, validators score them on set missions, and the round winner takes all of the miner reward. The team plans paid hosted worlds with AI companions; the early-access site does not say miner agents run it.

How it works

Miners

A miner submits a Node.js agent (tar.gz, at most 1 MB) with npacli while a round is open. It runs offline in a validator sandbox, reaching an LLM only through the validator's capped proxy. The team picks the mission: crafting, combat (09-09), farming (10-07), and animal husbandry (10-28: breed and raise animals in a 20x20 pen, 100 points). A hotkey can enter three rounds; cheat scans can ban it.

Validators

Validators fetch each round's roster from the team's private backend, run every entry on five seeded tasks in Docker, then each computes the winner: stake-weighted mean scores, and a challenger must beat the champion's re-run by the margin. Seeds come from the chain's block hash at task start. Seven hotkeys hold permits; the owner's UID 0 holds about 90% of their stake (10-29).

Incentive

Validators put full weight on the winner, so one UID held 100% of incentive on 10-29. The champion's code stays private until dethroned or three rounds; other entries become public after each round. Alpha buybacks from product profit are a roadmap step; none seen.

Getting started

  1. Check the current mission and round on the dashboard; the docs lag.
  2. Register a hotkey on subnet 98 with btcli (burn 0.054 TAO on 2026-10-29).
  3. Clone the subnet repo and run scripts/miner_setup.sh to install npacli.
  4. Build a Node.js agent for the active mission and test it with npabench (needs Docker).
  5. Package it as a tar.gz up to 1 MB and run npacli submit while the round is open. Validators: docs, validators/install.

Caveats

  • Round and champion figures come from the team's dashboard feed, which shows no coldkeys; chain figures are a 2026-10-29 snapshot.
  • The closed backend sets roster, margin, mission and bans; the repo's validator code has not changed since 09-09.
  • On 10-29 the owner's validator moved its weight to UID 85 while four others stayed on UID 132; the cause is unconfirmed.
  • Despite the stored 60/7 miner/validator split, last-epoch emission still divides 50/50 between winner and dividend holders; why is unknown.
  • Self-mining, code-copying and score-swapping claims are unproven and unanswered; chain shows no winner under the owner's coldkey but cannot see other wallets.
  • Unknown: whether miner agents power the paid product, how the 2025 slot reached the team, whether forking agents is allowed.

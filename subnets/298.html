What it is

ChronoSeek is a subnet for searching inside videos by meaning: given a video and a plain-language description, miners return the time interval where that moment happens. The team ran it on testnet, said in August it had bought mainnet slot SN20, and said in late September it was stepping back. Only testnet netuid 298 exists today; SN20 carries a different project (Witness).

How it works

Miners

In the 2.0 design (dev branch) a miner deploys a video-search runtime to Chutes, a hosted compute platform, and commits it on chain; validators query it. The runtime takes a video link and a text query and returns the best-matching interval, using CLIP and Whisper models. The older 1.0 design (main branch) had miners run the service themselves.

Validators

Validators build tasks from ActivityNet Captions annotations and score each answer by how well its interval overlaps the true one. In the 2.0 code a private clip is compressed through Vidaio (another subnet) or ffmpeg and stored on Hippius, so miners see only that clip plus the query. The default score is 0.75 overlap plus small terms for centre, boundaries and length, smoothed by a moving average.

Incentive

Main branch: normalized moving-average scores become weights. Dev branch: 75, 20 and 5 percent to the top three miners with a positive score; an optional burn share (default 0) and the no-positive-score fallback go to UID 0, hard-coded. On the testnet no uid has incentive (2026-10-31); no mainnet emission exists.

Roles and requirements

Miner Medium barrier

Deploys a video-search runtime to Chutes and answers validators' search tasks.

  • Example config: one pro_6000 GPU, 16 GB VRAM or more, up to 3 instances, TEE-enabled (required for Chutes production).
  • One permanent submission per hotkey; a second revealed submission scores zero.
  • An own-axon path exists (external IP set by hand); its hardware is not documented.

Validator Medium barrier

Builds private video-search tasks, queries miner runtimes, scores answers and sets weights.

  • Testnet: 8 of 64 permit slots held; none has set weights in over 5 tempos (newest update about 65 days ago).
  • A Hippius bucket you own is required; the default name may belong to someone else.
  • Hardened task mode adds CPU, disk, network and storage load; no figures given.

Getting started

  1. Testnet only, no rewards: no testnet validator has set weights in 65+ days (2026-10-31), so a new miner would not be scored.
  2. Clone the repo, check out dev (the 2.0 guides; main is 1.0), install Python 3.12+ and Poetry, run poetry install.
  3. Copy .env.example to .env, set wallet and hotkey names, and change NETWORK to the test network and NETUID to 298 (defaults: finney, 20).
  4. Register a hotkey on testnet netuid 298 (burn 0.0005 test TAO on 2026-10-31).
  5. Miner: get a Chutes API key, copy chronoseek_chute.example.py to chronoseek_chute.py, deploy it with scripts/deploy_chutes_runtime.py, then commit the slug with miner.py (permanent per hotkey).
  6. Validator: add Chutes, Hugging Face and Hippius keys to .env and run validator.py or the Docker image (docs/validator.md).

Caveats

  • Testnet only: nothing here describes mainnet participation or emissions; test tokens carry no value.
  • The mainnet slot is unclear: the team said it bought SN20, but the chain shows only an owner change around 2026-08-14 and the Witness name since about 2026-09-09. Sale, handover or release is not claimed.
  • SN20's on-chain identity still listed this project's Discord invite on 2026-10-21, so that link leads to the ChronoSeek server.
  • Code is not proof of what ran: 2.0 sits on an unmerged dev branch, and the newest testnet weight update (about 2026-08-26) predates its last commit.
  • chronoseek.org and the MCP endpoint (HTTP 526) did not answer on 2026-10-31; API, demo and MCP claims are team statements, untested.

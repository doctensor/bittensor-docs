What it is

Affine pays miners for improving one shared language model that reasons through math-style tasks. About every 35 minutes the team trains on one miner's uploaded batch, tests the result on held-out tasks, and pays that miner only if the model improved.

How it works

Miners

No mining client any more: a hotkey uploads one JSON file of prompts, its own outputs and rewards (up to 125 prompts, 1,000 rollouts). Hotkeys queue by registration and get one turn, ever; since 2026-11-05 a hotkey with no valid file after twice its expected wait drops to the back. The team trains one step on the file and tests it on held-out tasks. 222 hotkeys still wait.

Validators

Only the owner's validator sets weights (one permit, UID 0). A turn is green if the gain on held-out tasks is positive, its z-score (gain relative to noise) is above 1.00 and under 33% of answers hit the 65,536-token cap. The z bar was relaxed for epochs 513 to 552 and is flat again from 553.

Incentive

Weight is split equally across the last up to 10 green hotkeys still registered; the rest burns to UID 0. Since 2026-11-03 there is no gain multiplier: each payee gets 10.0%. The chain follows the payee list with a lag of hours: on 2026-11-06 the 10 earners matched the payee list exactly (a day earlier two new greens were still unpaid).

Roles and requirements

Miner Medium barrier

Uploads one batch file; paid only if its single turn passes the held-out test.

  • A local simulator tests a file before upload; green heads' fp32 masters (about 36 GB) allow an exact local step (repo).
  • One turn per registration, ever. An invalid file is skipped, not charged; 22 of 452 stored files were invalid on 2026-11-06.

Validator High barrier

Sets the weights; in practice only the owner's validator does.

  • Trainer, gate, grader and payee code are public, plus a weight-submission module; the link from the payee file to it is not shown. The secret seed and prior table are private.

Getting started

  1. Read the current guide (affine.io llms.txt) and the miner kit README.
  2. Register a hotkey with the burn (about 1.8 TAO on 2026-11-06), then activate it with the repo's command.
  3. Build one batch file in the published format; pre-check it with the local simulator.
  4. Upload it and confirm 'valid' in the status file.

Caveats

  • Green counts are snapshots: rules changed almost daily, and 28 greens in 195 rounds since epoch 600 is a small sample.
  • The payee-file-to-weight step is not in public code; the pay rule is the team's statement, which the chain matches with a lag of hours.
  • Team posts after 2026-11-01 22:00 UTC were not read (archive down); repo commit messages carry the owner's later decisions.

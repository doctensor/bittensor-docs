What it is

Subnet 87, run by Provenonce with Bitstarter.ai as partner, is built around what the team calls Proof of Assurance: checking how autonomous (AI agent) work was done against a declared contract for how it was supposed to be done. A miner receives a case with permitted evidence and returns one verdict: findings, no material deviation, or an abstention for lack of evidence. Validators keep hidden cases whose truth comes from private reference executors and score the answers. The public runs so far are on testnet with team-operated miners and are described by the team as conformance checks, not a competition between outside miners.

How it works

Miners

Per the repo, each assignment is one of two classes: an approval-applicability check (was an approval carried past a changed governing condition?) or a release-workflow check (does a release trace break its grammar?). The miner returns one Differential: either a list of findings (each with a code, severity, evidence references and optional confidence), a no-material-deviation answer, or an insufficient-evidence abstention. Release v0.1.0 (2026-10-09) ships a miner launcher called sn87-miner, a miner guide and a public verifier. Native Windows is unsupported; WSL2 works.

Validators

Validators issue hidden cases and score each response with one scorer. A failed integrity check or schema failure gives zero and counts the response as invalid. Otherwise the score is a weighted geometric mean of detection (weight 0.60: severity-weighted precision and recall, abstention scores 0), evidence (0.25: full credit only if every required reference is cited) and calibration (0.15: Brier-style on stated confidence). A window counts only if the miner was assigned enough cases (12 for the approval profile, 40 for the release profile) and at most 10 percent of responses were invalid or missing. Truth for hidden cases comes from private reference executors. Public parts are the scorer, wire contract, evidence bundle, signed transport, a staging validator, and truth for 75 public fixture cases.

Incentive

Per method, a preference value is the square of how far the window estimate exceeds 0.60 (zero if it does not), normalised into weights; if every value is zero, no weights are submitted. The whitepaper also defines rule score, utility, robustness and efficiency terms, which are inactive in the code. Two alternative scoring profiles (one pays a correct abstention) are committed but not on any weight path. On testnet, weights are submitted in plain mode with commit-reveal off; commit-reveal exists only as code tested against a fake chain. On testnet 582 (read 2026-10-21) the single validator permit holder had set weights about 41 minutes earlier, to two uids, and incentive was split equally between those two. The repo says every miner in the attested runs is operated by Provenonce and every evidence bundle is marked conformance-only.

Getting started

  1. Clone provenonce-ai/sn87-provenonce-public and read the README and miner guide (use Linux or WSL2; native Windows is unsupported).
  2. Run the public verifier. The team says it needs no wallet or account; expect an overall UNVERIFIED because scoring truth is private. This page did not re-run it.
  3. Run the sn87-miner launcher locally first; the FAQ asks people to report where it breaks.
  4. Outside miners enter through the shadow cohort on testnet 582: results are published but never enter a weight row. The criteria are proposed and the allowlist was empty on 2026-10-21.
  5. Questions go to the team Telegram group; the team says it collects them on Wednesdays and posts answers on Fridays. No path to register as a rewarded miner on mainnet 87 is documented.

Caveats

  • The mechanism runs on testnet. Mainnet netuid 87 is registered (about 295 days before 2026-10-21, identity name Provenonce) with 256 of 256 uids filled, but all 11 validator permit holders put 100 percent of their weight on uid 0, which matches the owner hotkey and coldkey (own check, mainnet blocks 9334320 to 9334331). Four of those validators had not set weights for more than two tempos. No miner is rewarded on mainnet.
  • Testnet rows show weights to two uids only. Which scoring method sits behind each uid is a private record that cannot be verified; the repo says all miners are team-operated and every bundle is marked conformance-only. A matched baseline ties the reference methods, and the repo keeps that null result.
  • Scoring truth comes from private reference executors, so the verifier reports scoring as UNVERIFIED by design. Chain and integrity checks pass per the README, but this page did not re-run the verifier.
  • Sources disagree on First Light: chat says 16 sealed cases, while the repo's limitations file says 12 assignments per method (the profile minimum). The difference was not reconciled.
  • The whitepaper's own economics section calls its parameters hypotheses to be tested. Only the HTML v0.7.2 was skimmed; the PDF was not read. Several defined terms (rule score, utility, robustness, efficiency) are inactive in code.
  • Plan statements in chat (re-routing Provenonce's enterprise workflow through SN87, an open oracle marketplace) have no code in the repo. The July plan for repo and testnet slipped: First Light was 2026-09-28 and the repo went public on 2026-10-06.
  • Shadow-cohort criteria are marked as proposed and awaiting approval. One outside application issue opened on 2026-10-09 had no comments on 2026-10-21. Whether any outside miner has ever been scored on testnet 582 is not shown.
  • Who operates the mainnet validator now is unknown. The channel also discusses funding and token stakes; this page makes no price, emission or funding claims, and the team's FAQ says its materials make no financial claims.

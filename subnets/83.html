What it is

CliqueAI asks miners to find large cliques in random graphs of roughly 300 to 900 vertices. Validators fetch each graph from a team-run service, send it to a random subset of miners under a 6 to 30 second limit, and score each answer on whether it is a valid maximal clique, how large it is compared with other answers, and how unique it is. Scores feed a slow moving average that is reshaped into on-chain weights. The code is open on GitHub, but the graph supply is a closed team service.

How it works

Miners

Run a server that receives a graph and returns a set of vertices forming a clique. The reference miner uses a standard NetworkX solver, with an optional graph-neural-network solver included. The repo lists 4 CPU cores as the minimum and no required GPU. Miners do not choose problems; validators decide who is queried.

Validators

Each round a validator picks one of four graph sizes at random (about 300, 500, 700 or 900 vertices, difficulty 0.7 to 1.0), requests a graph from the team's endpoint, relabels its vertices, and queries each eligible miner independently with the same probability. An answer counts only if it is a clique that cannot be extended. The score is normalised optimality times (1 plus difficulty) plus normalised uniqueness, where uniqueness is one divided by the number of miners that returned exactly the same vertex set. Each miner's rating is a debiased moving average with alpha 0.01, updated only when it was queried.

Incentive

Validators normalise ratings, apply a sigmoid centred on the median non-zero rating, then a power transform tuned so the top half of miners hold about 80 percent of the weight. Nothing is routed to UID 0 by validator code. The docs describe the scoring but not this reshaping step. Miner selection was stake-weighted until about 2026-04-25 to 2026-04-29 and has been equal-probability since.

Getting started

  1. Clone the GitHub repo and read docs/mechanism.md, keeping in mind that it lags the code (it lists three problem sizes and omits the weight reshaping).
  2. Start a miner with ./start_miner.sh, passing your wallet name and hotkey, --netuid 83, --subtensor.network finney and your public axon IP and port.
  3. Replace the default NetworkX solver with your own; the file miner.py shows where, and test_algorithm.py is a local check.
  4. Validators use ./start_validator.sh with the same style of flags and need to reach the team's graph service.
  5. If v0.0.18 is merged, miners must serve the new sealed-graph request type to receive scored challenges; check the repo before registering.
  6. Before spending registration fees, compare the current on-chain incentive distribution with your expected rank (see caveats).

Caveats

  • Chain data on 2026-10-21 matches the concentration figures quoted in chat: six coldkeys hold 232 of 256 UIDs and about all incentive. The chain does not show who controls those coldkeys, so the self-mining and single-operator claims made by miners are not verified here, and the team has denied them.
  • Chain weights are validator opinions, not payouts, and the emission shares above are last-epoch values from one snapshot.
  • Every validator draws its graphs from the same team-run HTTP service (closed backend), and validators serve an endpoint that returns their saved ratings to the subnet owner's signature. The repo does not show how, or whether, either is used beyond that.
  • Seven of the eight permit holders share the same top target UID. Whether that reflects independent scoring is untested.
  • The docs lag the code in at least two places: problem tiers (docs 3 tiers, code 4) and the weight reshaping step.
  • Whether any validator runs the unmerged v0.0.18 branch, and whether scores were reset, is unknown.
  • The Weights & Biases project redirected to another host on 2026-10-21 and its contents were not read; miners reported it stale in September. The frontend dashboard promised in 2025 was not found and miners still ask for one.
  • Moderators told miners not to ping them about subnet-specific problems, so chat is the team and miners talking, not neutral review.

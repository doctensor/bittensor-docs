What it is

Safeguard is meant to be a market for AI safety testing. Miners run adversarial agents that probe a target AI service through a relay; validators audit the conversations, and other subnets could use the safety score to scale their own rewards. It exists only on testnet.

How it works

Miners

Miners run a probe agent and commit its address to chain. Each task names a target relay and one safety concern. The miner holds a multi-turn adversarial conversation with the target through the validator's relay, so every turn carries a provenance commitment, and returns the transcript with its own severity estimate. People can also review hard cases the validator routes to them.

Validators

The validator (a Django app meant to replace an older validator.py) finds miners from chain commitments, sends probes to registered targets and checks each transcript's provenance; without valid relay commitments the score is zero. It audits with an optional HarmBench classifier (off by default), a lighter classifier and an LLM judge, and routes big disagreements with the miner's claim to human review.

Incentive

Per probe: the audit score (at least 0.05), plus up to 0.1 from the miner's own claim, plus up to 0.15 for matched detection cues, capped at 1. Contributions add up per miner each tempo (the 360-block reward cycle) and weights follow in proportion; if nobody earned anything, all weight goes to the owner UID, which burns it. A second track splits weight equally among human-review miners. On testnet no neuron has incentive (2026-10-31).

Roles and requirements

Miner Low barrier

Runs an attacker agent that probes a target AI service through the validator's relay and reports a transcript with a severity estimate.

  • Reference miner (separate safeguard-miner repo): a FastAPI server on port 8090; without the Chutes key its prober and scorer return nothing.
  • Human review (HITL_ENABLED, on by default) queues validator-routed cases at /ui/hitl; the dashboard is open unless an admin password is set.
  • No licence file in the miner repo (the validator repo is MIT).

Validator Low barrier

Dispatches probes through registered target relays, audits each transcript in tiers and sets miner weights once per tempo.

  • Nine neurons hold validator permits out of 64 slots (2026-10-31); setup is register, then stake, with btcli.
  • It needs a registered target relay to probe; the only target described is the team's own demo.
  • The README says an earlier validator crash went unnoticed for hours on testnet and a rival hotkey could have captured most emissions (undated).

Getting started

  1. Create a wallet and register a hotkey on testnet netuid 444 with btcli (--network test).
  2. Get a Chutes API key; the miner and the validator both use it for attacker and judge models.
  3. Miner: clone safeguard-miner, pip install -e ., fill .env from env.example (key, wallet, network test, netuid 444), run python miner.py; its address must be reachable.
  4. Validator: in the Safeguard-Subnet repo run bash run_validator.sh (defaults to testnet 444); it also starts an API on port 9090.

Caveats

  • Testnet only: no mainnet economics are described and testnet TAO has no market value.
  • All 9 testnet neurons hold validator permits but none earns; every weight stamp is 26+ days old, most about 205 (2026-10-31). A stamp can be a registration time, so no validator is proven to have run lately.
  • Whether any testnet miner or validator still runs is unknown, and the team has not said the project stopped.
  • The repo holds two validators with different scoring (legacy validator.py and the Django one); which one testnet used is unknown, and the weight vectors were not read.
  • The README links DESIGN.md, a whitepaper and a demo-client folder that are not in the repo, so the design rationale and the client payment model (future work) cannot be read.
  • The site's probe counts are undated team figures about its own demo targets, labelled research outputs, not a certification. The site answers over plain HTTP only.

What it is

GPUForge describes itself as a proposed subnet for verifiable GPU training. A publisher signs an immutable training job, miners run it on NVIDIA H100 hardware inside a sandbox, and validators score only work they can verify. At the time of research the public code is a protocol and verification library, not a running miner or validator, and the team labels the project pre-alpha.

How it works

Miners

Intended design: report H100 capabilities, supply hardware-backed attestation evidence where supported, accept a short-lived lease, run the pinned training container in an isolated environment, and return signed results, checkpoint commitments and timing evidence. There is no supported miner release and no installation guide yet.

Validators

Intended design: issue fresh challenges, check attestation, job identity, correctness probes, freshness and throughput, and turn verified results into normalized weights. The repository contains verification libraries but no validator program and no code that sets weights on chain was found.

Incentive

Planned rule is to score verified work rather than claimed hardware: missing, stale or inconsistent evidence earns nothing. The team's website says final scoring rules are still being defined, so the reward formula is not published.

Getting started

  1. There is no supported way to mine or validate yet; the README says operating instructions will be added only after the protocol, sandbox, adversarial tests and testnet criteria are met.
  2. Developers can read the README and run the offline configuration checks and unit tests described there, using local development configs that contain no credentials.
  3. Follow the repository and the team's chat updates for a release announcement.

Caveats

  • Nothing here describes a running network. Chain registration, emissions, validators and UIDs were not checked.
  • The repository's licence file says no licence is selected and all rights are reserved, so the code is viewable but not licensed for use or redistribution.
  • Capability reports are self-reported by design; hardware attestation, sandboxing and correctness checks exist as library code that the README says are not approved for untrusted workloads.
  • No team answers were found for the roadmap, the reason GPU training verification matters, or timing questions asked in chat after 2026-09-27.
  • The channel also contains unverified personal claims about the project's owner; these are not repeated here.

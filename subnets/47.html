What it is

GPUForge is a proposed subnet for verifiable GPU training: a publisher signs a training job, miners run it on H100 GPUs in a sandbox, and validators score only work they can verify. The public code is a pre-alpha library, not a running miner or validator. Yet netuid 47 has emitted since 2026-01-17, changed hands twice according to chat, and one uid collects all the miner rewards.

How it works

Miners

Intended design: report H100 capabilities, supply hardware attestation where supported, run a signed training job in an isolated sandbox, and return signed results and timing. No miner release exists. On chain, uid 149 (registered 2026-09-13) takes all incentive, is not linked to the owner's keys and has never set weights; its software is not known.

Validators

Intended design: issue challenges, check attestation, correctness and throughput, then turn verified results into weights. The repo has verification libraries but no validator program and no weight-setting code. On chain, 11 uids hold validator permits and 10 have set weights; 7 of them give uid 149 their top weight.

Incentive

Planned rule: score verified work only; the site says final scoring rules are still being defined. Chain on 2026-10-30: about 5,888 alpha a day is emitted; uid 149 gets 50%, the owner's uid 0 gets 33% (mostly validator dividends). These are recorded payouts, not proof of work done.

Getting started

  1. No supported way to mine or validate yet; the README says instructions come after the protocol, sandbox and testnet criteria are met.
  2. Registering a uid on netuid 47 costs 0.05 TAO (2026-10-30), but nothing published says what to run, so a registered uid is not a supported miner.
  3. Developers can read the README and run its offline configuration checks and unit tests; the local configs hold no credentials.
  4. Follow the repository and the team's chat for a release announcement.

Caveats

  • Nothing the team published describes a running GPUForge network. What the 159 registered uids run is not known.
  • The two handovers come from chat in earlier occupants' channels only; no owner-key change was dated on chain, and one would not by itself prove a sale.
  • The stored emission split gives miners 69.4%, but uid 149 received 50% of last-epoch emission; the gap is not explained.
  • Capability reports are self-reported by design; the README says the sandbox and attestation code is not approved for untrusted workloads.
  • No team posts after 2026-09-30; roadmap and timing questions went unanswered.

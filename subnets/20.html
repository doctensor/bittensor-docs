What it is

Witness is a video-understanding subnet. Miners submit full model weights, one immutable model per hotkey, and validators run every contender on the same private random audio-visual clips, scoring its timestamped claims about what is seen, said, written on screen and heard. The best model becomes the 'king' and, per the project's docs and website, receives all of the validator weight with nothing burned. Before a first king exists, all weight is burned. The mechanism described here is the 'mainnet v2' design the owner announced on 2026-09-28.

How it works

Miners

A miner prepares a package of full weights, config and tokenizer files in one of three supported architectures (salmonn2-pro, qwen2.5-omni, qwen3-omni; package caps of 24 GB, 24 GB and 44 GB), runs a small CPU model server and publishes an on-chain commitment of the package hashes (a wm2 record). The first valid commitment permanently reserves that hotkey, so one hotkey means one model for good. Evaluators download the weights over authenticated, pinned TLS and run them with their own loaders, so the miner needs no inference service or GPU to serve. The docs say there is no Witness challenge fee, though normal registration and transaction costs apply. The queue alternates between coldkeys, so registering more hotkeys does not jump the line. On 2026-10-23 the chain held 41 such model commitments, the newest from 2026-10-13.

Validators

Evaluating validators need a GPU, ffmpeg and labeling and judging API credentials; a CPU 'follower' is the default and replays finalized chain records. Every two subnet epochs (one window, 720 blocks, about 2.4 hours), each evaluator privately draws 10 videos from a public 1,000-entry catalogue (5 in windows before 12) and cuts 2 random 10 to 30 second clips from each. The king and every challenger admitted to that window answer the same clips, which are scored against two independent reference passes. Each result is published on chain as a compact wr2 record (window, miner uid, quality, reward, and the king's quality and reward on the same clips) before weights are decided. The docs say validators holding at least 100,000 SN20 alpha and a validator permit are the only ones miners serve weights to; that is a download gate, not a consensus threshold.

Incentive

Per clip, reward = quality x (0.9 + 0.1 x speed), where quality is an F1-style score of supported events against the references and speed is 1 minus elapsed time over the deadline. A video is the mean of its clips and an evaluation the mean of its videos. At window close each permitted evaluator counts in proportion to its total chain stake. A challenger becomes king if its stake-averaged quality is above 0.05 and its stake-averaged reward lead over the current king is above 0.02; the largest lead wins, and partial early-stop results can block a crown but never grant one. The king receives 100% of each validator's weight. Zero burn applies from window 16 (2026-09-30); in earlier windows the code burned 70% to the owner hotkey and paid the king 30%, which the chain showed on 2026-09-29 as a 74/26 split. With no king, weight goes to the owner hotkey, whose incentive is burned (the subnet's recycle-or-burn setting reads Burn); an operator can force that with a BURN_ALL setting. On 2026-10-23 the emission split read 18% owner, 41% validators, 41% miners, with all miner incentive on one uid (94). The README states that the reference labels and sampling secrets are private.

Getting started

  1. Before spending TAO or GPU time, confirm the contest is being scored: on 2026-10-23 the newest on-chain result record was from 2026-10-06, the crown had not changed since 2026-10-03, the dashboard returned 503 and the owner had not posted since 2026-10-02. A new submission may not be evaluated. Read the 2026-10-07 and later chat and the caveats below first.
  2. Read docs/miner.md and docs/launch.md in the repository. Use Python 3.11 or newer, install the package in a repo-local virtual environment and run the tests, as the README shows.
  3. Prepare one full-weights package in a supported architecture (qwen2.5-omni, qwen3-omni or salmonn2-pro) with the miner tool's prepare command. It hashes the package and creates a private TLS key and certificate; keep that state directory, because the fingerprints are permanent.
  4. Serve the package from a stable, publicly routable address on a registered hotkey, then publish the wm2 commitment with the miner tool's commit command. The first valid commitment reserves the hotkey for good.
  5. Keep the model server reachable across windows: each evaluator allows at most 15 minutes of active download per model, and reaching that limit drops the submission from that evaluator's queue without scoring it.
  6. To validate, plan for a GPU, ffmpeg and labeling and judging API credentials, 100,000 SN20 alpha and a validator permit; running as a follower needs none of the GPU or API parts. Do not send weights until you have read the activation checklist.

Caveats

  • What the chain shows, read on 2026-10-23 at blocks 9343888 to 9343927 and at sampled earlier blocks: one paid uid (94), set by 7 of 8 weight-setters, owner emission share 18% and no burn at any of 23 sampled blocks since 2026-09-30. Weights are validators' opinions, incentive trails them by up to two tempos, and samples up to 5.5 days apart cannot rule out brief changes. Who stands behind uid 94 or the earlier kings is not published here. Uid 94 is neither the owner's hotkey nor its coldkey, but that does not show who else controls it; it holds a validator permit but has set no weights.
  • No result has been published since 2026-10-06. The chain keeps only each hotkey's latest commitment, so this shows the newest record per hotkey, not the full history: the only result record present is from the owner's validator hotkey (window 73), and no other validator hotkey holds any commitment. Whether evaluation is running unpublished, paused or stopped is unknown. The docs say consensus uses only finalized chain data, so unpublished results cannot change the crown, and the validators that follow the chain keep setting weights for the last crowned model.
  • By design the crown follows the stake-weighted mean of the results that evaluators publish, the code counts only evaluators that published a result for that challenger, and the docs describe no quorum. On 2026-10-23 the only evaluator hotkey with a result record on chain was the owner's own, which also held about 63% of the permit holders' total stake (73% counting subnet alpha only), so the crown rests on its results alone. That is a property of the design, not evidence of misbehaviour.
  • The 2026-10-07 allegation is unproven. What was checked: the commits it cites exist, the same account wrote them and main, they sit on a deleted branch called 'self', and they contain evaluator code and comments describing an operator-side boost for chosen miners that would not show up in reports or policy hashes, with an environment block meant to switch it on. What was not checked: whether that code ever ran in production, the statistical tests on published reports, and the claimed links between miners. No public repository evidence shows the code was deployed, and none shows it was not. The owner denied self-mining on 2026-09-27, before those commits existed, and on 2026-10-02 said the rules apply equally to everyone; no reply to the 2026-10-07 post appears in the channel archive.
  • Scores cannot be recomputed from public material. The README says reference labels and sampling secrets are private, and results come from evaluator operators using their own API credentials. The dashboard is stated to be a display of validator data, not a consensus source, and it has been unreachable since at least 2026-10-15.
  • The docs say the three architectures are implemented loader formats, not a claim that each has passed mainnet GPU qualification. The owner said on 2026-09-29 that any of the three can be used.
  • The docs say there is no challenge fee, but one miner said on 2026-10-07 that they had paid about 0.2 TAO across five submissions. The chain's registration burn is 0.2 TAO, so the figure is consistent with a registration cost; this is not confirmed.
  • Chat before 2026-09-28 mostly describes an earlier design that the owner replaced; it is not documented here. The public repository showed no commit newer than 2026-10-02 on 2026-10-23, so any change to what validators run would not be visible in it.

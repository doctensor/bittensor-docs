What it is

RedTeam is a competition subnet in which miners write detection code for security problems and ship it as Docker images. The code is meant to be usable in real products. Challenges are published by the team, each with its own scoring server and rules. Two challenges are active as of 2026-10-22: one classifies which Chrome extensions are running (BEX Tracer v1), the other detects which anti-detect browser drives a web session (ADA v3).

How it works

Miners

A miner writes JavaScript for the active challenge, packages it in a Docker image, and commits the image digest. BEX Tracer wants one file per extension group that returns which of 89 named extensions are present. ADA v3 wants one file per target (AdsPower, Dolphin Anty, GoLogin, Multilogin, Octo Browser and a headless detector) that must stay silent on human sessions. Each miner may commit once per challenge per 24 hours; the newest commit replaces the earlier one.

Validators

Submissions go through a 24-hour cooldown with an encrypted commit and later reveal, then lint and obfuscation checks, then a comparison against other submissions for copying. Scoring runs on team-operated infrastructure, and validators pull accepted results once a day at 14:00 UTC and set weights. A submission must be scored and accepted before that time to count that day. The team states this is the mechanism; only the pull behaviour was checked against the docs, not independently in validator code.

Incentive

A submission is accepted if its score reaches the challenge's minimum (0.8 for BEX Tracer and 0.9 for ADA v3 in the repo config) and its similarity to others stays within limits. An accepted score holds for 10 days, decays to zero by day 15, and is passed through a softmax with temperature 0.2 over each miner's best commit. Each challenge's result is multiplied by its weight (0.6 for BEX Tracer and 0.4 for ADA v3 in the repo config). If a challenge has no scores, its weight goes to the other. Miners sharing an IP, Docker Hub account or coldkey are counted as one entity, with only the best score kept. On chain at block 9338192 (2026-10-22), ten of eleven validator permit holders set weights and all ten put the same single miner first at about 60 percent, which fits one accepted BEX entry taking the whole 0.6 share; roughly 124 other miners share the remaining 38 percent or so.

Getting started

  1. Read the docs page for the active challenge and the lifecycle and reveal-interval pages for the 24-hour commit rule.
  2. Clone the challenge repo and run its local test harness against your detection code.
  3. Package the code as a Docker image and push it to a Docker Hub account; one account is used for all your images.
  4. Use the miner repo (version 3.0.5 or later for the cooldown) to commit the digest, then reveal after the interval.
  5. Watch the dashboard for the status and logs of your submission and check that it is accepted before 14:00 UTC.

Caveats

  • The weights (0.6 and 0.4) and minimum scores come from the repo config (main and dev agree, last changed 2026-10-13). The chain on 2026-10-22 fits 0.6 for BEX Tracer but cannot show minimum scores. The BEX minimum is 0.85 in launch material and 0.8 in the repo; miners confirmed the change on 2026-10-21 and no explanation was found.
  • Chain figures are one snapshot (block 9338192, about 2026-10-22 09:41 UTC). The top miner holds about 0.5 points more than 60 percent, which is not explained, and one validator permit holder's weights are millions of blocks old. Numbers move with the daily 14:00 UTC pull and the decay.
  • The BEX bypass dispute that began on 2026-10-20 is mostly miners' claims. The team said the disputed entry gets full BEX emission; no re-scoring or rule change was announced through 2026-10-22. One miner says the bypass is now blocked, and no team post confirms that.
  • Statements that BEX or the subnet will end soon came from an account impersonating the owner on 2026-10-20 and are not team statements.
  • ADA v3's own guide contradicts itself on the split between browser and headless scoring. The code applies gates (a human or headless misjudgement scores zero) and then weights five browsers equally; the page follows the code.
  • ADA session counts per submission come from team statements (23) and were not checked in production. The Multilogin score cap is reported by miners and attributed to timeouts by the team.
  • Scoring uses a team-operated scoring server, so results depend on the team's infrastructure; the dashboard's validation reason text may be wrong. The team's 2026-10-05 plan to replace ADA v3 has no visible follow-up, and no date for the next challenge was given. Hotkey swaps have broken commit tracking, and the team advises against them.
  • Owner statements about token buyback and exchange accounts exist in chat; they were not verified and are not covered here.
  • Chat read: roughly 2026-09-20 to 2026-10-22. Older history was not read. The docs still list retired challenges, and one example command uses a stale challenge name.

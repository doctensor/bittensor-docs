What it is

UR (SN25) is a decentralized privacy network built from residential internet connections. Independent providers share their home bandwidth as entry and exit points, and user traffic is routed over several hops with layered encryption. The subnet pays providers for staying reachable and for carrying traffic for a network operator. The first and, at launch, only operator is BringYour, which runs the ur.io VPN apps and says it already has 100,000+ providers to move onto the subnet. The slot was previously used by Mainframe; UR took over the channel on 2026-08-18.

How it works

Miners

A miner runs the 'provider' program on a Linux or macOS machine with one stable public IP, joins an operator's pool with that operator's account, and registers a signed payout wallet (a Bittensor coldkey). Most providers need no subnet registration or burn: the operator holds one shared on-chain pool slot for all of them, and each provider claims a proof-backed share from a settlement contract on Bittensor's EVM. Up to about 200 of the largest fleets, ranked by how many distinct routable exit address blocks they serve, can instead bind their own on-chain slot and be paid by the chain directly; at block 9,343,602 (2026-10-23) no such fleet slot earned incentive. Claiming needs an EVM key funded with gas, which can be a separate relayer.

Validators

A validator walks server-assigned chains of providers to show they can carry traffic live, turns the results into per-provider liveness and latency statistics, and submits weights each tempo under commit-reveal. A pool's weight is the usage its operator reports times a quality score clamped to 0.75-1.0; a head-tier fleet is scored on how many distinct routable IPv4 /29 or IPv6 /48 blocks it served. At launch one validator does the measuring: the subnet owner's own, scoring UR's own pool, and the project's validator document says this means nobody independent cross-checks the scoring. On chain at block 9,343,602, 17 slots held validator permits and 12 had set weights; 10 of those, including the team's validator, set three-target weights with the same 45% top target, and the team's validator took about half of validator dividends. Whether the others are independent of the team is unknown.

Incentive

The normal Bittensor split applies, and the chain confirms it at block 9,343,602: 18% owner, 41% miners, 41% validators, no burn. Of the miner share, the launch policy gives providers 10% (called momentum) and sends the other 90% to a 2-of-3 multisig branded the Network Capacity Reserve, which the team says will pay for provider capacity ahead of demand against verified commitments; on chain the incentive is 45% and 45% to two reserve slots and 10% to the operator's pool slot, and the validator code accepts only this 1/10 and 9/10 split. A governance value (theta, 0.3 at launch) divides the providers' 10% between top fleets (30%) and the operator pool (70%). Operators are meant to deposit alpha in proportion to their usage, but every deposit rate is 0 in the initial period, so each pool counts as equal demand. Pools settle in 7-day epochs (50,400 blocks): the operator commits a payout list and providers claim from the vault with a proof roughly two days after the epoch closes. Version 1 settlement pays only providers the validator measured, about 1,500 per epoch; settlement v2, planned from epoch 3 (about 2026-10-23), pays by completed usage alone into one non-expiring account per payout wallet. So far epoch 1 captured about 3,482 alpha for the pool, but no payout root was committed, so the epoch was finalized at block 9,312,031 (about 2026-10-18) with that amount carried, and no claim event exists on the contracts through block 9,343,647.

Getting started

  1. Read the miner guide first (it was last updated 2026-10-14 and covers Linux or macOS). Today ur.xyz/operators.yml lists a single operator, BringYour (api.bringyour.com), so that is the pool a new provider joins.
  2. Install the newest provider release from the urnetwork/build releases page (releases appear daily; v2026.10.22 was the newest on 2026-10-23), with one stable public exit IP per provider. The timeline says the old miner is deprioritised from 2026-10-21.
  3. Authenticate with the operator account (provider auth), then start the provider once with --allow-client-registration. Note the printed client id and back up the state directory (~/.urnetwork). The repo's main branch (2026-10-22) also has a guided 'provider setup' command and 'provider status' / 'provider doctor'; the guide did not describe them yet, so check the help of the release you installed.
  4. Register a payout wallet: request a statement with provider wallet challenge <coldkey>, sign it with the coldkey and submit it with provider wallet set. Do this before the epoch in which you want to earn; default consent covers 65,536 epochs.
  5. Keep the provider running (the guide has a systemd example). After an epoch closes and its payout root finalizes, claim with provider claim --epoch N --rpc <EVM RPC>; a funded EVM key pays gas. No claim had happened on chain by 2026-10-23, and the timeline lists the first settlement v2 claims for no earlier than 2026-11-01.
  6. Validators: the guide says the current mainnet validator needs a provisioned production configuration and approvals, not a self-service setup, so ask the team in the channel before registering a hotkey.

Caveats

  • Chain state was read at block 9,343,602 (about 2026-10-23 03:40 UTC) and the settlement contracts up to block 9,343,647; both change quickly. Weights are validator opinions, not payouts, and the read did not map slots to people.
  • No provider payout has happened on chain yet: epoch 1 had no payout root and was finalized with its 3,482 alpha carried (block 9,312,031), and the contracts show no claims. Epoch 2 closes about 2026-10-23 18:09 UTC; its outcome was not known when this was written.
  • The 3,482 alpha captured for epoch 1 was not reconciled with the 10% provider share (about 295 alpha a day by the team's own figures); the cause was not checked.
  • Launch runs one operator and one measuring validator, both UR's. The validator document states that the independence assumption behind its scoring is not met at launch. Other validator slots set similarly shaped weights on chain; whether they are independent of the team was not checked.
  • The team and litepaper call mining and validating permissionless, but the validator guide (updated 2026-10-07) says mainnet bootstrap is provisioned by the deployment rather than self-service, and a validator steers only if it holds more than half of validator stake.
  • Dates are in flux. The team's launch timeline was last changed on 2026-10-15 and still lists steps from 2026-10-17 to 2026-10-21 as planned when read on 2026-10-23. Chat on 2026-10-13 said the v2 contract was live while the timeline listed it as planned; the v2 contracts were not located on chain.
  • No head-tier fleet slot earns incentive as of block 9,343,602; fleet binding only became possible after the commitment oracle was built on 2026-10-14.
  • Privacy claims are the team's. UR's own threat model says there is no independent audit of the protocol, connect engine or operator server code and that no cover traffic or padding is shipped; it was written against code of 2026-09-17. The Cure53 audit is only described as scheduled for November.
  • The routing check measures reachability to one known destination and cannot prove providers relay real user traffic honestly (validator document section 1).
  • All operator deposit rates are 0 and the team said on 2026-10-16 that the subnet was not yet earning revenue, so the usage-to-alpha demand loop described in the design is not running yet.
  • 90% of the miner share goes to the reserve multisig. The team says it is not used for team or operating costs and that allocations will be published; the reserve page showed none committed on 2026-10-21 and 2026-10-23.
  • The validator's runtime compatibility check admits specific reviewed runtime versions (481 and 482 in a repo document of 2026-10-22, which also says the owner waived full qualification of 482), while the chain reported runtime 483 on 2026-10-23. Whether the team's validator is affected was not checked.
  • The repo README describes the steady-state design (deposits, 41% to miners) and itself notes that launch differs. The repo has had an MPL-2.0 LICENSE file since 2026-10-21.

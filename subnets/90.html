What it is

KubeTEE describes itself as a decentralized AI factory: miners operate Kubernetes clusters of GPUs with hardware confidential computing (Intel TDX, NVIDIA confidential-computing GPUs, Kata and Confidential Containers) that are meant to serve AI workloads such as inference, batch jobs and agents. The README says it is not itself an inference subnet; models are exposed through a gateway run by the team and through an idle-capacity channel on SN28. Today the validator checks that a miner's cluster is ready and pays by hardware, not by the quality of work served.

How it works

Miners

Operate a Rancher-managed RKE2 cluster of GPU nodes. During Early Access (Phase 0) registration is reviewed by hand: the team labels the cluster with the miner's hotkey and deploys the software stack through GitOps. A team post on 2026-10-19 set the Phase 1 rules: a minimum of 3 nodes of one GPU type (previously 7), 3 extra nodes for each additional GPU type in a mixed cluster, and Blackwell-class GPUs only for new clusters, with Hopper to be phased out as Blackwell comes online (target November 2026). A 10 TAO per node collateral was announced; it is not enforced during Early Access.

Validators

Validator v1 reads the Rancher inventory with GET-only calls (authenticated by signing a challenge with the validator hotkey) and gives each miner a binary readiness verdict: hotkey binding, Rancher readiness, high-availability topology, capacity, 8-GPU passthrough and a confidential runtime handler. It sets weights once per epoch. Per the README status table, TEE attestation, job metrics and health checks are not yet part of the weights. The validator runs on the operator's own machine, not inside a TEE.

Incentive

Per the code, a ready miner's earnings in USD equal a price-card rate per GPU, times GPU count, times a tenure factor, times the window length. Weight is earnings divided by the epoch's emission pool. If total earnings exceed the pool, weights are scaled down pro rata; any unused part of the pool goes to the owner UID, which the README says is recycled rather than credited to the owner. Price-card values may move only within 0.8x to 1.25x of compiled-in defaults, and a Targon (SN4) payout feed can only pull them down. On-chain at block 9334298, all 8 validators with weights point at the same two UIDs and none at UID 0.

Getting started

  1. Read the README roadmap and docs/MINER-DEPOSIT.md in the subnet repo; they separate what ships today from what is planned.
  2. Early Access is by hand-review: contact the team in the subnet's channel, since self-service onboarding is a Phase 1 item and the team calls the pace demand-driven.
  3. Plan hardware to the 2026-10-19 rules: at least 3 nodes of one GPU type, with new clusters on Blackwell-class GPUs.
  4. After approval, the team binds the cluster to your hotkey with a label and deploys the stack with Rancher Fleet.
  5. To run a validator, use the ghcr.io/kubetee-ai/kubetee-validator:v1 image and follow validator/README.md in the repo.

Caveats

  • The README contradicts itself: the scoring and incentive sections say TEE attestation is mandatory, but its own status table says scoring today reads only Rancher inventory and readiness. This page follows the status table.
  • Paid jobs, the Jobs MCP server and attestation-based scoring are Phase 1 to 3 items and are not built. No revenue or buyback plan was found; a chat question on this on 2026-10-01 had no answer in the data read.
  • README price-card figures differ from those on the live dashboard, so this page quotes no prices. Throughput numbers are the team's own claims.
  • Dashboard and chain were read once, on 2026-10-21. Chain weights are validator opinions, not payouts, and it was not checked whether all 8 validators run the owner's code.
  • The README describes the owner's staging cluster (UID 56) as part of a split company structure in which the owner-side miner operator competes under the same rules. The validator config hardcodes that UID as the owner miner.
  • Not read: kubetee.ai, the llm.kubetee.ai gateway, saygm.com and any market data. Chat is moderated against price discussion, so none is included.

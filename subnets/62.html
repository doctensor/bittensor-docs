What it is

Ridges runs short competitions in which miners submit a single Python agent file that turns a repository and problem statement into a code patch. Validators run each agent in isolated sandboxes against hidden tests and report a 0-1 score, and only agents that beat the current leader earn emissions. On 2026-10-23 three competitions were open (test generation, database query engineering, linting) and the docs also list a problem-solving niche. The team also runs Ridgeline, a task-board product for assigning engineering work to agents.

How it works

Miners

Write agent.py exposing agent_main(input) that returns a diff, test it locally with the ridges miner CLI, then pay an upload fee by burning alpha (a price floor of about $5 that rises about 15% with each purchased upload and halves every 30 minutes; leftover burn is credited to the next upload) and submit it to one competition. Uploads also need OpenRouter keys.

Validators

Agents pass Screener 1, then Screener 2, then are run by three validators, and a problem counts only if every validator marks it solved. Scoring is deterministic: the fraction of hidden tests passed, with no model judge, and miners cannot see test names or logs. An LLM pre-screening review of the source rejects hardcoding and evaluation gaming before any run. The code whitelists 15 mainnet validators; on 2026-10-23, 23 chain uids held validator permits and 14 were setting weights.

Incentive

Emissions are first split across active competitions, then divided among each competition's approved agents by a reward score. An agent qualifies only by scoring at least 3% higher than the leader, or being at least 6% cheaper at an equal or higher score (general defaults; each competition sets its own). The reward grows with how long the leader went unbeaten and decays with a 14-day half-life. These formulas match the code on the main branch (commit 801d21ed, 2026-10-13). On 2026-10-23 the public competitions API showed shares of 48% for test generation, 48% for database query engineering and 4% for linting. The platform computes one weight mapping and the validators publish it on chain: at block 9343826 the 14 weight-setting validators had identical rows over 43 miners held by 28 coldkeys, with the top miner at 17.5% and the top five at 40.5% of incentive, commit-reveal off, and a subnet emission split of 18% owner, 41% validators and 41% miners. Weights are validator opinions, not payouts. A benchmark-phase rule (an admin-opened pool where the best score wins 100 times its score as reward points, with no time bonus) is documented and exists in the repo's staging branch, but it is not in main and the live competitions API shows no phase, so it is not confirmed live.

Getting started

  1. Install the miner toolkit from the main repo (pip install -e ".[miner]" or uv sync --extra miner).
  2. Run ridges miner setup and add an inference provider key to the generated .env.miner file.
  3. Run ridges miner run-local to test agent.py against a task (this is not identical to validator execution).
  4. Read the participation rules and pre-screening guide to avoid rejection for hardcoding.
  5. Upload with ridges upload --file agent.py, choosing a competition that is open for submissions (the CLI lists them, or pass --competition with the set id).
  6. If a burn lands but the upload is not confirmed, finish it with ridges resume-upload using the quote id and payment details; quotes expire after 15 minutes.

Caveats

  • Screening thresholds and problem counts in the docs come from Competition 23 and vary per competition; current values were not found.
  • Each competition's policy (thresholds, half-life, time scale) is not published, so the values quoted here are the docs' general defaults.
  • The docs say unallocated emission share is burned, but the platform code adds it to a configured owner hotkey. No weight reached the chain's owner hotkey at the blocks read, so neither behaviour was observed, and the code does not show what the owner does with such emission.
  • The benchmark-phase mechanism is described in the docs and exists only in the staging branch; this page does not claim it is live.
  • Code was read at commit 801d21ed on main (2026-10-13) and commit c6ac68f on staging (2026-10-21). Code shows what was written, not what runs in production, and the screener and score-aggregation code was not read end to end.
  • Chain figures are a snapshot at one block and describe published validator weights, not payouts.
  • Chat is moderated against price discussion, so this page contains no market data.

What it is

ORO evaluates agents that shop on behalf of a simulated customer: searching a frozen product catalog, asking the customer about unstated needs, adapting when price or stock changes, and placing one order. Miners submit a single Python agent file. Validators run it in sandboxes against ORO Bench, a set of generated shopping tasks sealed in versioned packs, and a daily race on hidden tasks picks the top agent.

How it works

Miners

Write a synchronous agent_main(problem_data) that drives a shopping session through the tools the environment supplies. Inference runs through OpenRouter, which is the only supported provider now that the docs call Chutes retired, and you pay for it. After an agent qualifies on the public task set, it can enter the daily race. Submissions are limited by an 18-hour per-hotkey cooldown.

Validators

Validators claim work from the ORO backend, verify the sealed task pack by hash, run the agent in an isolated Docker sandbox and report receipts from a trusted runtime. A task scores 0 to 1; an order that misses any requirement scores 0, and unnecessary questions or a weaker pick reduce a passing score. Validators need a registered hotkey, enough stake weight and a dedicated CPU host.

Incentive

The top agent is the one with the best difficulty-adjusted average over its last three races, and a challenger must beat it by a margin that shrinks over time. Per the docs, the top agent takes most emissions and a small protected share goes to survivors of the latest race, with the bottom 65% of a large race eliminated. The docs say the burn rate is currently 0%, and the chain agrees: on 2026-10-21 all ten weight-setting validators gave about 96.5% of their weight to one miner uid and none to the owner uid, which is the burn slot. Validator code keeps a 75% fallback burn used only if the backend value is missing.

Recent activity

  • 2026-10-21 (Chain read at block 9334663) On chain, one non-owner miner uid held about 96.6% of incentive and 64 uids had some incentive, which fits the documented top-agent-plus-survivor-tail split with no burn.
  • 2026-10-20 (#oro) The team warned miners that incentive-mechanism changes are coming in the next few days, without details, and advised rereading the agent interface and code requirements: agents that rely on anything being static will suffer.
  • 2026-10-20 (#oro) A miner reported that all 90 tasks in race 18 were re-runs of tasks from races 13 to 17; whether this was intended was not answered clearly in chat.
  • 2026-10-17 (ORO changelog and #oro) Agents that make several tool calls together were given more time to finish the group, reducing timeouts; the same day several miners had agents auto-discarded because their inference setup still pointed at the old provider.
  • 2026-10-15 (ORO changelog) Evaluations now stop gracefully when a miner's inference credits run out, keeping rewards from completed episodes, and temporary shopper-model errors are retried.
  • 2026-10-08 (ORO changelog) New evaluations began requiring an OpenRouter account in place of Chutes for inference.

Getting started

  1. Install the SDK with pip install -U "oro-sdk[bittensor]" and create a wallet with btcli.
  2. Register your hotkey on subnet 15 (needs TAO).
  3. Clone the subnet repo, pull its Git LFS assets and copy .env.example to .env with an OpenRouter key (connect OpenRouter for evaluations too: oro inference connect).
  4. Start from src/agent/environment_agent.py and test with docker compose run test --agent-file my_agent.py.
  5. Submit the file with the oro CLI or SDK once you pass the code checks.

Caveats

  • The documented 0% burn rate is set by the backend policy and may change; the chain read on 2026-10-21 matched it, but an announced incentive-mechanism change could alter the split.
  • The team announced on 2026-10-20 that incentive changes are coming in a few days; details were not published as of 2026-10-21, so scoring and emission rules here describe the system before that change.
  • Repo guides and the SDK sample still default to Chutes for local tests, while the docs say Chutes is retired and OpenRouter is the only supported provider.
  • Qualifying thresholds and the race challenge margin are published live on the leaderboard and not fixed in the docs.
  • Miner allegations in chat about individual race tasks and about task re-runs were not verified.
  • Chain data shows weights and incentive, not payouts or intent; the task-reward code inside the sealed environment runtime was not read.

What it is

ORO tests AI agents that shop for a simulated customer: they search a catalog, ask about unstated needs and finish with one order or a decline. Miners submit one Python file; each daily race runs on a newly generated shop, so memorised answers fail.

How it works

Miners

Write one Python function, agent_main(problem_data), that reads the world's tools from the request and makes one tool call per step, ending with an order or a decline. A task scores 1 only if that finish is fully correct within the budgets.

Validators

Validators claim work from the ORO backend, verify the sealed world pack and run each agent in an isolated Docker sandbox; the world's grader marks each task 1 or 0 and scores are averaged across validators. They set weights from backend standings, so every validator submits the same vector.

Incentive

The top agent has the best difficulty-adjusted average over its last three races; a challenger must beat it by a margin that starts at 0.011 and halves every 3.5 days. The top agent gets full weight and the last race's survivors share a falling ladder. Burn is 0%, so the top uid held 95.6% of incentive on 2026-11-06.

Roles and requirements

Miner Low barrier

Builds and submits one Python shopping agent; the top agent earns most emission.

  • Only models on ORO's OpenRouter allowlist work; each run's key expires after 1 hour.
  • One Python file under 1 MB; the practice world is public. Code is published after 5 days, the top agent's at once.

Validator High barrier

Runs agents in Docker sandboxes, reports scores, sets on-chain weights.

  • Reference hosts: AWS c7g.2xlarge or c6i/c7i.2xlarge; burstable CPUs time out. First start pulls about 8 GB. The container is capped at 8 GB, no swap.
  • The backend can withhold standings from an ineligible validator; the rule is not documented (code).

Enforcement

  • Changing or deleting a run key's spend cap mid-run is cap evasion: version discarded, hotkey banned.
  • Hardcoded task identifiers get the hotkey banned; submissions are also screened for security problems and copying.
  • Fixed lookup tables of product kinds, attributes or units are rejected with a full cooldown (rule widened after 2026-11-01).

Getting started

  1. Install the SDK (pip install -U "oro-sdk[bittensor]"), create a wallet with btcli and register your hotkey on subnet 15.
  2. Clone the repo, run git lfs pull, put an OpenRouter key in .env and run oro inference connect for network runs.
  3. Start from src/agent/environment_agent.py and test with docker compose run test --agent-file my_agent.py; read tools from the request, never hard-code them.
  4. Read the code requirements page, then submit with the oro CLI or SDK.

Caveats

  • The rules are 15 days old and still widening; miners report wrongful similarity rejections; no error rate is published.
  • The world runtime, graders and backend are not public; the promised race world-seed commitment was empty for races 12 to 16.
  • Docs no longer say who pays for the shopper's model calls; an older guide, since removed, said miners did.
  • The top agent, survivor list and burn rate come from ORO's backend; validator code falls back to 75% burn if it sends none.
  • Top uid 119 shares a coldkey with 2 uids that earn 0.12% together and now holds a validator permit; the top has sat under five different coldkeys since 2026-10-31.
  • Chat after 2026-11-01 was not read (archive down); newer team posts are missing.

What it is

MANTIS pays miners for signals that help predict market moves. Miners submit encrypted prediction vectors about once a minute across a set of crypto, forex, metals and cross-asset challenges, and validators decrypt them after a delay and score each miner by how much independent predictive value the vector adds. A newer challenge, FLOW, has miners submit full Bitcoin trades (direction, size fraction, stop, two targets, horizon) and optionally post their own collateral on chain through a contract on Bittensor's EVM.

How it works

Miners

Each miner builds prediction vectors for every challenge, encrypts them (an owner-key path plus a public Drand timelock path) and uploads one file per hotkey to its own Cloudflare R2 bucket, whose URL is committed on chain. The file is replaced about every 60 seconds. For FLOW, a miner also submits four trade tuples, one per time regime (1 hour to 336 hours), and may post a bet on chain before each trade opens.

Validators

Validators sample every 5 blocks, download the payloads, and decrypt them after a maturation delay (code default one week; the owner can read them immediately). They store embedding and price rows, run walk-forward regression scoring per challenge (logistic and ElasticNet meta-models, with clone-suppression through L2 regularisation and a uniqueness penalty on the LBFGS challenges), weight challenges by fixed factors, smooth with an EMA (alpha 0.15) and set weights every 360 blocks. The price data comes from a feed published by the team to an R2 bucket.

Incentive

Per-challenge scores are combined by challenge weight (eleven prediction challenges, with breakout 5.0, funding rank 4.0, ETH 1h LBFGS 3.5 and cross-sectional rank 3.0 the largest). FLOW pays on path-adjusted, Kelly-weighted trade returns; its significance gate was removed in code on 2026-09-17, so every scoring miner shares the main FLOW pool, with a small dust share kept in the split. The code sets 45% of weight to UID 0 (burn). The settlement of FLOW collateral is run by a team-operated process that is not in the public repo.

Getting started

  1. Register a hotkey on subnet 123 (the registration cost was 0.15 TAO on 2026-10-21).
  2. Install the dependencies in MINER_GUIDE.md, including the pinned timelock wasm wrapper (the PyPI timelock package does not match live payloads).
  3. Create a Cloudflare R2 bucket and commit its public URL on chain; the object key must equal your hotkey.
  4. Generate prediction vectors for every challenge, encrypt them with generate_and_encrypt.py and upload about once a minute.
  5. To enter FLOW, follow the repo's flow_post.py steps: open a collateral slot with your hotkey and post bets before each trade opens.

Caveats

  • FLOW emission weight: the team said 25% from 2026-09-14, but the code default is 0.0 and no commit changes it. Validators could set it by environment variable, so the deployed value is not verifiable from public data.
  • The README is out of date on two points: it lists a 0.35 burn (code and chat say 0.45) and still describes the FLOW significance gate as active.
  • On chain on 2026-10-21, five validators sent about 46% of weight to UID 0 and one sent 35%, which may be a validator on the older setting. Weights are validator opinions, not payouts.
  • The price feed is team-run and has frozen twice; every challenge depends on it.
  • Detailed per-challenge scoring output is not public. Miners asking for it in chat were answered by DM.
  • Miners reported deregistration about 20 hours after registering in August; chain immunity is 5000 blocks (about 16 hours), against some miners' expectation of five days. The chat data holds no clear resolution.
  • The FLOW release paper, the on-chain contract source and the team's settlement process were not read.
  • Chat says what the team said; code at the repo says what is published, not necessarily what the team's own validator runs.

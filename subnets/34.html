What it is

BitMind ran SN34 as a detector-versus-generator contest for AI-made media. Since 2026-10-22 it is Yugos: miners train a router that picks the provider, model and effort for each request, scored on quality, cost and time by a benchmark the team hosts. The team also sells routing as an API at yugos.ai.

How it works

Miners

A miner submits a trained router (model.py, model.safetensors, models.json). It returns one model choice per turn, which must come from the trained weights; keyword rules, lookup tables and prompt edits are banned. A compliance review and a private wording check run before grading. A hotkey may submit 3 new ZIPs per 24 hours.

Validators

Validators fetch the team's signed result, check its hash and age, map champion hotkeys to UIDs and set weights. Grading, cost and time are measured in the team's hosted service.

Incentive

A challenger must beat the reigning champion on the same questions (chat 40%, math and code 35%, agentic 25%): net value, meaning extra correct answers minus extra spend and time, must clear quality gates and a bound above 0.2. The champion gets 85%, the previous one 10%, the one before 5%; one hotkey can hold two seats.

Roles and requirements

Miner Medium barrier

Trains and submits a router that picks a provider, model and effort per request.

  • Package up to 24 GiB and 4,096 files; no network or provider keys when it runs.
  • Hosted runs take hours (median 3.3 h) with no per-question results.

Validator High barrier

Relays the team's signed champion list into weights; no grading, no miner code.

  • On 2026-10-31, 5 of 7 permit holders had set weights, all topping the champion's uid.

The v2.2 contest (live)

Open since 2026-10-28; the docs call it v2.2, the dashboard pack v0.1.2.

  • Every entrant, the old champion included, runs the same 2,375 questions (1,875 public, 500 private).
  • By 2026-10-31: 106 attempts by 31 hotkeys; 86 completed, 20 rejected by the wording check, 4 promotions.
  • On 2026-10-30 a miner already holding a seat was promoted again (net value 0.86) and now holds 90%; the 2026-10-28 champion holds 10%.
  • The wording check rejects a run when rewording raises its model-choice changes by over 20 points (95% confidence).

Getting started

  1. Check the dashboard and team channel first: the v2.2 contest is live, rules change fast, and each hotkey gets 3 new ZIPs per 24 hours.
  2. Install the yugos package (Python 3.11+); start from examples/starter-router and replace its fixed choice with weight-driven routing.
  3. Train the router (its choices must survive rewording), list every allowed provider and model in models.json, and test locally with your own keys.
  4. Register a hotkey on SN34 (0.78 TAO burn on 2026-10-31), then yugos pack and yugos submit; fund the run on the linked card page.

Caveats

  • Rules change fast; check the team channel before paying for an evaluation.
  • Grading, compliance and wording checks run in the team's closed service; validators do not re-grade.
  • Dashboard spend is what miners paid, not what they earn; weights are opinions, not payouts.
  • Support is thin: stuck runs and locked escrow were reported on 2026-10-28 to 2026-10-30; the team wants questions in the channel.

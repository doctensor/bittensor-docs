What it is

Ormas, run by Heron Cove LLC, sells verified coding outcomes. A client supplies a GitHub repository, a bounded task and an automated test that defines success. Miners offer a price before work starts, deliver a result branch, and are paid only if the delivery passes the client's test; a failed delivery costs the client nothing. Miners keep their models and agent loops private.

How it works

Miners

A miner runs the open ormas-subnet software against the Ormas gateway. It sees a privacy-safe envelope for each queued task, offers a firm price or a limit (an estimate plus a hard ceiling) or declines, then clones the repository, makes the change with its own tooling, runs the task's tests and publishes the branch. Admission is by operator approval and a qualification task, and the beta is open to US-based miners only.

Validators

A validator (or, in the alpha, the Ormas-operated checker) re-runs the client's test against the delivered branch in a pinned container, checks the diff stays inside the allowed paths, and signs accept or reject. The reference validator code is in the repo. Docs and the gateway's own published statistics say verification is currently operated by Ormas and independent validator acceptance is not live.

Incentive

Per the repo docs, an accepted delivery freezes an emission target equal to its settled USD price times a published rate (2x since 2026-10-05 under rate version earned-bid-2x-v1). Weights are described as proportional to owed USD under a per-hotkey cap, with shortfalls carried forward and unearned emission sent to the owner UID. Selection among offers uses price, settlement history and delivery record. A treasury top-up in alpha is planned, not live.

Getting started

  1. Check eligibility first: the beta is open to people in the United States only, and the operator approves each miner.
  2. Sign in at ormas.ai and mint a runner key from the miner page; it is shown once, expires after 30 days and can only register until your claim cap is raised.
  3. Install the miner (curl install.sh from ormas.ai, Python 3.10 or newer) or clone the repo, then run ormas-miner login.
  4. Register with a public miner name and the task cells your worker supports, then run ormas-miner doctor.
  5. Email ops@ormas.ai for slot approval; the team says to confirm your worker setup with them before paying for SN76 registration.
  6. Complete the proof/qualification job reserved for your miner, register your hotkey with ormas-miner register-hotkey, then start taking offers.

Caveats

  • Chain weights were NOT read. The repo contains no weight-setting code, and its docs disagree: DECISIONS.md (2026-10-02 status) says chain weights are planned, while CONTRACT.md and economics.md say weights are live. The README says the weight service relays a vector computed by the gateway.
  • Acceptance is operator-run: the site, README and the gateway's public statistics say verification is run by Ormas, which also runs a miner, so independent validation is not yet in place.
  • Docs say independent Protected-tier miner onboarding has not opened, while a 2026-10-18 chat post says the first independent Protected miner slot was approved. Both are team statements.
  • The treasury top-up in alpha, and its KYC/W-8 gate, are planned only; several parameters are marked open in the docs.
  • The gateway's public network and provider statistics showed no data (insufficient data, empty provider list) as of 2026-10-19, so network activity figures are team statements only.
  • A miner reported on 2026-10-14 that the gateway rejected a failure completion from the reference skeleton (unknown_field:error); no public confirmation of a fix was found.
  • Nothing here is a price, earnings or return claim; the docs say the alpha received for a target varies with pool and TAO/USD prices.

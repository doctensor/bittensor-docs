What it is

SN45 reads a large stream of financial news and has miners produce a structured analysis of each article: sentiment per asset, entities linked to tickers, numeric claims with confidence, exact quotes, an event fingerprint and narrative tags. Validators dispatch batches, audit samples and set weights. The output feeds AlphaRidge, the team's trading-analytics product (charts, screener, alerts, AI assistant, API), which the team says is free to use for now.

How it works

Miners

A miner receives leased batches of articles over Bittensor. Under the current triage scheme it first labels each article relevant, borderline or irrelevant against a published rubric (a tradeable asset is involved, or a macro event tied to an economy) and returns a proof of reading for every article, then deep-analyzes only the relevant ones. The default miner runs spaCy, GLiNER, Flair and ReFinED entity extraction plus FinBERT sentiment on the machine, and two LLM calls through the miner's own OpenRouter key (the default model is DeepSeek V4 Flash), then embeddings. The README gives 8 GB VRAM, 16 GB RAM, 60 GB disk and 8 CPU cores as the minimum and about 44 GB of models to download. Analysis takes roughly 12 to 18 seconds per article, and CPU core count is said to set throughput.

Validators

Validators fetch articles from the team's coordination API, lease them to miners, and check a sample of each batch by re-running the pipeline themselves. The code grades each sampled article with a continuous score that is the lower of two things: how closely it matches the validator's own analysis (grounding of numbers and quotes, enum fields, extracted fields, semantics) and a reference-free faithfulness check against the article. Relevance claims are judged against the published definition, and a miner whose claims keep being found not relevant can lose whole batches. Validators keep their own points and penalties and pool them with signed epoch snapshots from the other validators before setting weights.

Incentive

Per the README and code, pay is verified volume times a reputation multiplier. Reputation is a slow moving average of graded scores; below a midpoint the multiplier collapses toward zero. Points are priced in USD, converted to a percentage of miner emission, and whatever share no verified work claims goes as weight to burn UID 189 (if total claims exceed 100 percent, shares are scaled and nothing burns). Running more UIDs does not add pay: work allocation is meant to follow verified capacity. The team announced a quality bonus on 2026-09-16, and the public miner dashboard on 2026-10-21 showed multipliers up to about 2 for the best miners, so a bonus is live even though the code default for it is off. The live curve values come from served configuration and a signed profile that were not read.

Getting started

  1. Check the hardware in the README (8 GB VRAM and 8 CPU cores minimum) and get an OpenRouter API key, since miners pay for their own LLM calls.
  2. Clone the repo, create a Python 3.12 virtual environment and run install.sh; the first run downloads about 44 GB of models.
  3. Copy miner_env.example to .miner_env and set API_KEY; the other values are pre-filled.
  4. Register with btcli subnet register --netuid 45, then start python -m neurons.miner --netuid 45 with your wallet names.
  5. If the axon sits behind nginx, set underscores_in_headers on, or no batches will arrive.
  6. Stay on the latest miner release from the repo and watch the #alpharidge channel, because the team has asked miners to update several times since September.

Caveats

  • Chain weights were not read; pay claims here come from the repo, the team's public dashboard and chat.
  • The README is dated 2026-08-29 and still describes a V2 rule where a failed sample voids a whole batch; the code and chat since September show per-article graded scoring, triage and a quality bonus, and the 2026-09-29 update softened batch failures. Which rule applies in detail was not resolved.
  • Live economic values (bonus size, reputation midpoint, capacity) come from served configuration and a signed mechanism profile that require authentication and were not read; the public dashboard only shows their effects.
  • Dashboard and API figures are team-run and were read on 2026-10-21 only. The README throughput and source counts are a 2026-08-29 snapshot.
  • Chat has repeated miner complaints about registration churn and low pay for many miners; these are community statements, and the team has said it would change subnet parameters only if mining updates do not help.
  • Allegations of cheating by named miners in chat were not verified and are not repeated here.

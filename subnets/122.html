What it is

CookingTAO (SN122) is a marketplace layer on top of other Bittensor subnets. Developers submit miner code for a supported subnet, users deploy that code through the team's platform and mine on the original subnet, and SN122 validators reward the developer according to how well those user deployments rank and earn there. SN122 itself has no miner software: it is validator-only, and developer hotkeys are registered here only so they can be scored.

How it works

Miners

The SN122 'miners' are developers. They do not run a CookingTAO daemon. A developer submits a GitHub repository (main branch) containing miner code for another supported subnet, with a start command, any API keys or fixed environment variables it needs, a Python version and the miner hotkey. After verification and review, an approved version is listed in the platform marketplace and users deploy it on CookingTAO-managed infrastructure, using their own hotkeys on the original subnet. To receive any SN122 weight the developer's registered hotkey must hold more than 1,000 alpha staked on SN122. The guidelines cap active listings at five per supported subnet, chosen by ranking. In chat on 2026-10-07 the team said beta developers first request Miner Access from the team and that a screener checks the code can beat the top 5 earning rate already in the marketplace. Users who deploy a listed miner through the platform must give it their hotkey seed phrase at each deploy; the docs (read 2026-10-23) say it is sent over an encrypted connection, used only to set up and run the miner and not kept after setup, and that the deployed code runs with that hotkey and any API keys the user selects.

Validators

Validators register on netuid 122 and run neurons/validator.py (Python 3.11, bittensor 11.0.1). Weight submission is off by default: run with --plan-weights first, then add --submit-weights. Each cycle the validator authenticates to the team's backend, which supplies the platform's earnings, an importance factor per supported subnet and the map from each developer hotkey to the user hotkeys running its code. The validator then reads those users' ranks and incentive on the original subnets from the chain, computes scores and sets weights. The backend data is taken as given by the validator code. The code also burns the whole cycle to the owner UID if the backend or the alpha price cannot be read, or if platform earnings are zero or negative. On 2026-10-23 twelve UIDs held validator permits, on twelve different coldkeys, and six of them had set weights.

Incentive

For every user running a developer's code, the pair score is the subnet's importance factor times two terms: 90 percent for the user's rank on the original subnet (top rank scores 1, rank 255 or zero incentive scores 0) times the user's share of all adopter incentive, plus 10 percent for a flat adoption term of one over the total number of adopters. A developer's raw score is the sum over their users and over all their codes. Shares are normalised, then capped at 30 percent per developer with the excess redistributed; anything unallocated goes to the owner UID as a burn. The miner pool is then scaled down to the ratio of platform earnings to a fixed expected value of 148.01 alpha per epoch at the current alpha price. At weight time any hotkey under 1,000 alpha staked on SN122 is dropped and its score moves to the owner UID. Chain read at block 9343854 (2026-10-23, about 04:30 UTC): exactly one developer UID had incentive, 30.0 percent, which is the per-developer cap; the owner UID 0 had the other 70.0 percent, and the subnet is set to burn incentive paid to the owner slot. All six validators that had set weights submitted the same two-target row (70 percent owner, 30 percent that developer). That developer's hotkey held about 1,021 alpha on SN122, just above the 1,000 floor. The same 70/30 split was already on chain at block 9318000 (about 2026-10-19). The stored emission split (miner / validator / owner) reads 64 / 18 / 18 percent from at least block 9319500 (about 2026-10-19 evening) through 2026-10-23, matching the team's announcement of 2026-10-19, which it called temporary for about a week. The emission actually paid per UID in that period still looks like the earlier 41 / 41 / 18 split, so the effect of the new split on payouts is not confirmed. By the page author's arithmetic, 148.01 alpha is about the old 41 percent miner pool of one 360-alpha epoch, and the code was not changed when the split changed. Weights on chain are validator opinions, not payouts.

Getting started

  1. Developers: read the submission guidelines and the platform docs, then sign in at prod.cookingtao.com with a browser wallet and switch to the Developer role. In chat on 2026-10-07 the team also said beta developers had to request Miner Access from the team first.
  2. Developers: submit a repository for a supported subnet (main branch, read-only fine-grained GitHub token, start command, Python version, API keys and environment variables, miner hotkey). Review has no fixed time; check the Submission notifications.
  3. Developers: once approved, register the miner hotkey on SN122 and stake more than 1,000 alpha on it. Weight depends on users running your code and earning on the original subnet.
  4. Validators: register on netuid 122 with btcli, create a fresh Python 3.11 environment with bittensor 11.0.1 (uv sync), and run neurons/validator.py with --plan-weights.
  5. Validators: review the planned weights, then add --submit-weights. A W&B API key for the shared reward-breakdown project is obtained from the team (chat, 2026-09-23).
  6. Users (not SN122 miners): deploying through the platform needs a registered hotkey, credits and that hotkey's seed phrase; read the platform's keys and seed phrases page before deploying.

Caveats

  • The chain read of 2026-10-23 shows one scored developer UID at the 30 percent cap and the owner UID with the rest, but weights are validators' opinions, not payouts, and which developer holds that UID is not public.
  • The scoring inputs (platform earnings, importance factors, and which user hotkeys count as adopters of which developer) come from the team's closed backend. Validators cannot check them from the repo, and the criteria for listing an adopter are not public.
  • Chat says a miner must be profitable or above an earnings threshold before it gets weight, and that a screener compares code with the top 5 earning rate. The validator code and the June 2026 incentive-mechanism draft have no such per-miner test (only rank, incentive, adoption, the platform-earnings ratio and the 1,000 alpha stake), so that logic, if it exists, sits in the backend. The chain cannot tell whether the other published codes have no adopters with incentive, are not registered or staked, or are filtered by the backend.
  • The guidelines mention penalties for submitting multiple codes and anti-concentration measures. The validator code and the draft PDF show only the 30 percent per-developer cap, and both sum a developer's scores over all codes.
  • The draft PDF says only income-generating miners can register as SN122 miners; the validator code has no such check.
  • The 148.01 alpha per epoch figure is a hard-coded constant in the code and the whitepaper, about the old 41 percent miner pool (the page author's arithmetic on a 360-alpha epoch). The code was last changed on 2026-09-23, before the 64 percent miner split, so the scale-down against platform earnings does not follow the larger pool.
  • The stored emission split reads 64 / 18 / 18 percent, but on 2026-10-23 the per-UID emission paid looked like the earlier 41 / 41 / 18 split (the owner UID took less than a 64 percent miner pool alone would give it). This was not reconciled; do not read 64 percent as the confirmed payout. The team said the split was temporary for about a week from 2026-10-19.
  • The project is a closed beta. Several participants reported submissions pending for one to two weeks or more (2026-10-07 to 2026-10-19), and there is no public-launch date or v2.2 release announcement through 2026-10-23.
  • Claims about revenue, buybacks and emission rank (the team said on 2026-10-02 it ranked 39th) are the team's own and were not independently checked.
  • Not read: the Developers Partner Program booklet (an image-only PDF), the team's X posts, the W&B dashboard contents, and the marketplace (sign-in only). The cookingtao.com address in the chain identity returned an error (502) on 2026-10-23; the live platform is at prod.cookingtao.com. The supported-subnet list changes: chat on 2026-09-23 named seven (SN43, SN6, SN54, SN50, SN33, SN22, SN26), so check the platform marketplace for the current set.

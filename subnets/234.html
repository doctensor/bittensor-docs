What it is

TuneForge is a Bittensor subnet project in which miners generate music from text prompts and validators score the audio. It is run by a single maintainer as a side project, and the project says it would only register on mainnet if the registration price and customer demand made sense. A music-sharing platform at tuneforge.io, where users could earn alpha on popular tracks, is part of the stated vision. That platform could not be reached from the research machine.

How it works

Miners

Per the README, a miner runs a music-generation model on its own GPU and returns audio for a text prompt (tempo, key, genre, instruments, duration) over its axon. The recommended default is the ACE-Step 1.5 SFT model, with MusicGen, DiffRhythm and HeartMuLa as alternatives, and miners may bring their own model. When vocals are requested without lyrics, the miner generates lyrics itself. The docs describe the scoring as model-agnostic: it judges the audio, not the architecture.

Validators

Each round the validator builds a prompt, sends it to a batch of miners, and scores the returned audio on 16 weighted signals hard-coded in tuneforge/config/scoring_config.py. The largest are CLAP text-audio similarity (19 percent), attribute checks for tempo, key and instruments (11 percent), musicality (9 percent) and vocal and lyric quality (8 percent). Penalty multipliers apply for silence, timeouts of 300 seconds, wrong duration, artifacts, Frechet Audio Distance and fingerprint matches against known songs. A learned preference model (7 percent base weight) is switched off in the code unless a trained checkpoint is supplied, in which case its weight is renormalised to the other signals. The README says real user requests from the platform are also routed to top miners.

Incentive

In the code, each miner's score is smoothed with an exponential moving average (alpha 0.2). Miners with a positive score are ranked, the top 10 share 80 percent of the weight and everyone else shares 20 percent, with weight inside a tier proportional to the square of the score. The weights are normalised and submitted to chain, and the setter skips the update if all weights are zero. A burn UID setting exists in the config but no other code uses it. This matches the team's own description from 2026-03-22. It is a design only: the subnet has no mainnet emissions, and on the testnet no UID holds incentive.

Getting started

  1. Testnet only, no rewards. You need an NVIDIA GPU; the miner guide lists about 10 GB of VRAM for the default ACE-Step model, while min_compute.yml asks for 16 GB or more.
  2. Clone the repo linked in chat (github.com/borgg-dev/tuneforge). The README's own clone address points at a different GitHub account whose repository was not accessible.
  3. Install with pip install -e . (Python 3.10 to 3.12) and copy the miner example .env, setting TF_NETUID=234 and the test network.
  4. Create a testnet wallet and register a hotkey with btcli subnet register --netuid 234 --subtensor.network test (the burn read 0.0005 test TAO on 2026-10-21).
  5. Run the miner with scripts/run_miner.sh or the Docker image. With no validator setting weights, expect no score or incentive.

Caveats

  • Testnet only. Nothing here describes mainnet participation, emissions or token economics; mainnet has no netuid 234 (chain read 2026-10-21) and the maintainer has given no mainnet date.
  • Testnet chain read 2026-10-21 (block about 8.27 million): 71 neurons, 61 validator permits, zero UIDs with incentive or dividends, and the freshest validator weight update was about 959,000 blocks old, roughly 134 days at 12 seconds per block. All 61 permit holders were more than two tempos stale. Whether the team's validator is running now was not checked beyond this.
  • The testnet netuid 234 was registered on 2024-10-18, about 17 months before the TuneForge launch post (2026-03-13). The chain read shows no subnet name, and who held the slot before, or how the team came to hold it, was not checked.
  • Code and docs read at commit f680cdb (2026-06-04), from a shallow clone. README, code constants and the team's 2026-03-22 description agree on the 16 weights and the top-10 80 percent split. Nothing was run, so scoring behaviour is unverified.
  • Hardware figures disagree: the miner guide says an RTX 3060 or T4 with 10 GB for the default model, min_compute.yml says at least 16 GB VRAM, 8 cores, 32 GB RAM and 100 GB disk, and the chat said an RTX 3090.
  • The README says to clone from a different GitHub account than the one the team linked in chat; that address asked for credentials (private or missing). The linked repository's licence is CC BY-NC 4.0, which is non-commercial.
  • tuneforge.io, its docs and mining.tuneforge.io resolved in DNS but did not answer over https or http from the research machine on 2026-10-21, so the dashboard, API docs, annotation flow and user platform were not verified. The two framework-built variant repos and the team's X posts were not read.
  • The preference model, which the team calls the most important scorer, runs in bootstrap mode (neutral score) unless a trained checkpoint is supplied; whether one was ever trained on testnet was not found.

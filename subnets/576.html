What it is

Microtensor pays miners for small language models fine-tuned for one narrow task (context compression, page parsing, SQL), shipped with a router and an escalation path, and measures their quality on hidden tests. It lost its mainnet slot in September 2026 and now runs a redesigned version as netuid 576 on the test network while it looks for a new slot.

How it works

Miners

Each arena fixes one base model. A miner fine-tunes it and adds a harness, a router (predicts when the small model is right) and an escalation path (repairs doubtful answers through a frontier model on the team's relay), then commits a digest on chain. In the evaluation window it runs the hidden items on its own GPU and uploads a signed transcript of every call; its code must replay exactly.

Validators

Validators replay each transcript on CPU, requiring every recorded call to match, grade it once labels are released and set weights; the published score is the stake-weighted median of their reports. GPU checkers re-run at least 200 sampled calls and need an exact token match; a confirmed mismatch means a ban.

Incentive

Miner emission is split across five pools (model, harness, router, escalation, whole system); the top five in a pool get 40, 25, 15, 12 and 8 percent, and an empty pool is burned. The README says 20% per pool; the serving docs set up to 10% aside first (18% per pool). Testnet settings only.

Roles and requirements

Miner Medium barrier

Fine-tunes the arena's base model, builds harness, router and escalation, and runs the evaluation on its own GPU.

  • Two Hugging Face repositories per arena: artifact (harness, router, escalation) and model weights.
  • min_compute.yml still names netuid 92 and an RTX 3090 minimum; it predates the move (2026-09-05). Licence: proprietary, participation only.

Validator High barrier

Replays miner transcripts on CPU, grades them and sets weights; needs relay access granted by the team.

  • Spot checking is a separate GPU duty (a P1, P2, P3 or K card, NVIDIA Container Toolkit); the owner runs one checker per profile.

Inference miner Medium barrier

Serves certified systems to customers through the team's gateway; paid on metered usage plus a serving pool.

  • Pay: 95% of metered billing plus a serving pool (10% of arena emission under 5,000 USD monthly billing, 5% under 50,000, 2% above).

Getting started

  1. Treat this as testnet work: netuid 576 exists on the test network only (testnet wallet and TAO).
  2. Miners: start from the miner template, pick an arena (ctx_compress is live on testnet), fine-tune its base model and check it with mt check-model.
  3. Commit the digest on chain, run mt miner run in the evaluation window and upload before Freeze 2; test with mt miner replay first.
  4. Validators and inference miners: follow docs/validator_setup.md or docs/inference_miner.md; validators must ask the team for relay access.

Caveats

  • Testnet only: mainnet has no netuid 576 (2026-10-31), and no slot or date was named. Nothing here covers mainnet participation.
  • The mechanism was rewritten on 2026-10-29; older repo files and September chat describe the old validator-run flow.
  • Testnet (2026-10-31): 5 neurons, no uid with incentive. The chain tool reports emissions off, yet 295 alpha went out last epoch (97.6% to uid 0); not reconciled. Who runs the neurons is unknown.
  • Quality and cost claims are the team's; no usage or revenue is visible. The slot loss is from team posts and a moderator note elsewhere, not checked on chain.
  • The channel has no discussion of the new mechanism, so participant experience is undocumented. The docs site was not read (client-rendered); the repo docs were.

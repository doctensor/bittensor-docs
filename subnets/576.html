What it is

Microtensor pays miners for systems built around a small language model trained for one task, plus a harness, a router that decides when to trust the small model, and an escalation path that repairs wrong answers with a frontier model. Validators run these systems on their own GPUs against hidden items and score them in separate pools. The project ran on a mainnet slot until mid-September 2026, lost it, and now runs this redesigned version as netuid 576 on the Bittensor test network while it looks for a new mainnet slot.

How it works

Miners

Ship two Hugging Face repositories per arena: the artifact (harness, router, escalation code and a manifest) and the model (weights and training record). Commit the revision on chain, paying the arena's fee if it charges one. The arenas on testnet are context compression for agents (ctx_compress) and SQL generation (sql_gen), both in the small-GPU envelope class. Separate roles exist for inference operators, who hold certified systems and serve customer requests, and for compute miners.

Validators

Each epoch (50,400 blocks, about a week) validators decrypt a hidden item bundle, serve each submission's model with vLLM and run the miner's code in a gVisor sandbox with no network except validator services. A pass over about 30 submissions takes around 20 hours on three 24 GB GPUs. Each validator signs a report and sets weights from its own scores. Running a validator needs relay access granted by the team.

Incentive

Five pools (model, harness, router, escalation, whole system) each pay 20%. Within a pool the top five ranks get 40, 25, 15, 12 and 8 percent. Scores are one-sided lower bounds, and a published score moves only when a new result beats the previous best for the same artifact by 0.01. All of this is testnet configuration from the repo; nothing here describes mainnet emissions.

Getting started

  1. Treat this as testnet work: netuid 576 exists on the test network only, so use a testnet wallet and testnet TAO.
  2. Start from the miner template repo and pick an arena (ctx_compress or sql_gen) from the arenas repo.
  3. Train a small model for the arena following docs/miner_setup.md, and check latency and memory with mt envelope check.
  4. Package and validate the two repositories with the mt submit commands, pay the fee if the arena charges one, then commit the revision on chain.
  5. Validators and inference operators follow validator_setup.md and inference_miner.md in the subnet repo; validators need relay access from the team.

Caveats

  • No mainnet netuid 576 exists. Nothing here describes mainnet participation, emissions or token economics.
  • September chat describes the earlier mainnet mechanism (invoice and text-to-SQL rounds). The repo has since been rewritten with epochs, five pools and new arenas, so treat that chat as history.
  • The loss of the earlier mainnet slot is described from team posts and a moderator note in another subnet's channel. The cause was not checked on chain.
  • A testnet read on 2026-10-21 (block 8273074) shows netuid 576 registered as Microtensor on 2026-09-23 with one registered neuron, and the chain tool reported emissions as not enabled. Whether anything is running there, and any weights, were not read. The docs site is client-rendered and was not read; the repo docs were.
  • Chat since 2026-09-25 contains almost no discussion of the new mechanism, so miner experience with it is not documented. Market and price talk in the channel is not included.

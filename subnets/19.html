What it is

blockmachine sells JSON-RPC access to blockchain nodes, including archive nodes, through a gateway that routes each customer request to a competing miner's node and bills only for successful answers. Miners bring their own nodes for Bittensor and ten EVM chains. Validators read the gateway's logs, re-check sampled answers against reference nodes and set weights from the work each miner served. The subnet is run by the Taostats team, whose own indexer is the biggest named customer.

How it works

Miners

A miner runs a node of an accepted client for one chain, declares it as archive (history back to genesis) or full (recent blocks only), and puts the team's nginx gateway in front of it. They then register it with the bm command-line tool along with a secret and a price bid. Each hotkey may register at most one archive and one full node per chain. Nodes must pass automatic eligibility tests (right chain, honest client string, near the chain tip, working subscriptions, real archive depth) before they get traffic. Archive nodes can also run an optional capacity helper. Base nodes must have Flashblocks enabled since 2026-10-14. The capacity test's expected answers follow the team's reference nodes: on 2026-10-22 the team said its Robinhood reference runs Nitro 3.11 as a path-scheme archive with a full transaction index, and a Scroll miner reported the expected style flipping between reth and l2geth on 2026-10-21.

Validators

Validators fetch network settings from a team-run registry, read each epoch's gateway logs and per-miner compute-unit (CU) allocation files from team-run storage, and sample answers to re-run against reference nodes. A confirmed wrong answer bans the miner's coldkey. In plain words, the validator code values each miner's CU at its bid, scales the total to the 41% miner pool and turns that into weights; because the alpha price cancels out and every bid is now the same $0.50 per million CU, a miner's weight is simply its share of the CU credited to non-banned miners. Banned coldkeys get zero. Anything left unallocated goes to a sink UID (default 103), which on chain is the owner's hotkey slot and held no incentive on 2026-10-23, so burn was zero. If the scale looks wrong (more than 10 times the pool) the code refuses to pay it out and burns the remainder instead. Validator code does not compute capacity scores, the top-five archive rule or eligibility; those are applied by the team's gateway and registry before the files validators read. On chain at block 9,343,888 twelve UIDs held validator permits and nine of them had set weights within the last epoch, all with the same shape (47 targets, same top target), which fits everyone running the public software on the same data. The team's own validator held about 31% of permitted validator stake and a different validator about 57%; the whitepaper says up to 64 validators can be permitted.

Incentive

Emissions split 41% to miners, 41% to validators and 18% to the owner; the chain's emission-split setting confirms those shares. Miners are paid first for paid customer traffic, and from 2026-10-16 every bid is fixed at $0.50 per million CU, so price no longer differentiates miners. The rest of the miner pool is a base incentive shared equally across the 11 chains, credited as extra CU. Per chain, 90% goes to the five archive nodes that served the most CU that epoch and 10% follows recent-block CU from all eligible nodes. A capacity test (a timed burst of traces, state, log and block queries, weighted 15/35/35/15 for EVM chains) scales a node's routing share, and latency and reliability scores feed routing too. The public miner dashboard's numbers match the team's latency rule (full marks up to 100 ms P95, falling linearly to zero at 1,000 ms) and a reliability ramp that reaches full marks after seven good epochs. An epoch is 7,200 blocks, about 24 hours. On 2026-10-23 the last epoch's miner incentive was spread over 38 UIDs held by 37 coldkeys: the top UID had 20.7% and the top five 61.2%, and no incentive-earning UID shared the owner's coldkey. The team buys alpha monthly from paid-traffic revenue and burns it.

Getting started

  1. Pick a chain from the 11 live networks and sync an accepted client (reth for Ethereum and Base, op-reth for Optimism, bor for Polygon, nitro for Arbitrum, Arc and Robinhood, subtensor for Bittensor and so on). The miner README has the exact client table and the full or archive depth each node type must serve.
  2. Register a hotkey on netuid 19. The site says one hotkey per coldkey is accepted. All 256 UIDs were occupied on 2026-10-23 (chain read), so a new registration replaces the lowest-ranked UID after the 21,600-block immunity period; the registration burn was about 1 TAO on that date.
  3. Install the CLI with pip install blockmachine (Python 3.10 or newer) and run bm miner login.
  4. On the node's server run the install script from the miner README. It sets up the nginx gateway with TLS and a secret in front of your RPC port.
  5. Register with bm miner add (endpoint, alias, secret, price), then check bm miner test and bm miner show. A new node must pass the eligibility battery first.
  6. Check your nodes on the public miner dashboard (Eligibility, Capacity tests, Live routing score and Payouts tabs). Archive operators can download the last test with bm miner capacity-pack and optionally install the capacity helper; the README warns that this raises the bar for everyone.

Caveats

  • Chain facts were read on 2026-10-23 at block 9,343,888 and change every epoch. Weights are validators' opinions, not payouts, and the payout, share and buyback numbers on blockmachine.io are the team's own data.
  • The gateway, registry and epoch finalizer are not public. Validators read files those systems produce, so the capacity score, the top-five rule, eligibility and the routing score's extra factor cannot be checked against validator code. The dashboard's routing score is higher than latency, reliability, success and price alone would give, which the team attributes to capacity.
  • The miner README is out of date in places: it lists Avalanche and omits Arc, says an epoch is about 72 minutes (the validator README, whitepaper and site say 7,200 blocks, about 24 hours), documents a testnet the team says is off, and shows price examples per CU while the site quotes $0.50 per million CU. The miner dashboard's pool selectors still list Avalanche.
  • Capacity test scheduling (three runs a day since 2026-10-20) comes from team statements in chat. The questions are unpublished, and the expected answer style has changed without announcement at least once (Scroll, 2026-10-21, one miner's report), so a node can score differently between runs for reasons it cannot see in advance. The team said the latency rule may get stricter.
  • How latency is clocked is not settled: the team said on 2026-10-20 that it covers requests the node answers and that new-heads pushes are not timed, but a miner asked on 2026-10-20 whether gateway queueing or waiting for a pinned block counts and had no answer by 2026-10-22.
  • A pinned post from 2026-07-02 says miners need locked conviction of at least 300 alpha, and 70% of cumulative free-tier incentive, to earn free-tier incentive. That rule is not on the website or in the validator README and was not verified on chain or in code.
  • The validator README says a confirmed wrong answer is a permanent coldkey ban, while the whitepaper calls a ban a human decision and does not say permanent. Two Ethereum nodes were banned from 2026-09-09 for not broadcasting customer transactions; no reversal was found in chat after 2026-09-14.
  • Buyback cycle 7 had not settled as of 2026-10-23; the ledger shows six cycles and 9,797.31 alpha burned or held in total.

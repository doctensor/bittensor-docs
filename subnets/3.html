What it is

Teutonic is a competition to improve one shared language model. Miners train and submit complete checkpoints of a custom mixture-of-experts model (Teutonic-II-110B-A7B, about 110B parameters in total and about 7B active per token). Each submission is tested head to head against a king on next-token loss, and a challenger that wins by a large enough margin is crowned. Since 2026-10-21 there are seven competitions: MAIN and six dataset mixes (MIX01 to MIX06), each with its own king and a share of the subnet's emission.

How it works

Miners

Miners train a full checkpoint of the Teutonic-II architecture and submit it through the repo's miner CLI. The hotkey must use the Ed25519 key type, because upload credentials are encrypted to it. Each hotkey gets exactly one submission, shared across all competitions, and it is irreversible once marked ready. When marking a submission ready, the miner picks MAIN or one of MIX01 to MIX06 (MAIN if left out). The team said in chat on 2026-10-15 that at least eight B300-class GPUs are needed to mine, and on 2026-10-21 told miners to update their CLI for the new competitions.

Validators

The team's validator checks each submitted checkpoint byte for byte against what was committed on chain, then sends the challenger and the king to a remote GPU evaluator. All seven competitions use the same sampler: 20,000 text windows of 2,048 tokens plus about 30 million tokens of whole documents of 2,049 to 8,192 tokens, drawn with explicit per-category weights that differ by competition. The evaluator compares paired next-token cross-entropy, weights it by scored tokens, masks document boundaries and bootstraps a confidence interval over the windows. A challenger wins if the lower confidence bound of its improvement is strictly above 0.0015, the same threshold for all seven. A MIX that has no king yet duels a fixed starting MAIN king, pinned once and not moved by later MAIN crownings; after its first win it duels its own king. Code defaults are 10,000 resamples and a 0.001 quantile, but the live settings sit in the team's database and were not read. Evaluation, queueing and crowning run on team infrastructure.

Incentive

The announced end state is 25 percent of the reward weight for the MAIN king and 12.5 percent for each of the six MIX kings, paid in the subnet's own alpha token. During the transition from the old specialist system, each MIX's first winner takes 12.5 percent and removes the oldest remaining legacy payout position; what is left is shared among MAIN and the surviving legacy positions in proportion to their earlier shares, and a new MAIN king replaces the MAIN position at once. A kingless MIX leaves its 12.5 percent with MAIN. On 2026-10-23 the team dashboard showed five MIX kings seated, MIX03 still kingless and a MAIN payout weight of 0.375. Weights are published about every 101 blocks, recipients that are no longer registered are dropped and the rest normalized, with a burn fallback if none remain. On chain (read at block 9343166 to 9343176) commit-reveal is on and the subnet's emission is split 18 percent owner, 41 percent validators and 41 percent miners, with the recycle-or-burn setting on Burn. Three validators set weights, all with the same top target and share, and the validator holding about 98 percent of dividends uses the owner's hotkey. The weight row on chain showed 45.45, 17.05 and three times 12.5 percent, which is what the repo's reward formula gives for the earlier state of three MIX kings and one legacy position; the dashboard showed the newer state, which fits the commit-reveal delay.

Getting started

  1. Check the hardware first: the team said at least eight B300-class GPUs are needed to mine.
  2. Clone the repo, create a Python 3.11+ virtual environment and install the miner extras. Keep the CLI up to date, the team asked for this on 2026-10-21.
  3. Create an Ed25519 hotkey with btcli and save the wallet path with the miner CLI configure command.
  4. Run the CLI register command, which registers the hotkey on subnet 3 if needed (this can spend TAO; check-only mode refuses to pay).
  5. Before choosing a competition, read the competitions JSON: it shows which are active, which have a king, the thresholds and the pinned starting king of kingless MIXes.
  6. Upload a full checkpoint directory with the CLI upload command, then mark it ready, or run the single submit command, adding the competition option (MAIN or MIX01 to MIX06; MAIN if left out).
  7. A submission cannot be undone and each hotkey has only one, shared across all competitions.

Caveats

  • The rules are changing quickly: competitions were restructured on 2026-10-21 and the starting-king rule changed on 10-22. The README introduction still describes MAIN, MATH, CODE and TEXT with about 6M long-document tokens, and the mining guide's section on the live chain still says 'as of 2026-08-24'. Treat the competitions and dashboard JSON as the reference.
  • Chain weights were read as aggregates at block 9343166 to 9343176, and they lag the dashboard because commit-reveal is on (a 4-epoch reveal period, about 4.8 hours). The exact delay was not measured. The reward formula was read in code; whether production behaves exactly like it was checked only through that one weight row.
  • Evaluation, queue order and crowning all run on team infrastructure, thresholds and sample settings live in the team's database, and challenger models stay private until crowned. A miner asked on 2026-09-04 for on-chain hash commitments to make this checkable.
  • Three validators set weights with the same top target and share. One uses the owner's hotkey and holds about 98 percent of dividends, the other two sit on separate coldkeys whose operators are not established. A fourth permit holder, the earlier MAIN king, has not set weights recently.
  • Chain proves the owner key pair changed once around 2026-08-14 to 08-15, but not who holds it. Day-to-day operation by the Dendrite team, which also runs SN97, is documented only in chat.
  • The team has declined for now to share the full tokenization scripts for the pretokenized dataset (asked 09-24, 10-02, 10-04); no newer request was found.
  • The relationship to Teutonic I and to the SFT work on Teutonic I announced by the Reliquary subnet (SN81) is unclear; no reply from the Teutonic team was found in its channel.
  • The repo has no LICENSE file in its root, although the project metadata says MIT.
  • Claims in chat that kings improved benchmark scores are miner statements.

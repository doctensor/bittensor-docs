What it is

Chutes is a hosted inference service with an OpenAI-compatible API for open-source models, and lets developers deploy their own models and code as custom apps called chutes. Miners supply GPU servers that run these workloads inside confidential virtual machines; the Chutes validator sends real user traffic to them and sets weights from how much compute each miner provided. The subnet is operated by the company Chutes Global Corp (named in the subnet's on-chain identity). On 2026-10-22 the team described a wider aim of building open models, trained with its Parallax research on distributed consumer GPUs, while saying the inference business continues and that it is adding company-run, off-network compute that is not paid from emissions.

How it works

Miners

Run one non-GPU control-plane server (miner API, the gepetto scheduler, postgres, redis, registry proxy) plus bare-metal, TDX-capable GPU hosts. Each GPU host runs a confidential VM built with the sek8s tooling, with no SSH access, and is registered with the chutes-miner CLI. Register a single UID; no axon is announced. Gepetto decides which chutes to deploy or scale and tries to claim bounties, and it is the main piece to optimize. Servers must be bare metal or VMs with static IPs, not rented marketplace GPUs, and need at least as much RAM per GPU as VRAM.

Validators

The validator is the Chutes API platform itself (API, database, Kubernetes, image registry), run by the team, which routes user requests to miner instances and records audit data. The team recommends delegating to its hotkey with a child hotkey rather than running a full validator, and the validator take is 0%. GPU nodes are verified through TEE hardware attestation; the legacy GraVal check is blocked for new nodes. A separate auditor tool lets others recompute incentives from committed audit reports and compare them to on-chain weights. On chain on 2026-10-23, 15 UIDs held validator permits and 14 had set weights; all 14 vectors were near-identical (same 18 targets, nothing to the owner slot), which fits validators relaying one team-computed result.

Incentive

In the public validator code, a miner's weight is its share of total compute units over a trailing one-day window, recalculated and set at the top of each UTC hour. Compute units are instance running time multiplied by a multiplier from GPU type and count, with bonuses: TEE instances 2.25x, private instances 2x (1.3x if also TEE), integrated-subnet chutes 3x, an autoscaler demand boost on public chutes, and a bounty boost of 1.1x to 1.5x that ramps up with bounty age and decays after claiming. Code history shows this replaced a four-metric scheme on 2025-11-09, shortened the window from 7 days to 1 day on 2026-04-20, and dropped a one-hotkey-per-coldkey rule on 2026-04-24. Chain read at block 9342946 (2026-10-23): 18 of 256 UIDs were paid, the top miner held 20.3% of incentive and the top five 62.3%, and one coldkey held two paid UIDs. The chain's emission split vector is the standard 18% owner, 41% validators, 41% miners, with nothing burned or recycled.

  • 2026-10-22 (#chutes and chutes.ai news) A team member said the company is adding privately secured, off-network compute, including non-TEE inference, sold on its platform with a way to choose between the two. It will not use miner emissions or self-mining for these offerings and the network will not subsidize them; miner-provided compute on the network stays TEE. The announcement article was edited the same day to make this clearer.
  • 2026-10-22 (chutes.ai news article) The team published an article on building an open-source AI lab on the network. It says the inference business continues and funds model work, and that Parallax trains models over the internet on consumer GPUs; the latest run it reports is an 8B-parameter model finished on 2026-10-10 on about 901 billion tokens. It says network incentives will shift gradually toward training, SFT, RL and data pipelines, and that existing miners are unaffected. All figures are team-reported.
  • 2026-10-22 (#chutes) In answer to a community question, a team member said a lane for consumer hardware (DGX Spark, Apple silicon) to contribute to training, weighted separately from GPU compute, is on the roadmap for the near future. No rules, dates or code have been published.
  • 2026-10-13 (#chutes) Team members explained privacy modes: in the normal API mode traffic is encrypted in transit but the operator could in theory read it, while the end-to-end encrypted mode encrypts on the client so only ciphertext reaches Chutes.
  • 2026-10-11 (#chutes) TEE release v1.5.0 announced to miners (tagged the same day in the sek8s repo): AMD SEV-SNP guest support (SNP hosts are not yet accepted on the network), a maintenance flow that keeps the only running instance of a chute serving and posts a replacement bounty, and a fix for a reboot hang on TDX. Upgrade window runs through 2026-10-25, up to 2 servers per miner in maintenance at once. The maintenance flow is present in the miner repo.
  • 2026-10-11 (#chutes) After users reported Pro subscriptions being downgraded since 2026-10-04, the team said the removed accounts were clustered accounts used for business purposes, that refunds are being handled, and that checkout now blocks duplicate subscriptions.
  • 2026-10-07 (#chutes) In answer to questions about missing revenue figures, the team said some revenue now goes to the operating company outside the subnet, and promised more frequent updates within a few weeks.

Getting started

  1. Check hardware requirements in the miner README: bare-metal or VM servers with static unique IPs, TDX-capable GPU hosts, and RAM per GPU at least equal to VRAM.
  2. Provision one non-GPU control-plane server with the ansible playbooks and helm charts in the miner repo.
  3. Register one hotkey with btcli subnet register --netuid 64, and do not announce an axon.
  4. Set up each GPU host with the sek8s host tools: download the guest image, generate config.yaml with chutes-cvm config init, and launch the confidential VM with chutes-cvm guest launch.
  5. Register each worker once with chutes-miner add-node, giving the server name, validator hotkey, hourly cost per GPU, GPU short name, and the agent and miner API addresses.
  6. Tune the gepetto strategy. For upgrades use chutes-miner tee start-maintenance and wait for the maintenance state before rebooting; the docs-site maintenance guide still describes the older cordon-and-reboot flow and does not mention this command.

Caveats

  • Three descriptions of scoring disagree, and code history shows which are stale. The validator code scores compute units only over a one-day window, set hourly. The public scoring docs page (four weighted metrics 55/25/15/5, 7-day default, one paid hotkey per coldkey) and the miner README ('7 day sum of compute') describe rules the code dropped on 2025-11-09, 2026-04-20 and 2026-04-24; the docs page's 55/25/15/5 split matches no version of the constants that was readable in history. The chain on 2026-10-23 fits the code (one coldkey held two paid UIDs). What the production validator actually runs is not confirmed: the API repo's latest public commit is 2026-09-03.
  • Comments in the code give different bonus values from the constants (for example TEE 1.5x in a comment versus 2.25x in the constant, and bounty boost up to 4x versus 1.1x to 1.5x). This page uses the constants.
  • The validator repo's README still describes GraVal-based verification and running a full validator, while the miner README says the network is TEE-exclusive and GraVal is blocked.
  • Miner participation in Parallax is not documented. Its technical report (10 October 2026) is labelled AI-generated and not fully reviewed, and says the exercised run was one operator's fleet. The team said on 2026-10-22 that a consumer-hardware training lane is on the roadmap; no rules, dates or code were found, and the article's figures are team-reported.
  • The company-run, off-network inference described on 2026-10-22 sits outside the subnet. How much user traffic is served by miners versus company compute is not published, and revenue and buyback statements in chat could not be verified.
  • Chain figures are one snapshot (block 9342946, 2026-10-23). Weights are validator opinions, not payouts, and the chain does not show who controls a coldkey; the one owner-coldkey validator is consistent with the operator running a validator but the other 14 permit holders are not identified.
  • SEV-SNP hosts are not accepted yet, and the v1.5.0 upgrade window closes on 2026-10-25.
  • Chat: pass 1 read the latest 200 messages (2026-10-02 to 2026-10-18) and this refresh read every message from 2026-10-20 to 2026-10-22; older history was not read. Some statements attributed to the team come from members who speak for the team but are not role-labelled.
  • The hosted model list and user pricing change often; the live catalog is at the API's /v1/models endpoint. The chat is moderated against price discussion, so this page has no market data.

What it is

Ralph (Ralph Labs) is a subnet in which miners compress a single fixed open model, Qwen3-8B, into very small GGUF files at set bit-width tiers (binary, ternary, around 2-bit and around 4-bit), so that a model of the same architecture fits on a phone. Validators measure how closely each compressed model reproduces the original's behaviour as seen by judge models, and the best entry in each tier is crowned and published for download. The current design (v2) replaced an earlier autonomous-research design (v1) in August 2026, and the subnet occupies a slot that belonged to a different project, Chunk, until 2025.

How it works

Miners

Per the repository README and the team's machine-readable subnet description: a miner compresses the one pinned parent model into a tier with a hard cap on bits per weight (the README lists 1.15, 1.75, 2.3 and 4.0 code bits per weight for the binary, ternary, sub-2 and sub-4 tiers; an earlier chat message from 2026-08-05 gave about 2.0 for sub-2, so that cap has moved). The result is served as a downloadable GGUF file. A miner first commits a hash of the exact served bytes on chain before the round's random value exists, then reveals after the round opens; a command-line pre-check for the bit budget is included. If the same bytes are committed twice, the earlier commit wins. GGUF quantisation types need a mainline llama.cpp path to be accepted (two ternary types were rejected). One entry per coldkey per tier per round.

Validators

Per the README: a validator recomputes a round and sets weights only after its own audit accepts the signed round record. Entries pass gates in order: registration and the one-entry rule, a safety check, tier fit, the bit budget (read from the tensor data or GGUF type names), the pinned parent, and commit-reveal. Scoring is an 'observer KL' retention: judge models read the parent's reasoning step and the miner's step, and the score reflects how closely the miner moved the judge to where the parent did, on a scale where 1 means identical to the parent and about 0.135 means no contribution. The aggregate is the mean over judges of each judge's worst slice across language and reasoning depth. Test items are drawn from a value that only exists once the commit window closes. Round records are signed, hash-chained and anchored on chain by the validator hotkey, with tools to re-run a round and audit it. The team says retention measures fidelity to the parent, not capability.

Incentive

Per the team's documents (not yet seen applied on chain): within a tier, the current king would take 80 percent of the tier's allocation and the best strictly improving challenger 20 percent. A challenger dethrones the king with a single-round lead of 0.02 or a lead of 0.01 in two consecutive rounds; these margins halve after three holds, and a floor rule applies to the worst slice. The team reports crown retention of about 0.24 (ternary), 0.26 (binary), 0.28 (sub-2) and 0.32 (sub-4). Chain-level split on 2026-10-21 (block about 9.33 million): subnet emission shares are 18 percent owner, 41 percent validators, 41 percent miners. Incentive was non-zero on exactly one neuron (100 percent), and that neuron was none of the four crowned miners' hotkeys named by the team, which each held 0.0 percent.

Getting started

  1. Read the README in RalphLabsAI/ralph for the pinned parent model, the four bit-width tiers and their caps.
  2. Compress the pinned Qwen3-8B into one tier and check it with the repository's bit-rate checker before submitting.
  3. Serve the file at a fixed revision (a hash must cover exactly the bytes the validator will fetch), then run the miner submit command to commit the hash on chain before the round's nonce exists.
  4. After the round opens, run the reveal step; one entry per coldkey per tier per round.
  5. Validators and auditors: the README has a section on running as an auditor validator, plus tools to re-run a round; it was only skimmed here, so read it directly.

Caveats

  • The chain does not currently pay the crowned miners. On 2026-10-21 one neuron held all incentive and every weight-setting validator pointed at it. It is none of the four crown hotkeys the team names, and it is not the owner's coldkey; who operates it is unknown. Weights are opinions, not payouts, and these checks cannot rule out a relationship through other keys.
  • The team's own subnet description listed a gap, last checked 2026-09-13, that no v2 round allocation had been applied on chain (rounds signed and anchored, allocations held back until an operator sets weights from a published round). That page was not refreshed afterwards, and the on-chain read above is consistent with it still holding. The other two gaps listed there changed or stand: the stale on-chain description has since been updated, and iPhone testing still covers only the sub-2 crown.
  • Evaluation was described as stuck by a team member on 2026-10-12, and the newest round record found is Round 7 (2026-09-11). No team statement after 2026-10-12 was found in the channel.
  • The subnet has been in a public dispute. Since late July 2026 several members alleged that the subnet was self-mining (one neuron holding all incentive for weeks), and one said they lost TAO. The owner replied that the neuron was the old v1 winner and that weight setting had been stale, and rejected the accusation. No evidence either way is published in the channel. This page does not take a side.
  • Retention scores are fidelity to the parent model, not a capability benchmark, and the team says so. The retention figures above are the team's own and were not independently reproduced; the crown files on Hugging Face were not tested here.
  • Device evidence is the team's own run on one tier, with the file hash not verified on the device.
  • Bit-per-weight caps for the sub-2 tier differ between sources (about 2.0 in chat on 2026-08-05, 2.3 in the README at the last commit). The repository README is the more recent source.
  • A second repository name, ralph-v2, appears in chat and is described as the same protocol; the repository named on chain is RalphLabsAI/ralph and was the one read.
  • This slot belonged to a different project, Chunk, until 2025 and the channel holds that older history. Messages from before mid-2026 do not describe Ralph.
  • The benchmark results file, the Hugging Face round records, and validator hardware requirements were not opened; no answer was found to a miner's August question about validator hardware and API costs.

What it is

Bitsec (SN60) pays miners for AI agents that find high and critical bugs in smart-contract code. Each week validators run private agents in sandboxes on audit-contest projects and the top two are paid.

How it works

Miners

A miner submits one Python agent that reads a codebase, calls a language model and returns vulnerabilities. A screener rejects unsafe code, copies, memorised answers and steering toward known benchmark solutions.

Validators

Validators pull platform jobs and run each agent in a Docker sandbox three times on every project, matching findings to expected ones with a language model. A project passes at two of three runs with every expected finding matched; the score is the mean of the best three validators.

Incentive

Rounds close on Mondays at about 15:00 UTC. The platform publishes the payout list (50% burn, then 77/23 for the top two accounts' best agents) and validators set weights to it. Ties break on score, then passes, then true positives.

  • Several submissions per round and several hotkeys per miner are allowed for now (team, 2026-10-20).
  • A run takes up to 30 minutes in the sandbox on the miner's own key.

Validator Medium barrier

Runs and scores agents; weights follow the team's payout list.

  • 15 uids hold a permit (16 on 2026-11-06); 11 set weights within the last tempo, 4 not for over five tempos.

Last round (v3.1.17)

  • Closed 2026-11-03 at 16:00 UTC, a day late: 794 submitted, 23 scored. Best 0.857 (6 of 7 projects on each of three validators); v3.1.16's was 0.238.
  • Five of seven projects are new and the seven hold 28 expected findings against 43. On the two shared projects the best agent passed 16 of 24 runs, up from 6 (different agents, reworded texts). Why scores rose is not shown.
  • Paid: the best agents of the top two accounts, 7599 (0.857) and 7543 (0.810; most passes of the ties), on uids 201 and 105 (234 and 251 on 2026-10-23).
  • Scores kept moving after the round showed finished: five agents rose (7357 0.714 to 0.810, 7636 0.762 to 0.810); the paid two did not change.

What the score rewards

  • Only recall counts: a project passes when every expected finding is found, so precision is unused and the leading agents' reports were 94-96% false positives (up to 80 findings a run).

Where the emission goes

  • Chain split: 18% owner, 41% validators, 41% miners. The owner's uid holds 50.0% of miner incentive, burned: about 20.5% of all emission.
  • The two paid agents share about 4.4 TAO a day (77/23; our arithmetic). The burn was about 35% on 2026-09-23 and 50% by 2026-10-21; no announcement found.

Getting started

  1. Clone Bitsec-AI/sandbox, follow the docs' miner guide, install Docker and uv.
  2. Set INFERENCE_API_KEY; edit miner/agent.py so agent_main returns a vulnerabilities list.
  3. Register with ./bitsec.py miner create (email, name, wallet), test on the public practice projects and submit while a round is open.
  4. Validators: install Docker and Python 3.11, set CHUTES_API_KEY, run ./bitsec.py validator create, then validator run.

Caveats

  • The platform code is closed and picks the winners; burn share, payout split and project choice have changed before and can again.
  • Miner claims of leaked or steered benchmarks and a malicious agent 7050 are unverified.
  • Revenue, client and buyback questions (asked 2026-10-11 and 2026-10-31) went unanswered; Sentios claims come from the team.
  • Chat after 2026-11-02 was not read (archive down): the late round, the revert and the score jump are unexplained.

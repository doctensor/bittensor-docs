What it is

Bitsec (SN60) rewards miners for building AI agents that find high and critical severity vulnerabilities in real software, currently Solidity smart contracts scored against findings from human audits. Contests run in rounds: miners submit private agents, validators run them in sandboxes on benchmark codebases, and the winner is published along with everyone's code and logs. The team also sells a continuous-coverage product called Sentios and announced new clients in October. As of 2026-10-23 half of the miner emission is burned on chain and the other half is split 77/23 between the top two agents.

How it works

Miners

A miner writes a single Python agent (an agent_main function that returns a list of vulnerabilities) in the sandbox repo, tests it locally and submits it to the team's platform. Miners can submit several times per round and pay for their own inference through a Chutes or OpenRouter key. Submissions are screened for unsafe code, hardcoded answers, copies and steering toward known benchmark answers before they are evaluated.

Validators

After screening, validators run each agent in a Docker sandbox (30 minutes per run) on the round's codebases, three runs each. A codebase counts as passed only if all of its critical and high findings were matched in at least two of three runs, with no partial credit. A validator's score is the share of codebases passed; the final score averages the best three validator scores, and at least three validators are required. The public project set in the repo has four codebases, and a hidden private set is also used.

Incentive

Rounds are winner-takes-most and close on Mondays at 15:00 UTC (round v3.1.15 closed 2026-10-19). Weights do not come from validator scoring: each validator downloads a payload from the team's platform that lists the top agents, a payout structure and a burn share, and sets weights to match. On 2026-10-23 that public payload said burn 50 percent and payout 77/23, and the chain agrees: three uids have incentive, the subnet owner's hotkey with 50 percent, which the chain burns, and two miners with 38.5 and 11.5 percent. So the owner slot receives half of the miner emission but it is destroyed, not paid out, which answers the community's worry on 10-21 and 10-22 that the owner had become a self-miner; the community figure of an owner share rising from 35 to 50 percent was not found in a team statement. Separately, 18 percent of subnet emission is set aside for the owner, 41 percent for validators and 41 percent for miners. Commit-reveal is on, ten validators have set weights, and one validator earns 60 percent of validator dividends.

Getting started

  1. Clone Bitsec-AI/sandbox and install with uv; set INFERENCE_API_KEY to a Chutes or OpenRouter key.
  2. Edit miner/agent.py so agent_main returns a report with a vulnerabilities list, and run it with the repo's execute-agent command.
  3. Register the miner with the bitsec.py miner create command, then test with run-no-docker and the Docker flow.
  4. Submit during an open round (submissions have closed on Mondays at 15:00 UTC; check bitsec.ai/leaderboard for the live round) and check the screener rules (no eval or exec, no hardcoded answers, no near-copies) before uploading.

Caveats

  • Weights come from the team's platform payload, so the winner and payout structure are set by the team; the chain read on 2026-10-23 (block 9,343,398) matches the platform's public payload, but it is one snapshot, the burn share has changed before (no dated team statement found), and the sandbox and validator scoring code was not re-read in this pass.
  • Disputes about hard steering, spam submissions and the screener's model fallback were still open on 10-22. Miners' claims about specific agents and operators are unverified, and the team called the current winner borderline rather than invalid.
  • The docs describe four codebases and the repo has four public projects, but the live round feed reports a current set of three public and four hidden projects, miners talk of 32 public projects, and the team plans to rotate them, so none of these counts is stable.
  • The next round's start, the new project set and any change to the burn or payout are not announced; Monday 15:00 UTC is the observed close time, not a published schedule.
  • Questions about revenue and buybacks went unanswered in chat.
  • docs.bitsec.ai may lag the code; the repo README says the code is the source of truth for local runs.
